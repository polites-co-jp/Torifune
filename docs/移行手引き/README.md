# 移行手引き（Migration Guide）

破壊的変更（Breaking Change）を行ったときに、移行の手順をここへ置く。

対象となる変更は `docs/仕様書/07_開発者向けガイド.md` §47 に定義してある。

## 置き方

ファイル名は**変更後のバージョン**にする。

```text
docs/移行手引き/
├── README.md      このファイル
└── 0.2.0.md       0.1.x から 0.2.0 へ上げるときの手引き
```

## 書くこと

* 何が変わったか（変更前と変更後を並べる）
* なぜ変えたか
* Plugin作者・利用者が何をすればよいか（具体的な手順）
* 移行しなかった場合に何が起きるか

Plugin API の破壊的変更を伴う場合は、`packages/plugin-api` の
Plugin API Version（`07_開発者向けガイド.md` §48）を上げ、その番号を明記する。

## まだ何も無い理由

Torifune は最初の公開前であり、**互換性を保つべき外部の利用者がまだ存在しない**。
そのため移行手引きは1件も無い。破壊的変更が無かったのではなく、
互換性の対象がまだ生まれていない段階にある。

最初の公開以降は、§47 の対象に触れる変更を入れるたびにここへ1ファイル増える。
