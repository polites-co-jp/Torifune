# 外部サイト導入手順（アクセス計測タグ）

**この文書は、計測されるWebサイト側のプロジェクトへ渡すためのものである。**
Torifune の内部を知らなくても、これだけで導入できるように書いてある。

Torifune を運用する側の手順は `docs/マニュアル/アクセス解析設置.md` にある。

---

## 1. 受け取るもの

Torifune の運用担当から、次の2つを受け取る。

| 名前 | 例 | 何か |
| --- | --- | --- |
| 計測サーバーのURL | `https://torifune.example.com` | タグの配布元であり、送信先 |
| 公開キー（サイトキー） | `3f9a…`（64桁の16進） | どのサイトからのアクセスかを識別する文字列 |

**公開キーは秘密ではない。** HTML に出るし、隠す必要も無い。
このキーで数値を読み出すことはできない（送信専用）。
ただし**第三者が偽のアクセスを送ることはできる**ので、
むやみに配って回るものでもない。

---

## 2. 最短の導入

計測したいページの `<head>` に、次の1行を入れる。

```html
<script src="https://torifune.example.com/t.js" data-site="（公開キー）"></script>
```

これだけで、そのページの表示が記録される。

* **Cookie を使わない。** 同意バナーの仕組みとは独立している
* **画面の描画をブロックしない**（送信は非同期）
* **失敗しても何も起きない。** 送信できなくても例外を投げず、画面には影響しない
* `defer` / `async` を付けてもよい

### フレームワーク別

**WordPress** — テーマの `header.php`（`wp_head()` の前）、または
「ヘッダーにコードを挿入」できるプラグインで `<head>` へ入れる。

**Next.js（App Router）** — `app/layout.tsx` に置く。

```tsx
import Script from 'next/script';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ja">
      <body>
        {children}
        <Script
          src="https://torifune.example.com/t.js"
          data-site="（公開キー）"
          strategy="afterInteractive"
        />
      </body>
    </html>
  );
}
```

**Nuxt** — `nuxt.config.ts` の `app.head.script` へ
`{ src: 'https://torifune.example.com/t.js', 'data-site': '（公開キー）' }` を追加する。

### Content-Security-Policy を設定している場合

サイト側に CSP がある場合、次の2つを許可する。許可しないと**何も送られない**。

```text
script-src  https://torifune.example.com   ← t.js を読み込むため
connect-src https://torifune.example.com   ← 計測データを送るため
```

`connect-src` を忘れやすい。`script-src` だけではタグは読めても送信で落ちる。

## 3. SPA（クライアント側ルーティング）の場合

**配布タグは SPA のクライアント側遷移にも対応している。**
`history.pushState` / `replaceState` / `popstate` を見て、
**pathname が変わるたびに**送る（Plausible / Umami と同じ方式）。
Next.js App Router や React Router の `router.push` でも、タグを貼るだけで
ページ遷移が記録される。

* 同じ pathname への `replaceState`（クエリ更新・スクロール復元）では送らない
* ハッシュ（`#`）だけの変化では送らない
* 遷移時の `referrer` は送らない（`null`）。流入元は初回表示のときだけ記録する
* タグが2回貼られても二重には送らない

タグを貼れない事情がある場合（CSP でスクリプトを許可できない等）は、
アプリ側から直接送信する。送信内容は次章の仕様に従う。

```ts
const ENDPOINT = 'https://torifune.example.com/api/v1/collect';
const SITE_KEY = '（公開キー）';

export function trackPageView(path: string, referrer: string | null): void {
  const body = JSON.stringify({ key: SITE_KEY, path, referrer });

  // Content-Type は text/plain のままにする（後述）。
  const blob = new Blob([body], { type: 'text/plain;charset=UTF-8' });

  if (navigator.sendBeacon !== undefined && navigator.sendBeacon(ENDPOINT, blob)) {
    return;
  }

  void fetch(ENDPOINT, {
    method: 'POST',
    headers: { 'Content-Type': 'text/plain;charset=UTF-8' },
    body,
    keepalive: true,
    // 応答は読まない。CORS を開かせないために no-cors でよい。
    mode: 'no-cors',
  }).catch(() => {
    // 計測の失敗でアプリを止めない。
  });
}
```

ルーターの遷移完了イベントで `trackPageView(location.pathname, document.referrer || null)`
を呼ぶ。**初回表示ぶんも自分で呼ぶこと**（タグを貼っていないため）。

### `Content-Type` を `application/json` にしてはいけない

**ここが唯一の落とし穴。** `application/json` は CORS のセーフリスト外で、
送信のたびにプリフライト（`OPTIONS`）が飛ぶ。計測サーバーは
既定でクロスオリジンの CORS を許可していないため、**計測が丸ごと落ちる**。

`text/plain` はセーフリストなので単純リクエストとして通る。
本文が JSON であること自体は問題ない（受け側は Content-Type を見ずに JSON として読む）。

## 4. 送信仕様

```text
POST https://torifune.example.com/api/v1/collect
Content-Type: text/plain;charset=UTF-8
```

```json
{
  "key": "（公開キー）",
  "path": "/pricing",
  "referrer": "https://example.com/blog/post"
}
```

| フィールド | 必須 | 制約 | 備考 |
| --- | --- | --- | --- |
| `key` | ○ | 1〜200文字 | 公開キー |
| `path` | ○ | 1〜2000文字 | `/` で始まるパス。絶対URLでも可（パスだけ取り出される） |
| `referrer` | – | 2000文字以内 | `null` 可。**ホスト名だけが保存される** |

### 応答

**常に `204 No Content` を返す。** 成功しても、キーが誤っていても、
サイトが存在しなくても同じ応答になる（キーの当たりを探らせないため）。

**つまり、応答では成否を判断できない。** 動作確認は次章の方法で行う。

### 認証・CSRF

不要。トークンもヘッダも要らない。

### 流量制限

**1分あたり600件／IPアドレス**。超えると `429` を返す。
通常の閲覧で当たることはない。負荷試験を行う場合は事前に運用担当へ伝えること。

## 5. 動作確認

1. **ふつうのブラウザで**タグを貼ったページを開く
2. 開発者ツールの Network に `collect` が出て、ステータスが **204** であること
3. Torifune の運用担当に、**アナリティクス → そのサイトの「設定」タブの受信状況**で
   「最終受信」が更新されているか確認してもらう（**集計を待たずに分かる**）。
   数字が画面に出るのは集計のあと（既定では最大 15 分）

`curl` や自動テストのユーザーエージェントで叩くと **Bot と判定され、
記録はされるが画面には出ない**。確認は必ず実ブラウザで行う。

### うまくいかないとき

| 症状 | 原因 |
| --- | --- |
| Network に `collect` が出ない | タグが読み込まれていない。`t.js` の URL、`data-site` の綴りを確認 |
| `t.js` が 404 | 計測サーバーのURLが誤っている |
| CORS エラーが出る | `Content-Type` を `application/json` にしていないか（§3参照） |
| CSP のエラーが出る | `script-src` / `connect-src` の許可漏れ（§2参照） |
| 204 なのに数値が出ない | 運用担当に受信状況の**状態**を見てもらう。「Bot のみ受信」なら User-Agent、「未受信」なら公開キーの取り違え。「受信中（集計待ち）」なら次の集計を待てばよい |

問い合わせるときは、**貼ったタグの1行**、**対象ページのURL**、
**Network に出た `collect` のステータス**を添えると早い。

## 6. 何が送られ、何が送られないか

サイトの訪問者へ説明する必要が生じたときのために、記録される内容を挙げる。

**送られるもの**

* 公開キー（どのサイトか）
* パス（`?` 以降は送らない。送っても保存されない）
* リファラ（**保存されるのはホスト名だけ**。パスは捨てられる）

**送られないもの**

* Cookie（**そもそも作らない・読まない**）
* 入力内容、フォームの値、DOM の中身
* ログイン情報、ユーザーID

**計測サーバー側で保存されないもの**

* **IPアドレスの生値**
* **User-Agent の生値**

訪問者の識別には、IPと User-Agent から作るハッシュを使う。
**元になる値は保存されず、ハッシュの作り方（ソルト）は日ごとに変わる**ため、
日をまたいで同じ訪問者を追跡することはできない。

> 同意取得が必要かどうかは、適用される法令と運用による。
> **この文書は法的な判断をしない。** 判断材料として上の内容を使うこと。

---

## 7. 停止のしかた

タグの1行を消せば、それ以降は一切送らない。
アンインストール作業も、残るファイルも無い。
