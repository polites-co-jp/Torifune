# 上位仕様の改訂履歴

`docs/仕様書/` は安定した基盤であり、勝手に書き換えない（`CLAUDE.md`）。
改訂したときは、**何を・なぜ・どの節を**変えたのかをここへ記録する。

---

## 2026-08-24 コンテンツを Core の責務から外す

### 決定

**`contents` を Torifune Core のドメイン・テーブル・API・画面から外す。**

コンテンツ管理は Plugin の責務とし、Torifune は次の3つを提供するに留める。

1. 画面を作るための Plugin 機構（Page / Menu / Widget / Extension Point）
2. デザインを揃えるための共通 UI Component と CSS トークン
3. データへアクセスするための API（Public API / Plugin Data API）

### 理由

Torifune の価値は**汎用性**にある（`CLAUDE.md`「絶対に守る境界」）。
「コンテンツ」が何であるかは利用者ごとに大きく違う。

* ブログ記事なのか、LP の原稿なのか、メール文面なのか
* 本文は Markdown なのか、ブロック構造なのか、外部 CMS への参照なのか
* 公開フローに承認が要るのか

Core が特定の形を決めると、それに合わない利用者は Core を使えず、
合う利用者にとっても中途半端なものになる。
**形を決めずに、決められる仕組みだけを提供する**ほうが、
Plugin First の方針（`03_プラグイン設計.md` §2.1）と一貫する。

Sites / SNS / Campaigns / Analytics は「マーケティング活動の対象と実績」であり、
形が利用者によって大きく変わらないため Core に残す。

ただし **Core が提供するものではない**ことが分かるよう、各所に注記を足した。

### 欠番の扱い

`docs/設計/` の ID 008 は欠番とする。
既に書かれたコードのコメントが `010-plugin-api` / `011-plugin-runtime` 等を
参照しているため、繰り上げると参照が壊れる。**採番の連続性より参照の正しさを優先する。**
