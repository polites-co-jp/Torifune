# バックアップとリストア

`02_データベース設計.md` §14 は「バックアップ方式を Torifune 本体の必須機能として
固定しない」としている。運用の形が利用者ごとに違うためで、その判断は変えない。

ただし**手順が書かれていないと、いざというときに戻せない。**
標準構成（PostgreSQL 1インスタンス = 1データベース）での手順をここに置く。

## 何を守る必要があるか

| 対象 | 失うと何が起きるか | どこにあるか |
| --- | --- | --- |
| データベース | すべて。ユーザー・サイト・SNS・Plugin の設定 | PostgreSQL |
| `TORIFUNE_ENCRYPTION_KEY` | **DB があっても暗号化された値を復号できない** | 環境変数 |
| `plugins/` のファイル | 導入済み Plugin の実体 | ファイルシステム |

> **鍵は DB に入っていない**（`02_データベース設計.md` §13）。
> DB だけ取っても、SNSの資格情報と Plugin の Secret は戻らない。
> **鍵と DB は別の場所に、しかし同じ世代で保管する。**
> 鍵を回した（変えた）ら、その前のバックアップは古い鍵でしか読めない。

## バックアップ

### データベース

```bash
pg_dump --format=custom --no-owner --no-privileges \
  "$DATABASE_URL" > torifune-$(date +%Y%m%d-%H%M%S).dump
```

`--format=custom` を使う理由は、リストア時に並列復元でき、
テーブル単位の部分復元もできるため。

コンテナ構成なら、

```bash
docker compose exec -T postgres \
  pg_dump --format=custom --no-owner --no-privileges -U torifune torifune \
  > torifune-$(date +%Y%m%d-%H%M%S).dump
```

### 鍵

`TORIFUNE_ENCRYPTION_KEY` と `TORIFUNE_ENCRYPTION_KEY_ID` を、
**DB のバックアップとは別の場所へ**控える。同じ場所に置くと、
片方が漏れた時点で両方漏れる。

### Plugin のファイル

```bash
tar czf torifune-plugins-$(date +%Y%m%d).tar.gz plugins/
```

DB の `plugins` テーブルは「どの Plugin が導入済みか」しか持たない。
**実体は `plugins/` にある。** 片方だけ戻すと、導入済みなのにファイルが無い
（または逆の）状態になる。

## リストア

### 手順

1. **アプリを止める。** 動いたまま戻すと、復元中の DB へ書き込みが入る

   ```bash
   docker compose stop web
   ```

2. 空のデータベースを用意する

   ```bash
   dropdb torifune && createdb torifune
   ```

3. ダンプを流し込む

   ```bash
   pg_restore --no-owner --no-privileges --dbname "$DATABASE_URL" torifune-YYYYMMDD-HHMMSS.dump
   ```

4. `plugins/` を同じ世代のものへ戻す

5. **その世代の鍵**を環境変数へ設定する

6. マイグレーションを当てる（ダンプが古い版なら差分が当たる）

   ```bash
   torifune migrate
   ```

7. アプリを起動し、`/api/ready` が `ready` を返すことを確かめる

### 戻したあとに確かめること

* ログインできる
* SNSアカウントの資格情報が「設定済み」と出る
  （出ないなら**鍵が世代と合っていない**）
* 導入済み Plugin が一覧に出て、有効なものが有効のままである

管理者のパスワードが分からなくなった場合は、
`torifune reset-password --login-id=<id>` で再設定できる（`README.md`）。

## 定期実行

世代管理は運用側の方針に合わせる。最低限、

* **復元を試したことのないバックアップは、バックアップではない。**
  定期的に別環境へ戻して、上の「確かめること」を通す
* 鍵を回したら、その時点で新しい世代のバックアップを取り直す

## この文書の限界

論理レプリケーションや PITR（Point-in-time Recovery）は扱っていない。
必要な規模になったら PostgreSQL 側の機能で組む。Torifune 側に作るものは無い。
