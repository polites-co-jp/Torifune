## 実装中に見つけて直したこと

### 再試行の予約時刻をアプリの時計で入れていた

`next_attempt_at` の既定値は DB の `now()` で入るのに、
再試行の予約と比較をアプリ側の `new Date()` で行っていた。

**わずかな時計のずれで「まだ送らない」になる。** テストが実測で捕まえた
（1回目の配信が実行されない）。既定値・比較・再予約のすべてを
DB の `now()` に寄せた。

## 決めたことの要点

* **Plugin のイベントは中継しない。** 名前も中身も Plugin 次第で、
  Core が「外へ送ってよい」と判断できない
* **発火の場で送らない。** 受け手が落ちていると Torifune の操作が遅くなる／失敗する
* **署名の対象は `timestamp.body`。** 本文だけだと、古い正当な配信をそのまま
  送りつけられる（リプレイ）
* **「1回だけ」を保証しない。** ネットワーク越しには原理的に「少なくとも1回」しか作れない。
  配信IDを渡して、受け手が判断できるようにする
* **内部ネットワークへの送信は止めない。** 自己ホストで社内の受け手へ送るのは
  正当な用途。設定できるのは `system.manage` を持つ人だけで、
  その人は既にもっと強い操作ができる
