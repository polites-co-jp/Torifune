# 024-responsive 設計

## 1. 目的

レスポンシブ対応（`06_画面設計.md` §31）。`002-Torifune機能完成` T10。

`001` は「本格的なデザイン、レスポンシブの作り込み」を範囲外としたが、
§31 は実装対象の§であり、`002` の完了条件（193§）に含まれる。

## 2. いまの状態

* **`@media` が全コード・CSSに0件**
* `app-shell.tsx` が `gridTemplateColumns: 'var(--tf-size-nav) 1fr'`（220px固定）。
  幅の狭い画面でサイドバーが本文を潰す
* `layout.tsx` に `viewport` 指定が無く、モバイルで既定の980px幅として描かれる
* 表が横に溢れて、ページ全体が横スクロールする

## 3. 決めたこと

### 3.1 「作り込み」はしない。壊れないところまで

`001` が範囲外としたのは**デザインの作り込み**であって、
「狭い画面で使えないこと」の容認ではない。

やるのは、

* 幅375pxで**ナビゲーションと主要画面が破綻しない**
* 表が**その表の中で**横スクロールする（ページ全体が横に伸びない）
* タップできる大きさがある

やらないのは、モバイル専用のレイアウト・ハンバーガーメニューの開閉アニメーション・
画面ごとの作り分け。

### 3.2 断点は1つだけ

`--tf-breakpoint-md: 768px`。

**増やさない。** 断点が増えるほど、どの画面でどう見えるかを確かめる組み合わせが増える。
1つで足りなくなったら、そのとき足す。

### 3.3 ナビゲーションは「横に並べる」で畳む

狭い画面ではサイドバーを本文の上へ移し、項目を横に並べて折り返す。

**開閉するメニューにしない。** 開閉には状態と操作が要り、
Server Component のままでは作れない（`app-shell.tsx` はサーバー側で描いている）。
項目数が10に満たない今、常に見えているほうが速い。

### 3.4 スタイルは `globals.css` へ書く

これまでインラインの `style` で書いてきたが、**`@media` はインラインで書けない**。

クラスを足して CSS 側で切り替える。
既存のインラインスタイルを全部書き換えることはしない
（差分が大きくなり、レビューできなくなる）。**レイアウトに関わる箇所だけ**。

### 3.5 表の横スクロールは共通コンポーネント側で

`Table` を包む要素に `overflow-x: auto` を付ける。
画面ごとに書くと、新しい表を足したときに忘れる。

## 4. 受け入れ条件

1. 幅375pxでナビゲーションと主要画面が破綻しない
2. 表が表の中で横スクロールし、ページ全体が横スクロールしない
3. `viewport` が指定されている
4. 広い画面での見え方が今までと変わらない
