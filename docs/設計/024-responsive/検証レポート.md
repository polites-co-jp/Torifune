# 024-responsive 検証レポート

## 受け入れ条件

| # | 条件 | 判定 | 根拠 |
| --- | --- | --- | --- |
| 1 | 幅375pxでナビゲーションと主要画面が破綻しない | ✅ | E2E `responsive.spec.ts`（主要7画面＋ログイン画面） |
| 2 | 表が表の中で横スクロールし、ページ全体が横スクロールしない | ✅ | 同「広い表はページではなく表の中でスクロールする」 |
| 3 | `viewport` が指定されている | ✅ | 同「viewport が指定されている」 |
| 4 | 広い画面での見え方が変わらない | ✅ | 同「ナビゲーションが本文の左に並ぶ」（1280px） |

## 実際に直した壊れ方

| 症状 | 原因 |
| --- | --- |
| モバイルで文字が読めない | `viewport` が無く、既定の980px幅で描かれてから縮小されていた |
| 狭い画面で本文が潰れる | サイドバーが `220px` 固定 |
| ページ全体が横に伸びる | 本文の grid セルに `min-width: 0` が無く、広い表が親を押し広げていた |

3つ目は**表側だけを直しても直らない**（`Table` には既に `overflow-x: auto` があった）。
grid の子は既定で `min-width: auto` になり、中身より小さくならない。

## 決めたことの要点

* **断点は1つ（768px）。** 増やすほど、どの画面でどう見えるかを確かめる組み合わせが増える
* **開閉するメニューにしない。** 開閉には状態と操作が要り、`app-shell.tsx` は
  Server Component のままでは作れない。項目数が10に満たない今は常に見えているほうが速い
* **既存のインラインスタイルを全部書き換えない。** `@media` が要る
  レイアウト部分だけクラスへ出した。全部書き換えると差分が大きくなり、レビューできなくなる

## やっていないこと（意図的）

モバイル専用のレイアウト、画面ごとの作り分け、アニメーション。
`001` が範囲外とした「デザインの作り込み」はそのまま範囲外。
ここでやったのは「狭い画面で壊れない」ところまで。
