## 1. 直したもの

配信ジョブは期限の来た予約の列を作ってから、1 件ずつ着手する（前の行の `publish()` を待つ）。着手（`claimForPublish`）と
支度待ちへ送る書き込み（`deferSkipped`）が、列を作るとき（`listDue`）の条件のうち `delivery_mode = 'auto'` と
`scheduled_at <= now()` などを見ていなかった。

* 列に並んだ後に、承認を経ていない予約を `PATCH` で**未来の日時**・**手動投稿**に変えても（200 が返る）、そのまま即時に送っていた。
  手動投稿に変えた場合は、人が後で手で出すと二重投稿になる。取りやめてから予約し直す、承認待ちに戻してから指定時刻で承認し直す、でも同じ
* `deferSkipped` は、手動投稿に変えられた行の飛ばし回数を数え、3 回目に `failed` にして `social.post.failed` を出していた。
  未来へ直された行には、`PATCH` が消した待ち時刻を書き戻していた

**直し方**：Repository の中だけの述語 `dueForAutoPublish` を `listDue` から 1 文字も変えずに切り出し、`listDue`・`claimForPublish`・
`deferSkipped` が同じ UPDATE 文の中で使う（`now()` は DB がその文で評価する）。当たらなかった行は黙って飛ばす（`due` にだけ数える）。
`recordOutcome`（送った事実の記録）と `failInterrupted`（中断の判定）には掛けない。API・Plugin API・マイグレーションは変えていない。

## 2. 検証で確かめたこと

* `spec-verifier` は全件のテストを流し、述語・3 メソッド・`recordOutcome`・`failInterrupted`・ジョブの件数の扱いへ**変異 30 件**を入れ、
  等価変異（`scheduled_at IS NOT NULL` だけを外す。`NULL <= now()` は偽なので振る舞いが変わらない）を除き**すべて検出**された。
  既存テストの差分は追加だけで、期待値を弱めたものは無い
* `security-reviewer` は、手動投稿・未来の予約・承認待ち・下書き・着手済みの行がどれも着手の UPDATE で除かれること、
  `PATCH` と着手のどちらが先でも（行ロックを待った UPDATE の再評価を含めて）送らない側に倒れること、
  同時実行・再試行・中断の判定で二重に送る向きに倒れないこと、`recordOutcome` / `failInterrupted` に述語を掛けないことが悪用できないことを確かめた。
  **テストは実行していない**
* `boundary-guardian` は、Domain が `pg` / `kysely` に依存しないこと、述語が Infrastructure の非公開関数であること、
  公開 API・OpenAPI・Plugin API・マイグレーションに差分が無いこと（`PLUGIN_API_VERSION` は 1）、SaaS の内部事情が混ざっていないことを確かめた

## 3. 指摘と対応

| 出所 | 指摘 | 対応 |
| --- | --- | --- |
| spec 軽微 1 | `048` 設計 §6.10 の表の「中断した配信の判定」に `delivery_mode = 'auto'` が抜けている（`049` より前から） | **直した** |
| spec 軽微 2 | 実装プランに作業機の内部事情（3000 番ポートを別のアプリが使っている）が書かれている | **一般的な書き方に直した**（`048` の実装プランの同じ記述も） |
| boundary 低 | 互換性の欄が「イベントは変わらない」だけで、本件の行では誤って出ていた `published` / `failed` が出なくなることを書いていない | **設計 §6.7・§9 と API 仕様書 §9 に一言足した**（形と意味は変わらない） |
| security 低-1 | 待ち時刻はアプリの時計で書き、比べるのは DB の時計（`035` から）。アプリの時計が 60 秒以上遅れ、同じ行が列に二度積まれる稀な場合だけ、再試行の行を同じ実行で再び着手しうる | **設計 §6.6 の記述を直し、§11.3 に記録した**。コードは変えない（本件の範囲外） |
| security 低-2 | `035` 設計 §6.5.7 の件数の不変条件の説明に、支度待ちへ送る UPDATE が 0 行だった行が入っていない | **直した** |
| spec 参考 | claim の `status`・`publish_started_at`・`next_attempt_at` を外す変異は #9 の 1 件だけが落とす | 記録のみ（判別力は足りている） |

`048` の検証レポート §4 の 7 は「`049` で直した」に更新した。
