# Webサイト管理 設計

## 1. 目的

Torifune が管理するWebサイトを登録・編集・削除できるようにする。

このスプリントには**もう一つの目的**がある。
**以降のドメイン（SNS、キャンペーン、アナリティクス）が踏襲する型をここで確立する。**
Domain / Application / Infrastructure / API / UI の分け方、テストの書き方、
Event の発火の仕方を、ここで決めて次から繰り返す。

## 3. スコープ

### やること

* `sites` テーブルとマイグレーション
* Domain（Entity / 業務ルール / Repository Interface）
* Application（UseCase 5種、トランザクション境界、Permission 要求）
* Infrastructure（Repository 実装）
* API（`/api/v1/sites` の CRUD）
* UI（一覧・作成・編集・削除）
* Event の発火（購読側は `011-plugin-runtime`）

### やらないこと

* サイトのクロール・死活監視・スクリーンショット取得（Plugin の責務）
* サイト単位の権限（「このサイトだけ編集可」）。機能単位の Permission のみ
* サイトに紐づくファイル・メディア管理

## 5. データモデル

### `sites`（`migrations/004_sites.sql`）

| カラム | 型 | 制約 |
| --- | --- | --- |
| `id` | `uuid` | PK |
| `name` | `text` | NOT NULL、空文字不可、1〜200文字 |
| `url` | `text` | NOT NULL、`http://` または `https://` で始まる |
| `description` | `text` | NOT NULL DEFAULT `''` |
| `status` | `text` | NOT NULL、CHECK in (`active`, `paused`, `archived`) |
| `created_at` / `updated_at` | `timestamptz` | NOT NULL DEFAULT `now()` |
| `created_by` | `uuid` | NULL 可、FK → `users(id)` ON DELETE SET NULL |

### Index

| 対象 | 目的 |
| --- | --- |
| `sites(created_at DESC)` | 既定の並び順 |
| `sites(status)` | 状態での絞り込み |
| `sites(lower(name))` | 名前での並び替えと検索 |

**URL に一意制約を付けない。** 同じサイトを別の目的で2つ登録したい場合がある
（本番と検証、言語別など）。重複は利用者の判断に任せる。

### 状態

```text
active ⇄ paused
   │        │
   └────────┴──→ archived
```

`archived` は「もう使わないが記録は残す」状態。一覧の既定では隠す。

## 6. API

| メソッド | パス | Permission | 説明 |
| --- | --- | --- | --- |
| GET | `/api/v1/sites` | `site.read` | 一覧 |
| POST | `/api/v1/sites` | `site.write` | 作成 |
| GET | `/api/v1/sites/{id}` | `site.read` | 取得 |
| PATCH | `/api/v1/sites/{id}` | `site.write` | 更新 |
| DELETE | `/api/v1/sites/{id}` | `site.delete` | 削除 |

### 一覧のクエリ

| 名前 | 型 | 説明 |
| --- | --- | --- |
| `page` / `perPage` | number | ページング |
| `status` | `active` \| `paused` \| `archived` | 絞り込み |
| `q` | string | 名前・URL の部分一致 |
| `sort` | `name` \| `createdAt` \| `updatedAt` | 先頭 `-` で降順。既定は `-createdAt` |

**`archived` は既定で含めない。** 明示的に `status=archived` を指定したときだけ出す。

### 作成・更新の入力

```jsonc
{ "name": "コーポレートサイト", "url": "https://example.com", "description": "", "status": "active" }
```

更新は部分更新（PATCH）。指定しなかった項目は変えない。

## 7. 画面

### `/sites` 一覧

```text
┌────────────────────────────────────────┐
│ Webサイト                     [+ 新規] │
├────────────────────────────────────────┤
│ 名前            URL           状態     │
│────────────────────────────────────────│
│ Example Site    example.com   稼働中   │  [編集] [削除]
│ Sample Site     sample.com    停止中   │  [編集] [削除]
├────────────────────────────────────────┤
│ ページ送り                             │
└────────────────────────────────────────┘
```

* Loading / Empty / Error / 権限なし の4状態を持つ
* Empty のとき「新しいWebサイトを登録」への導線を出す
* `site.write` を持たないユーザーには [+ 新規] と [編集] を出さない
* `site.delete` を持たないユーザーには [削除] を出さない
* **ただしそれは認可ではない。** サーバー側で必ず検証する

### `/sites/new` `/sites/{id}/edit`

型Bのフォーム（`02_画面デザイン方針.md`）。
サイドバーは Plugin の Extension Point（`site.edit.sidebar`）用に確保する。

### 削除

確認ダイアログを出す（`06_画面設計.md` §37）。

## 8. 権限（Permission）

| 操作 | Permission |
| --- | --- |
| 一覧・取得 | `site.read` |
| 作成・更新 | `site.write` |
| 削除 | `site.delete` |

未認証は 401、権限不足は 403。

## 9. Plugin API への影響

このスプリントでは公開しない。ただし S10 で次を公開する。

* Data API の `sites` 部分（読み取り・書き込みとも Permission を通る）
* Event：`site.created` / `site.updated` / `site.deleted`
* Extension Point：`site.edit.sidebar` / `site.list.actions`

**Event のペイロードは Plugin API のバージョン管理対象になる**
（`07_開発者向けガイド.md` §23）。ここで形を決めるときは、後から足せる形にする。

## 10. 受け入れ条件

### 作成

1. 有効な入力でサイトを作成できる
2. 作成したサイトに ID・作成日時・作成者が入る
3. 名前が空なら 422
4. 名前が 200 文字を超えたら 422
5. URL が `http://` / `https://` 以外なら 422
6. URL が URL の形をしていなければ 422
7. `status` に定義外の値を渡すと 422
8. `status` を省略すると `active` になる
9. 同じ URL のサイトを2つ作れる（重複を禁止しない）
10. `site.write` が無ければ 403、未認証なら 401

### 取得・一覧

11. 作成したサイトを ID で取得できる
12. 存在しない ID で 404
13. **不正な形式の ID（UUID でない）で 404**（500 にしない）
14. 一覧が `{ data, meta }` の形で返る
15. `meta.total` が全件数を返す
16. 既定の並びが `-createdAt`
17. `sort=name` で名前順になる
18. **`sort` に未許可の値を渡すと 422**
19. `status` で絞り込める
20. **`archived` が既定で含まれない**
21. `status=archived` を指定したときだけ `archived` が出る
22. `q` で名前の部分一致検索ができる
23. `q` で URL の部分一致検索ができる
24. `q` が大文字小文字を区別しない
25. **`q` に `%` や `_` を入れても、ワイルドカードとして解釈されない**
26. `site.read` が無ければ 403、未認証なら 401

### 更新

27. 名前だけを更新できる（他の項目が変わらない）
28. `updated_at` が更新される
29. 存在しない ID で 404
30. 不正な値で 422
31. `site.write` が無ければ 403、未認証なら 401

### 削除

32. サイトを削除できる
33. 削除後に取得すると 404
34. 存在しない ID の削除で 404
35. `site.delete` が無ければ 403、未認証なら 401
36. **`site.write` だけでは削除できない**

### Event

37. 作成時に `site.created` が発火する
38. 更新時に `site.updated` が発火する
39. 削除時に `site.deleted` が発火する
40. **UseCase が失敗したときイベントが発火しない**

### 画面

41. 一覧が表示される
42. Empty のとき登録への導線が出る
43. 作成できる
44. 編集できる
45. 削除に確認ダイアログが出る
46. 確認をキャンセルすると削除されない

### 境界

47. `domain/site/` が `pg` / `kysely` / HTTP の型を import していない
48. UseCase がすべて Permission を要求している（`003` の監査テストに載る）
