## 1. 目的

画面は URL の `?page=` を次のように数にしている。

```ts
const page = Math.max(1, Number(params['page'] ?? 1) || 1);
```

`Number()` の結果が有限か・整数か・上限内かを見ていないので、次の値がそのまま Repository の `OFFSET`（`(page − 1) × perPage`）へ届き、PostgreSQL が断って **500** になる。
漏れるものは無いが、共有されたリンクや手で書き換えた URL で自分の画面が開けなくなる。

| 値 | `page` | `OFFSET`（`perPage` 20） | 結果 |
| --- | --- | --- | --- |
| `Infinity`・`1e400` | `Infinity` | `Infinity` | 500（`bigint` に解釈できない） |
| `1.01` | `1.01` | `0.2…` | 500（小数） |
| `1e18` | `1e18` | `2e19` | 500（`bigint` の範囲外） |
| `1e300` | `1e300` | `2e301`（文字列にすると `2e+301`） | 500 |

`/analytics` の `parsePage` は `Number.isInteger(page) && page >= 1` を見るので `Infinity`・小数は 1 になるが、`1e18`・`1e300` は整数として通り、表のタブ（ページ・参照元。`perPage` 50）で同じく 500 になる（コードからの推定。受け入れ条件 #16 で確かめる）。

### やらないこと

* 画面の `perPage` の丸め（裁定。いまも URL から読んでいない）
* 最後のページより後ろの `page`（例：`?page=99`）を最後のページに寄せること。いまも HTTP の API と同じく空のページを返しており、500 ではない（§11）
* `0x10`（16 と読む）・`1e3`（1000 と読む）のような `Number()` の読み方の是正。有限の整数になるので害が無い
* `normalizePagination` に `Symbol` を渡すと例外になる件（`043` 検証レポート security 情報）。Data API の振る舞いを変えるので本件に混ぜない

## 4. レイヤ配置

| 層 | ファイル | 内容 |
| --- | --- | --- |
| Domain | `apps/web/src/domain/repository.ts` | `export function normalizePage(value: unknown): number` を足す。`normalizePagination` の `page` はこれを呼ぶ（純関数。DB 製品に依存しない） |
| Presentation（画面） | §3 の 6 ファイル | `normalizePage(params['page'])`（`/social` は `params['postPage']`）で求める。`/analytics` の `parsePage` を消す |
| UI | 変えない | ページ送りは受け取った `page` から前後のリンクを作るだけ（§7） |
| Application・Infrastructure・API・Plugin | 変えない | |

**部品を Domain に置く理由**

* 守りたいのは Infrastructure が計算する `OFFSET` で、その規則は既に `normalizePagination`（Domain）にある。画面側に別の実装を書くと、Data API と画面で規則がずれうる。`page` の半分を切り出して**同じ関数を両方が呼ぶ**形にすれば、規則は 1 か所になる
* `app/` → `domain/` の依存は既存（`app/analytics/page.tsx` と `app/sites/[id]/edit/page.tsx` が `@/domain/repository` から `NotFoundError` を引く）。ESLint が `app/` に禁じるのは DB 製品と Connection の入手で、Domain は禁じていない。**新しい依存の向きは生まれない**
* `normalizePagination({ page }).page` を画面から呼ぶ案は採らない。使わない `perPage` まで丸める関数を画面が呼ぶと、「画面の `perPage` は丸めない」という約束が読み取りにくくなる
* UI 層（`ui/server/`）に部品を置く案は採らない。中身が Domain の関数の転送だけになる

**`normalizePage` の規則**（`normalizePagination` の `page` と同一。§3 の 1 のとおり振る舞いは変えない）

1. `undefined` / `null` → 1
2. それ以外は `Number(値)`。**有限の数にならなければ** 1（`NaN`・`±Infinity`・`'abc'`・`'1e400'`・2 つ以上の要素の配列）
3. 小数は切り捨てる（`'1.01'` → 1、`'2.9'` → 2）
4. 1 以上 `Number.MAX_SAFE_INTEGER` 以下に丸める（`'0'`・`'-5'`・`''` → 1、`'1e18'` → `Number.MAX_SAFE_INTEGER`）

前後の空白は `Number()` が無視する（`' 3 '` → 3、`' '` → 0 → 1）。
同じキーを 2 回付けた URL（`?page=2&page=3`）は Next.js が配列にし、`Number(['2', '3'])` は `NaN` なので 1。いまの画面も 1 なので変わらない。

**上限の妥当性**：最大の `perPage` は `/analytics` の 50。`(MAX_SAFE_INTEGER − 1) × 50 ≒ 4.5 × 10^17` は `bigint` の上限（約 `9.2 × 10^18`）に収まり、
文字列にしても指数表記にならない（`10^21` 未満）。`043` の `security-reviewer` が Data API で確かめた性質と同じ。

| 要求 | 変更前 | 変更後 |
| --- | --- | --- |

| `?page=1e18`・`1e300` | **500**（6 画面すべて） | `Number.MAX_SAFE_INTEGER` ページ目（空のページ） |

## 7. 画面

画面構成・遷移は変えない。**ページ送りの部品（`ui/components/table.tsx` の `Pagination`）とリンクの組み立ては変えない。**

* 一覧の部品は受け取った `page` を表示し（「`page` / 最後のページ（全 N 件）」）、`page ± 1` を URL に書く。丸めた後の `page` を渡すので、表示もリンクも有限の整数になる
* `Number.MAX_SAFE_INTEGER` ページ目の「次へ」は最後のページを超えているので押せない。「前へ」は `MAX_SAFE_INTEGER − 1` ページ目へ飛び、それも 200 の空のページ（§11 の 1）
* `/analytics` の `analyticsHref` は `String(query.page)` を書く。丸めた値なので指数表記は出ない
* `ui/settings/user-list.tsx` の再読み込みは `/api/v1/users?page=<丸めた値>` を叩く。HTTP の入口は `page` を安全な整数として受ける（`043`）

## 10. 受け入れ条件

**A = 単体（純関数）、B = 結合（DB を通す。UseCase）、D = 画面（E2E。Playwright）、E = 静的検査。**

### 10.1 `normalizePage`（A）

1. (A) `undefined`・`null` → 1
2. (A) `'3'` → 3、`3` → 3、`' 7 '` → 7、`'2.9'` → 2、`'1.01'` → 1、`2.9` → 2
3. (A) `'0'`・`'-5'`・`'-0.5'`・`''`・`' '`・`0`・`-5` → 1
4. (A) `'Infinity'`・`'-Infinity'`・`'NaN'`・`'abc'`・`'1e400'`・`Infinity`・`-Infinity`・`NaN` → 1
5. (A) `'1e18'`・`'1e300'`・`1e18`・`String(Number.MAX_SAFE_INTEGER + 2)` → `Number.MAX_SAFE_INTEGER`。`String(Number.MAX_SAFE_INTEGER)` → `Number.MAX_SAFE_INTEGER`
6. (A) 同じキーを重ねたときの配列 `['2', '3']`・`['abc', '1e18']`・`[]` → 1
7. (A) 1〜6 のすべての値 `v` で、`normalizePagination({ page: v }).page === normalizePage(v)`（規則が 1 か所であること）
8. (A) 1〜6 のすべての値で、結果が `Number.isSafeInteger` かつ 1 以上で、`BigInt(結果 − 1) * 50n` が `9223372036854775807n` 以下

## 13. リスク

1. **`Number.MAX_SAFE_INTEGER` ページ目を開けること**：空のページが 200 で返るだけで、`OFFSET` は `bigint` に収まる（§4、受け入れ条件 #8〜#10）。行数に比例する負荷も無い

3. **E2E を作業機で流せないこと**：コンテナの手順（§10.6）が要る。B（#9・#10）で DB 側の性質を先に確かめ、D は画面の配線の確認に絞る
