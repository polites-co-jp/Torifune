### 確定事項（設計書から。プランで蒸し返さない）

* **Core（`apps/web` / `packages/plugin-api` / `migrations`）に 1 行も足さない。** 作るのは `plugins/sns-instagram/` の 7 ファイルと、テストだけ（設計 §1 / §3.2 / §9）
* **2026-09-23 ユーザー裁定：画像のみ。動画（Reels）・ストーリーズは扱わない**（設計 §3.2 の引用枠 / §9.4 の 5 / §11 #1）。`video_url` を 1 度も送らない
* **この Plugin は状態を 1 つも持たない。** `store` を読みも書きもしない、`registerSettings` を呼ばない、`context.ui` / `context.data` を呼ばない（設計 §5.3 / §7 / §8）。
  したがって **`createInstagramPublisher` は `store` を受け取らない**（設計 §10.1）
* `plugin.json` の `permissions` は **空**、`extensions` は **`['social']` ちょうど**（`ui` を宣言しない。設計 §8.1）
* `credentialFields` は **`igUserId`（text）/ `accessToken`（secret）/ `accessTokenExpiresAt`（text）の 3 つで確定**。後から足せない（設計 §5.1 / §5.2）
* `limits` は **`{ bodyMaxLength: 2200, mediaRequired: true, mediaMax: 10 }`**（設計 §9.1）。`PublisherLimits` にキーを足さない
* **`manual` のキーを置かない**（`manual: undefined` も書かない。設計 §9.3）。手動投稿は Core が g で 422 にする
* 外へ出す要求は **R1〜R6 の 6 種類だけ**。宛先は `https://graph.instagram.com` の定数、版は `GRAPH_API_VERSION` の定数（設計 §6 / §6.1）
* **トークンの延長（R6）は公開（R4）に成功した後だけ**、残り 30 日未満か期限不明のとき。`rotatedCredential` は 3 キーを明示して組む（設計 §6.7）
* **`retryable` の支配的な規則**：R4 の前は既定 `true`（直らないものは `false`）、R4 の後は既定 `false`（レート制限だけ `true`）、R4 の成功後は `ok: true` を覆さない（設計 §6.9）
* `reason` に載せてよいのは **固定の日本語・HTTP status・既知の `code` / `error_subcode`・固定の案内文だけ**。Graph API の自由文は載せない（設計 §6.11）
* **マイグレーションは無い。** テーブルもカラムも Permission も足さない（設計 §5 / §8）
* **TorifuneHub への変更は無い。** SaaS 固有機能（テナント・課金・コンテナ管理）に触るタスクは本プランに無い

### テストの方法（設計書に無い、プラン側で決める手段）

* **偽の Graph API（A 群）**：`fetch` の偽物は「要求の列（URL・メソッド・ヘッダ・本体・`init.redirect`・`init.signal`）を記録し、
  **URL のパスとメソッドで R1〜R6 を見分けて**、`test-support/instagram-graph.ts` の応答例から `Response` を返す関数」を各ファイルにローカルで持つ。
  `createInstagramPublisher({ fetch: fake, now, wait })` に注入する（設計 §10.1）
* **偽の `fetch` の abort の振る舞い**：`init.signal` が発火したら **`signal.reason` で reject** する（本物の `fetch` と同じ。#67 がこれを実測で固定する）。
  解決しない要求は `new Promise((_, reject) => signal.addEventListener('abort', () => reject(signal.reason)))`
* **本物の `fetch` を呼ばない仕掛け（#97）**：A 群 4 本（conformance を含む）と B 群 1 本のそれぞれの `beforeEach` で
  `globalThis.fetch` を「呼ばれたら投げる」実装に置き、`afterEach` で元へ戻す。**共有ヘルパにしない**（静的検査が各ファイルの綴りを読むため。`036` #52 / #83 と同じ）
* **`now` の注入**：可変の時計（`let current = Date.parse('2026-09-23T12:00:00.000Z'); const now = () => new Date(current);`）。
  **偽の `fetch` や偽の `wait` の中で `current` を進める**と、「R4 の前に準備期限を過ぎる」「R6 の前に残り時間が尽きる」を実時間を待たずに作れる（#47 / #49 P3）
* **`wait` の注入**：呼ばれた `ms` を記録し、即座に解決する偽物（#34 / #35 / #70）。`current += ms` も行う
* **同時本数（#33）**：偽の `fetch` が R1 を**保留**し、保留中の本数の最大値を数える。全部の R1 が来たか（あるいは上限で止まったか）を見てから順に解決する
* **逆順の応答（#32）**：子の R1 を保留し、**添字の大きいものから**解決する
* **子どうしの打ち切り（#51）**：2 番目の子の R1 だけを 400 で即返し、他の子は保留する。保留中の要求が受け取った `init.signal.aborted === true` を見る
* **定数の結線（#70）**：`036` #81 の手を写す。`AbortSignal.timeout` を差し替えて**渡った ms の列**を記録し、偽の `fetch` が呼ばれた瞬間の「直前に作られた要求ごとの ms」と URL を組にする。
  入口で作られる `PUBLISH_TOTAL_BUDGET_MS` / `PREPARE_BUDGET_MS` は**列の先頭 2 つ**として見る。`wait` に渡った ms は偽の `wait` が記録する
* **手で発火させる（#71 / #73）**：`AbortSignal.timeout` を「ms ごとに `AbortController` を作ってその `signal` を返す」実装へ差し替え、
  テスト側から `PREPARE_BUDGET_MS` / `PUBLISH_TOTAL_BUDGET_MS` の controller を `abort(new DOMException('', 'TimeoutError'))` する
* **ループバック（#64〜#68 / #98）**：`node:http` で `127.0.0.1:0` にサーバを立て、`036` #74 と同じ作法で `afterAll` に閉じる。
  **本物の `fetch` はモジュールの読み込み時に `const realFetch = globalThis.fetch` で退避**しておき、
  「書き換え前の URL が `https://graph.instagram.com/` で始まることを確かめ（始まらなければ**呼ばずに投げる**。#98）、起点だけをループバックへ差し替えて `realFetch` を呼ぶ」ラッパを `fetch` として注入する
* **B 群の偽 Graph API**：`index.ts` は `fetch` を注入しないので、**`globalThis.fetch` を偽物へ差し替える**（`036` と同じ）。
  **R3 は最初から `FINISHED` を返す**（B 群は既定の `wait`＝本物の `setTimeout` を使うので、`IN_PROGRESS` を返すと実時間で 1 秒待つ）。
  既定の `now`（実時間）を使うので、#82 の期限は **`Date.now()` からの相対**（10 日後）で作る
* **B 群の Plugin の有効化**：`discoverPlugins().plugins.find((p) => p.manifest.id === 'sns-instagram')` → `installPlugin` → `enablePlugin`（`036` と同じ）
* **#17（`social` を外した Manifest）**：`plugin.json` を書き換えず、`enablePlugin` に `{ ...entry.manifest, extensions: [] }` と実物の `entry.plugin` を渡す
  （`extensions` は省略可なので空配列で有効な Manifest になる）
* **#91（provider の衝突）**：sns-instagram を有効化したうえで、`{ provider: 'instagram', label: 'x', credentialFields: [] }` を登録するだけの合成 Plugin を `enablePlugin` に渡す
* **#87〜#90（登録時の 422）**：`import { POST } from '@/app/api/v1/social/posts/route'` を直接叩く（`036` #67 と同じ）
* **`afterEach` の掃除（B）**：`social_posts` → `social_accounts` → `plugin_store` → `plugins` → `users` の順に `deleteFrom`。
  併せて `resetPluginRegistry()` / `resetPluginRuntime()` / `resetPublisherRegistry()` / `resetPermissionRegistry()` / `resetEventHandlers()` / `resetLogger()`

## 3. タスク分解

原則：**1 タスク = 1 コミット**。各タスクは「テストを書いて失敗を確認 → 実装 → 通す」の順。

## 7. リスクと注意点

1. **`fetch(` の綴りを増やさない（T6 / #2）。** `graph.ts` の内部は `impl(url, init)` で呼ぶ。`globalThis.fetch` は `FetchImpl` の型宣言と `resolveFetch()` の中だけ
2. **`store.` / `console.` / `context.ui` という綴りを `plugins/sns-instagram/**/*.ts` のコメントにも書かない（全タスク / #7）。**
   #7 は字面で見るので、コメントの「Key-Value store.」のような文でも落ちる。「`store` を使わない」と書きたいときは `.` を続けない
3. **要求ごとの `AbortSignal.timeout` は `impl()` の直前に同期で作る（T6 / #70）。** carousel の子は並行に走るので、
   生成と呼び出しのあいだに `await` を挟むと、T18 の「直前に作られた ms」が別の子のものになり、結線が合っていても落ちる（逆に、入れ替わっていても通る）
4. **abort の理由で分類を分ける（T6 / T13 / T17）。** 本物の `fetch` は `signal.reason` で reject する。
   `AbortSignal.timeout` 由来は `TimeoutError`、子どうしの打ち切りと `input.signal` は `AbortError`（呼び出し元の `abort()` の引数による）。
   **「子どうしの打ち切りは失敗に数えない」「合計の期限は `timeout`」「`input.signal` はその場で抜ける」**を、`error.name` だけでなく**どの signal が `aborted` か**でも確かめて決める。
   偽物の reject の名前は T17（#67）の実測に合わせる
5. **`budget` の判定は `now()`、打ち切りは `AbortSignal.timeout`（T8 / T14）。** 判定を実時間だけに預けると `budget` の分岐をテストが通せない（`036` 検証レポート R-2）。
   逆に `now()` だけにすると本番で実時間の打ち切りが効かない。**両方を持つ**
6. **R4 は外側の signal の下で送る（T6 / #71）。** 準備の signal を渡すと、準備に 14 秒かかった配信の R4 が 1 秒で切られ、`retryable: false`（結果不明）を量産する
7. **R4 の後は疑わしきを `false` に倒す（T15）。** `transient`・5xx・JSON でない・`id` 無しも `false`。**SNS の投稿は取り消せない**
8. **R4 の成功後は `ok: true` を覆さない（T10 / T11）。** R5 / R6 の失敗・形の不一致・例外は `externalUrl` / `rotatedCredential` を省くだけ。
   **`try` の範囲を R4 の成功の前後で分け**、R5 / R6 の例外が外側の `catch` に落ちて `ok: false` にならないようにする
9. **`rotatedCredential` を `...credential` で組まない（T11 / #40 / #48）。** Core が将来 `credential` に何かを足しても書き戻さないため
10. **B 群は既定の `wait`（実時間）を使う（T20）。** 偽の R3 は最初から `FINISHED` を返す。`IN_PROGRESS` を返すと 1 秒ずつ実時間を待つ
11. **B 群は `globalThis.fetch` を差し替える（T19〜T21）。** `index.ts` は `fetch` を注入しない。**`afterEach` で必ず元へ戻す**
12. **#94 が落ちたら既存の spec を直さない（T22）。** #94 は「変更なしで通る」ことが条件。落ちた場合は原因（`plugin-manager.tsx` の入れ子の `section` など）を特定し、
    **直す場所（spec か Core の画面か）は設計の判断を仰ぐ**（本プランの範囲では Core を変えられない）
13. **`GRAPH_API_VERSION` の値と既知の `error_subcode` の集合は実装時に調べて固定する（T5）。** 設計はどちらも値を書いていない（設計 §6.1 / §11 #11）。
    値は Meta の公開ドキュメントから取り、**README（版）と `graph.ts` の定数（両方）**に置く。subcode の集合は小さくても安全側（`unknown`）に倒れる
14. **`plugins/` を変えたら `pnpm generate:plugins`（全タスク）。** `pnpm typecheck` は走らせないので、先に叩かないと `generated-registry.ts` が古いまま
