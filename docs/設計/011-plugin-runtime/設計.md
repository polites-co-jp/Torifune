# Plugin Runtime 設計

## 1. 目的

`010-plugin-api` で決めた契約に沿って、**Plugin が実際に動く**ようにする。

満たすべきことは5つ。

1. `plugins/` を走査してレジストリを作る（ビルド時。決定事項 D-02）
2. ライフサイクル（install / register / enable / disable / uninstall）を管理する
3. 依存関係を検証し、満たさない Plugin を有効化しない
4. Plugin のページ・メニュー・Widget・拡張点を描画する
5. イベントの購読を繋ぐ

## 3. スコープ

### やること

* `plugins/` の走査とレジストリ生成
* Plugin の状態を DB で管理する（installed / enabled / disabled）
* Manifest の検証と依存関係の解決
* `PluginContext` の組み立て
* catch-all ルート（`/plugins/[pluginId]/[[...rest]]`）
* Menu / Widget / Action / Extension Point の描画
* イベント購読の登録と解除
* Plugin の Permission 登録

### やらないこと

* 管理画面（`012-plugin-manager`）
* 再ビルドを伴う導入フロー（`012`）
* Plugin の独自マイグレーション（Store で足りるため、必要になるまで作らない）
* サンドボックス化（`03_プラグイン設計.md` §23 の将来拡張）

## 4. レイヤ配置

```text
apps/web/src/plugin/
├── store.ts          既存（010）
├── data-api.ts       既存（010）
├── logger.ts         既存（010）
├── registry.ts       読み込んだ Plugin の保持
├── loader.ts         plugins/ の走査と Manifest 読み込み
├── lifecycle.ts      有効化・無効化と状態の永続化
├── dependencies.ts   依存関係の検証
├── context.ts        PluginContext の組み立て
└── extensions.ts     UI 拡張の収集

apps/web/src/app/plugins/[pluginId]/[[...rest]]/page.tsx
plugins/                       ローカル Plugin の配置先
```

## 5. データモデル

### `plugins`（`migrations/007_plugins.sql`）

| カラム | 型 | 制約 |
| --- | --- | --- |
| `id` | `text` | PK（Plugin ID） |
| `version` | `text` | NOT NULL。導入時のバージョン |
| `status` | `text` | NOT NULL、CHECK in (`installed`, `enabled`, `disabled`) |
| `installed_at` | `timestamptz` | NOT NULL DEFAULT `now()` |
| `enabled_at` | `timestamptz` | NULL 可 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `now()` |

**`plugins` に無い Plugin は「未導入」。**
`plugins/` にファイルがあっても、DB に行が無ければ動かない。
ファイルを置いただけで勝手に動くと、意図しないコードが実行される。

### 状態遷移

```text
（ファイルがある）
      │ install
      ▼
  installed ──enable──→ enabled
      ▲                    │
      └────disable─────────┘
      │
      │ uninstall
      ▼
（行を削除）
```

## 6. API

このスプリントでは HTTP API を足さない（`012-plugin-manager` で足す）。

内部の入口：

```ts
/** ビルド時に生成されたレジストリから、有効な Plugin を読み込む。 */
export async function loadEnabledPlugins(connection: Connection): Promise<LoadedPlugin[]>;

/** UI 拡張を集める。 */
export function collectMenus(permissions: ReadonlySet<string>): MenuRegistration[];
export function collectExtensions(point: string, permissions: ReadonlySet<string>): ...;
```

## 7. 画面

### catch-all ルート

```text
/plugins/<plugin-id>/<残り>
```

* Plugin が未導入・無効なら **404**
* 登録されていないルートなら **404**
* Permission を持たなければ **403**
* **画面を隠すだけにしない。** ここで必ずサーバー側の検証を通す（`06_画面設計.md` §24, §30）

### ナビゲーションと Widget

`005-ui-shell` で確保した位置へ差し込む。

## 8. 権限（Permission）

| 操作 | Permission |
| --- | --- |
| Plugin の有効化・無効化・導入・削除 | `plugin.manage` |

Plugin が登録した Permission は `003-authorization` のレジストリへ入る。
Plugin を無効化したら取り下げる。

## 9. Plugin API への影響

`010-plugin-api` の契約を変えない。**実装だけを足す。**

## 10. 受け入れ条件

### 読み込み

1. `plugins/` にある Plugin を検出できる
2. Manifest が不正な Plugin を読み込まない
3. `plugins/` にあっても DB に行が無ければ動かない
4. `disabled` の Plugin が動かない
5. `enabled` の Plugin の `activate` が呼ばれる

### ライフサイクル

6. 導入すると `installed` になる
7. 有効化すると `enabled` になり `enabled_at` が入る
8. 無効化すると `disabled` になる
9. 削除すると行が消える
10. 二重に導入しても行が増えない
11. 有効化で `activate` が呼ばれる
12. 無効化で `deactivate` が呼ばれる
13. **`activate` が例外を投げても、本体が起動できる**
14. 例外を投げた Plugin は `disabled` になる

### 依存関係

15. 依存 Plugin が導入されていなければ有効化しない
16. 依存 Plugin が無効なら有効化しない
17. 依存のバージョンが範囲外なら有効化しない
18. 依存を満たせば有効化できる
19. **循環依存を検出する**
20. 依存されている Plugin を無効化すると、依存元も無効化される

### UI 拡張

21. メニューが追加される
22. Permission を持たないユーザーにメニューが出ない
23. Widget が追加される
24. 拡張点へ差し込める
25. Plugin が自分の拡張点を定義できる
26. 無効化すると、その Plugin の拡張がすべて消える
27. 並び順を指定できる

### ルーティング

28. 登録したページが `/plugins/<id>/...` で表示される
29. 未導入の Plugin のページが 404
30. 無効な Plugin のページが 404
31. 登録していないルートが 404
32. **Permission を持たないユーザーが 403**
33. 未認証が 401 相当（ログインへ誘導）

### イベント

34. Plugin がイベントを購読できる
35. 無効化すると購読が解除される
36. **Plugin のハンドラが例外を投げても、発火元が成功する**
37. Plugin が自分のイベントを発火できる
38. **Core のイベント名は Plugin から発火できない**

### Permission

39. Plugin が Permission を登録できる
40. 無効化すると Permission が取り下げられる
41. Plugin が `system.*` を登録できない
