## 3. security-reviewer

### 重大（修正済み）

**制御文字を含むパスで「ページ」タブが落ちる。** 受け口が制御文字入りのパスをそのまま保存し、ロールアップが
その key で内訳を書き、画面が `keys` に渡すと `isValidBreakdownKey` で 422 になって Server Component が落ちていた。
公開キーは誰でも読めるため、未認証の第三者が 1 リクエストで管理画面の一部を落とせる。

対応（設計 §5.3.6 として記録）:

1. 受け口の `normalizePath` は制御文字（0x00〜0x1f、0x7f）を含むパスを記録しない
2. ロールアップはパス別の内訳（`path_*` / `landing`）の key に制御文字を含むパスを出さない（過去の生ログの防御）
3. 画面は読んだ key を `isValidBreakdownKey` で濾してから引き直す

テスト: `access-log.test.ts`（#99）、`analytics.integration.test.ts`「制御文字を含むパスの生ログ」（#100）、
`e2e/analytics.spec.ts`「ページタブ › 制御文字を含むパス」。

### 低

| 指摘 | 対応 |
| --- | --- |
| `siteId` に UUID でない値を渡すと API が 500 | Repository で UUID でなければ空結果にした（#101）。API は 200 で `data: []` |
| `page` に上限が無く極端に大きい値で 500 | 既存の一覧 API と同じ挙動。今回は変えない（設計 §11 に記録） |
| `APP_URL` 未設定時の計測タグ `src` がヘッダ由来 | 着手前からの挙動。今回は変えない（設計 §11 に記録） |
| Plugin の `analytics.list` が上限なしで、key 付き行の分だけ量が増える | Plugin は信頼するコード。JSDoc で `key: ''` の指定を案内 |
| `docs/デザイン/` が未追跡で残っている | 設計用の作業ファイル。本ブランチではコミットしない |
