# 028 アナリティクス／ダッシュボード再設計 — 要件と裁定

設計書（`設計.md`）を書くための入力。デザインモック
[`デザイン/Torifune Analytics.dc.html`](デザイン/Torifune%20Analytics.dc.html) を
現行実装へ適用するにあたり、モックと現行実装の齟齬をユーザーに問い合わせて裁定した結果をまとめる。
**この裁定は決定事項であり、設計書はこれに従う。**

## 1. 対象画面

| 画面 | 経路 | モックの内容 |
| --- | --- | --- |
| ダッシュボード | `/dashboard` | 直近7日固定。PV / 訪問者 / 直帰率 / SNS投稿 の KPI、PV と訪問者の2本線チャート、サイト別の行（クリックで `/analytics?siteId=…&period=7d`）、実施中のキャンペーン、最近の投稿、最近の活動 |
| アナリティクス | `/analytics?siteId=…&tab=…&period=…&from=…&to=…` | 1サイトずつ表示（合算「すべて」は無くす）。期間プリセット（7日 / 30日 / 90日 / 今月 / 前月 / カスタム）と前期間比較。「Bot を集計に含める」スイッチ。サイトの下に 概要 / ページ / 参照元 / 訪問者 / 設定 の5タブ。タグ未設置のサイトは選択肢に「（未設置）」を付け、本文は導線のみ |

### サイトごとのタブ

- **概要**: KPI 5つ（PV・訪問者・セッション・直帰率・平均滞在）、日次推移（2系列）、上位ページ 5、参照元 5、時間帯別、デバイス別
- **ページ**: パス / PV / 訪問者 / ランディング / 直帰率 / 平均滞在（PV順）
- **参照元**: ホスト / セッション / 訪問者 / 直帰率 / 割合。`(direct)` を含む
- **訪問者**: 訪問者・セッション・訪問者あたり PV・1日あたり訪問者、デバイス、時間帯、Bot のアクセス（Bot PV / 人の PV / Bot の割合 / Bot が最も多かった日）
- **設定**: 計測タグ（コピー）、公開キー再発行、受信状況（状態 / 最終受信 / 最終集計 / 日付の区切り）

現行 `/analytics` にあった計測タグ一覧は、各サイトの「設定」タブへ移す。

### 前期間比較

期間と同じ長さの直前期間と比べる。率（直帰率）は pt 差、その他は % 差。
直帰率は下がると緑、それ以外は上がると緑。差が無いときは灰色。

## 2. 裁定（ユーザー決定、2026-09-04）

| # | 論点 | 裁定 |
| --- | --- | --- |
| 1 | モックにある指標（セッション・直帰率・平均滞在・Bot・時間帯・デバイス・参照元・ランディング・パス内訳）が現行 DB / ロールアップに無い | **バックエンドも拡張して全指標を出す。** 下記 §3 の提案 SQL を基にマイグレーション・ロールアップ・UseCase・API・画面までを 1 機能として通す。設計 018 の該当節は本設計で改訂する |
| 2 | 「国別のアクセス」（世界地図 + 国別表） | **今回は出さない。** 設計 018 §7「地域推定はやらない」を維持。`access_logs.country` / `pageviews_country` も追加しない |
| 3 | 配色・タイポグラフィ（`#0052ff`、Inter / JetBrains Mono / Noto Sans JP、カード角丸 24px、ピル型ボタン、ヘッダー 64px）が現行 `tokens.css` と異なる | **`tokens.css` を差し替えて全画面に適用。** 共通部品（Card / Button / Tabs / Table / Select / Input 等）も新しい見た目に更新する。フォントは Google Fonts への実行時アクセスを避け `next/font` でセルフホストする。他画面のモック（別ファイル）との整合は今回は検証しない |
| 4 | 進め方 | feature ブランチ `feature/028-analytics-dashboard-redesign` で、設計 → プラン → テスト → 実装 → 検証 の流れで進める |
| 5 | 設定タブ「公開キーを再発行」に対応する UseCase / API が無い | **実装する。** `site.update` 権限。ConfirmDialog で「既存のタグが無効になる」を確認してから実行し、監査ログに残す |
| 6 | モックの文言が集計を CLI `torifune analytics rollup` として案内しているが、実装は `POST /api/v1/analytics/rollup` のみ | **文言を API 呼び出しに合わせる。** 設計 018 §4.1 / §4.3 の CLI 記述も実装に合わせて改訂する。CLI は追加しない |
| 7 | 推移チャートが 2 系列 + Y 軸ラベル + X 軸目盛り + 凡例。設計 014 §3.1 は「軸・凡例・目盛りを持つ汎用チャートは作らない」 | **Chart 部品を拡張する**（複数系列・Y 軸ラベル 最大/中間/0・X 軸目盛り・凡例）。ライブラリは入れず SVG のまま。表による代替表示は維持。設計 014 §3.1 を改訂して記録する |
| 8 | 受信状況の 最終受信 / 最終集計 / 生ログの保持日数 | **最終受信・最終集計は出し、保持日数は出さない。** 最終受信 = `sites.analytics_last_seen_at`（rollup 時に `max(occurred_at)` を書き戻す）。最終集計 = そのサイトの `analytics.updated_at` の最大値（`source = 'core'`） |

## 3. 提案 SQL（デザイン側に同梱されていたもの。裁定 #2 により国別は除く）

```sql
-- アクセス解析の指標拡張
--
-- 方針: analytics に「内訳キー」を1列足す。指標名の列は増やさない。
--   * 参照元・ランディング・時間帯・デバイスは値の種類が開いている（ホスト名、パス、0〜23）ため、
--     metric 名に埋め込むと isValidMetricName（^[a-z][a-z0-9_]*$）に収まらない。
--   * key を持たない指標（pageviews / visitors / sessions / bounces …）は key = '' のまま。
--     Plugin の既存の record() 経路は変更不要。
--
-- 追加する Core の指標（rollup が upsert する。すべて Bot を除く）
--   metric             key                    value
--   pageviews          ''                     PV 数（既存）
--   visitors           ''                     訪問者ハッシュのユニーク数（既存）
--   sessions           ''                     セッション数（同一 visitor_hash の PV を 30 分無操作で区切る）
--   bounces            ''                     PV が 1 件だけのセッション数（直帰率 = bounces / sessions）
--   dwell_ms           ''                     同一セッション内の連続 PV 間隔の合計（ミリ秒）
--   dwell_samples      ''                     上記の間隔の件数（平均滞在 = dwell_ms / dwell_samples。最後のページは含まれない）
--   bot_pageviews      ''                     device = 'bot' の件数（表示はするが他の指標には含めない）
--   pageviews_hour     '00' 〜 '23'           時間帯別 PV（TORIFUNE_TIMEZONE で区切る）
--   pageviews_device   desktop|mobile|tablet  デバイス別 PV
--   landing            <path>                 セッション最初の PV のパス別セッション数
--   referrer           <host> | '(direct)'    セッション最初の PV の referrer_host 別セッション数
--   path_pageviews     <path>                 パス別 PV（上位ページを生ログから引かずに済ませる）
--   path_visitors      <path>                 パス別ユニーク訪問者
--   path_bounces       <path>                 そのパスでランディングし直帰したセッション数
--   path_dwell_ms      <path>                 そのパスの滞在ミリ秒合計（次の PV までの間隔）
--   path_dwell_samples <path>                 上記の件数

ALTER TABLE analytics ADD COLUMN key text NOT NULL DEFAULT '';

ALTER TABLE analytics DROP CONSTRAINT analytics_pkey;
ALTER TABLE analytics ADD PRIMARY KEY (site_id, metric_date, source, metric, key);

-- 「サイト × 期間 × 指標」で内訳を引く。
CREATE INDEX analytics_site_metric_idx ON analytics (site_id, metric, metric_date DESC);

-- 計測タグの受信状況を画面に出すため、最終受信時刻をサイトに持たせる。
-- collect が INSERT のたびに UPDATE すると書き込みが倍になるので、rollup 時に
-- max(occurred_at) を書き戻す（表示は「最終集計時点の最終受信」で足りる）。
ALTER TABLE sites ADD COLUMN analytics_last_seen_at timestamptz;

-- 生ログからセッションを組むための並び順。
-- 訪問者ハッシュは日ごとにソルトが変わるため、セッションは日をまたがない（設計 §3.2 と整合）。
CREATE INDEX access_logs_visitor_idx ON access_logs (site_id, visitor_hash, occurred_at);
```

### データの扱い（デザイン側メモより）

- 画面は `analytics` だけを読む（生ログを画面から集計しない、設計 018 §4.1 のまま）
- 新しい指標は rollup が `access_logs` から作り、`analytics` へ upsert する
- 滞在時間は同一セッション内の連続 PV の間隔から求める。計測タグは変えない。
  セッション最後のページは測れないため「実際より短め」と画面に注記する
- セッションは同一 `visitor_hash` の PV を 30 分無操作で区切る。ハッシュは日ごとに変わるので日はまたがない
- UseCase / API の追加案: `listAnalyticsBreakdown(siteId, from, to, metric)` → `[{ key, value }]` を
  key ごとに期間合計して返す。`listTopPaths` は `path_pageviews` の内訳で置き換えられる。
  `GET /api/v1/analytics/breakdown?siteId&from&to&metric` を `05_API設計.md` §33 の Pagination で
- 「Bot を集計に含める」がオンのときは、Bot は 1 アクセス = 1 セッション = 直帰として数える
  （モックの `agg()` 参照）。Bot のアクセス欄の数値はスイッチに左右されない

## 5. 既存テストへの影響（参考）

`apps/web/e2e/analytics.spec.ts` は `[data-tracking-snippet]` / `[data-site-id]`、見出し「アナリティクス」、
空状態の文言に依存し、`apps/web/e2e/dashboard.spec.ts` は見出し「直近7日」「アクセス推移」
「最近の投稿」「最近の活動」、ラベル「ページビュー（7日）」、チャートの `aria-label`、
リンク「アナリティクスで詳しく見る」に依存する。画面の文言変更に合わせてテストも更新する。
