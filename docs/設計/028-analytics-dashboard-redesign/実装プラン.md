### UI 部品の単体テストの方法（#93〜#98）

既存設定に jsdom も testing-library も無く、`.test.tsx` も無い。**新しい依存を足さず、Node 環境のまま**次で行う。

* `react-dom/server` の `renderToStaticMarkup` と `react` の `createElement` を使い、**`.test.ts`（JSX なし）**で書く。
  `.tsx` にすると `ui-shell.test.ts` の `componentFiles()`（`ui/components/*.tsx` を全部読む）の検査対象になるため避ける
* 属性の検査（`role="switch"`、`aria-checked`、`aria-current="page"`、`data-peak`、polyline の本数、凡例・軸ラベルの文字列）は静的 HTML の文字列一致で行う
* #93 の「`disabled` のときクリックしても `onChange` が呼ばれない」は DOM イベントが無いので、
  (a) 静的 HTML に `disabled` 属性が付くこと、(b) `Switch` を関数として直接呼び、返った要素の `props.onClick` を叩いても `onChange` が呼ばれないこと、の 2 つで担保する。
  **このため `Switch` は hooks を持たない制御コンポーネントにし、`onClick` を root の `<button>` に置き、ハンドラ内で `disabled` を見る**
* `SegmentedControl` は `Tabs` と同じく `next/link` を使う。`renderToStaticMarkup` で `Link` が Next のコンテキスト無しに描けない場合は `vi.mock('next/link', ...)` で `<a href>` に差し替える（属性 `aria-current` の検査には影響しない）
* 新規部品は `'use client'` を付けてよい（Node では文字列として無視される）。`useState` 等を使う部品（`settings-tab.tsx` など画面側）は単体テストの対象にせず E2E で見る

## 3. タスク分解

原則：**1 タスク＝1 コミット**。各タスクは「テストを書いて失敗を確認 → 実装 → 通す」の順。
各まとまり（G1〜G7）の最後で `pnpm test` / `pnpm typecheck` / `pnpm lint` / `pnpm format:check` が通る。
E2E（`pnpm test:e2e`）は G2・G3・G7 の終わりに全件流す（ビルドが要るため毎タスクでは回さない。
G5・G6 で既存 E2E が一時的に落ちるのは、そのタスクで E2E の書き換えも同時に行うことで最小にする）。

  マイグレーション冒頭のコメントに流し直し手順、`docs/マニュアル/アクセス解析設置.md` §4 と `README.md` に同じ手順を書く

## 5. マイグレーション

| 順 | ファイル | 内容 |
| --- | --- | --- |
| 20 | `migrations/020_analytics_breakdown.sql` | §5.1 のとおり（`key` 追加 → CHECK → PK 付け替え → `analytics_site_metric_idx` → `sites.analytics_last_seen_at` → `access_logs_visitor_idx` → `DROP INDEX IF EXISTS access_logs_path_idx`） |

* **既存データ**：`ADD COLUMN ... NOT NULL DEFAULT ''` は既存行を `''` で埋める。4 列で一意だった行は 5 列でも一意なので PK の付け替えは失敗しない。データを消す文は無い。`DROP INDEX` は索引だけ
* **ダウン**：自前ランナーは前進のみ（既存方針）。戻す必要があれば手で `key` 列と索引を落とすが、`key <> ''` の行が存在すると 4 列 PK に戻せない旨をマイグレーションのコメントに書く
* **適用後の運用手順**（マイグレーション冒頭コメント・`docs/マニュアル/アクセス解析設置.md` §4・`README.md` の 3 箇所に同じ内容）：
  1. `pnpm migrate`
  2. 保持している生ログの最も古い日を確かめる（`SELECT min(occurred_at) FROM access_logs`）
  3. `POST /api/v1/analytics/rollup` に `{ "from": "<最古の日>", "to": "<今日>" }` を渡して流し直す（400 日を超える場合は分割）
  4. 流し直せない期間の `sessions` は旧定義のまま残り、`bounces` 等は無い。集計値は消さない
* **テスト**：`useScratchDatabase` は毎回 001〜020 を適用するので、既存の結合テストがそのまま新スキーマで走る。#2 だけは 2 段適用（§3 T1）

## 7. リスクと注意点

1. **PK 変更と `ON CONFLICT`**：T1 でマイグレーションと `putPoint` の `onConflict` 列を同時に変えないと、結合テストが全滅する。T1 を分割しない
2. **集計 SQL の複雑さ**：§5.3.2 の CTE は 1 本の SQL に 19 指標の `UNION ALL` が並ぶ。Kysely の型付きビルダでは書きにくいので `sql` テンプレートで書く（現行 `aggregateDaily` と同じ）。`:tz` は `sql` の埋め込み値として 1 箇所で束ねる。`key=''` の 8 指標を「生ログがあれば 0 でも出す」ために、`logs` の (site, day) 集合を土台にした `LEFT JOIN` にする
3. **タイムゾーン境界のテスト**（#10、#14）：`process.env['TORIFUNE_TIMEZONE']` を切り替えたら `resetTimeZoneWarning()` と `resetDailySalts()` を `afterEach` で戻す（既存 `describe('1日の境目')` と同じ）。ローカルの日付で「今日」を作らない
4. **E2E の実行順依存**：ダッシュボードは全サイト合算なので、他テストが残した記録で値が動く。#67〜#72 は「出ること」と「行の存在」までにし、値の一致は #77（サイトを絞る）と #86（`pg` で前期間を投入したサイトを絞る）で見る。#89（サイト 0 件）は `pg` で `sites` を消してから開く。この 1 本は他テストと並列に走らせない（`test.describe.configure({ mode: 'serial' })` か、ファイル末尾に置く）
5. **権限なし利用者の作り方**：`viewer` は `analytics.read` を持つ（`014_analytics.sql`）。#37 / #73 / #88 は `POST /users` を `roles: []` で叩いてログインする。パスワードは既存 E2E と同じ長さの文言を使う（ポリシー）
6. **フォントのファイル名の `[`**：`next/font/local` の `src` に `Inter[wght].woff2` を渡す。Next 16（Turbopack）で角括弧の解決に失敗する場合は `Inter-Variable.woff2` 等へ改名し、`fonts/README.md` に理由を書いて報告する（設計 §7.4.5 のファイル名からの逸脱になるので、検証レポートに残す）
7. **Noto Sans JP の入手**：公式配布に可変 woff2 が無いため fonttools で変換する（T14）。変換元・ツール・バージョンを README に記録する。ファイルは 5MB 前後になるので `preload: false` を必ず付ける。**リポジトリに入れるのは woff2 と LICENSE だけ**（TTF は入れない）
8. **オフラインビルド**：`pnpm build` がフォントを取りに行かないことを、#92 の静的検査に加えて、ネットワークを切った状態の `pnpm build` で 1 回確かめる（`scripts/verify-container-rebuild.sh` の流れで）
9. **`renderToStaticMarkup` と `next/link`**：Node で `Link` が描けなければ `vi.mock('next/link')`。`Tabs` の既存挙動には触らない
10. **`ui-shell.test.ts` の px 検査**：新規部品の高さ・幅はすべて `--tf-size-*` を使う。SVG の `viewBox` の数値と `strokeWidth` は px ではないので通るが、`style={{ height: 160 }}` のような数値は既存 `Chart` にしか残さない（`'sm' | 'md' | 'lg'` へ寄せる）
11. **`page.tsx` の暫定コード**（T8）：G2 の時点で `app/analytics/page.tsx` が `listAnalyticsBreakdown` から `TopPath[]` を作る。T19 で必ず消す。残すと `TopPath` 型が画面に残り続ける
12. **`listTrackedSites` の `archived`**：現行 SQL に状態の絞りは無いので既に含まれている。T7 では #42 で明示的に確かめるだけで、`DEFAULT_LISTED_STATUSES` を持ち込まない
13. **監査ログ**：`regenerateSitePublicKey` の `audit.detail` は `() => ({ changed: ['publicKey'] })` のように**入力にも戻り値にも依存しない**形で書き、値の混入経路を作らない（#45）
14. **`dashboard.spec.ts` L95**：`[data-tracking-snippet]` の取得先を `&tab=settings` へ変えるまで（T18）ダッシュボードの E2E が落ちる。T18 のテスト書き換えで同時に直す
15. **OpenAPI のパス一覧**（`api-foundation.spec.ts` L90）：新ルートを足したら必ず更新する。忘れると E2E が落ちる
16. **SaaS 固有機能への踏み込み**：無し。サイト単位の Permission・テナント分割は設計どおり作らない
