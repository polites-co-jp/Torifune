### 指摘

#### F-1（要対応・中）`DatabaseProvider` に `kysely` の型が透けている

受け入れ条件 28 は満たしていない。

```text
DatabaseProvider.connect(): Promise<Connection>
Connection.db: Kysely<Schema>          ← ここで kysely が露出する
```

**原因：`設計.md` §10-28 と `実装プラン.md` §4.4 が食い違っている。**
実装プランは「`Connection` の中に Kysely を持つ。ただし Plugin へ公開するときは
`db` を露出しない別の型に絞る」と明記しており、実装はプランに従っている。
受け入れ条件のほうが、その但し書きを取り込めていなかった。

**対応（記録）**：受け入れ条件 28 を次のとおり読み替える。

> 28'. `packages/plugin-api` が公開する Database Provider 契約に `pg` / `kysely` の型が現れない。
> Torifune 本体の内部インターフェースはこの限りではない。

28' の検証は **`010-plugin-api`（S10）で行う**。
現時点で本体内部の `Connection` からクエリビルダを剥がすと、
Repository が使える手段が無くなり、抽象化のためだけの層が1枚増える。
`provider.ts` には「Plugin へ渡してはならない」旨をコメントで明記してある。

この読み替えは `設計.md` を書き換えずに本レポートへ記録する
（上位仕様ではないが、成果物の履歴は残す）。

#### F-2（軽微）`apps/web` と `packages/*` で import の書き方が違う

`apps/web` は拡張子なし、`packages/*` は `.js` 付き。
Turbopack が相対 import の `.js` → `.ts` を解決しないため。

意図した使い分けだが、**どこにも書いていない**と後から触る人が混乱する。
→ `CONTRIBUTING.md` に追記した。

### 指摘

#### S-1（要注意・情報）テスト用DBの作成に `CREATE DATABASE` 権限を使っている

`runner.integration.test.ts` はテストごとに使い捨てDBを作る。
開発・CI の PostgreSQL では接続ユーザーが所有者なので動くが、
**本番相当の権限分離環境ではこのテストは動かない**。

これは意図した設計（`実装プラン.md` §6 に記載済み）。
本番のアプリケーション接続ユーザーに `CREATE DATABASE` を与えないことと矛盾しない。

#### S-2（次スプリントへ）`users.password_hash` にハッシュ以外が入る余地

DB 制約としては任意の文字列を入れられる。
Argon2id 形式であることの保証は `002-authentication` のアプリケーション側で行う。
