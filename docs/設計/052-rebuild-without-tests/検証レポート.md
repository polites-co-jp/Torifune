# 052 本番のビルドの型検査からテストファイルを外す 検証レポート

`050` の実装中に見つかった、`050` より前からの不具合を直した作業単位。同梱 Plugin のフォルダが `/app/plugins` から消えると
（Plugin の削除で「ファイルも消す」を選んだ場合など）、以後のコンテナ内の再ビルドがすべて失敗し、新しく導入・削除した Plugin が反映されなくなっていた。
**ユーザー裁定（2026-10-02）**：`051` の後に別の作業単位で直す（ビルドの型検査からテストを外す方向）。

実装完了時点（`fe5edb9`）に対し、3 つの検証エージェントを**互いの結果を見せずに独立して**走らせた。

| 担当 | 判定 |
| --- | --- |
| `spec-verifier`（設計との整合） | **合格**（重大 0・軽微 3・設計書の注記 1。受け入れ条件 #1〜#17 はすべて判別力のあるテストがあり、変異 17 種はすべて検出） |
| `boundary-guardian`（境界・公開 API） | **合格**（違反 0。情報 3） |
| `security-reviewer`（セキュリティ） | **合格**（重大・中 0・低 1） |

ユニット・結合 **278 ファイル・11,617 件全通過**、typecheck / lint / format:check / `next build` 通過（ビルドの後に Next.js が設定ファイルを書き換えていないことも確認）。
E2E 全件 **502 件通過**（Playwright のコンテナ）。`./scripts/verify-container-rebuild.sh` は **#30〜#33・052 #16〜#17 すべて通過**。

---

## 1. 原因と直し方

* 原因は Next.js 16.3 の既定（`experimental.useTypeScriptCli: true`）で、ビルドが `tsc --project <tsconfig> --noEmit` を流し、
  テストファイルを含めて誤りがあれば止まるようになっていた。`apps/web/src/plugin` のテスト 27 本が同梱 Plugin のソースを直接 import しているので、
  フォルダが 1 つ消えるだけで TS2307 になり、再ビルドが失敗して前のビルドへ戻っていた（実装の前に、コンテナでそのとおり落ちることを確かめた）
* **直し方**：`apps/web/tsconfig.build.json`（`extends: "./tsconfig.json"` に `exclude` でテスト・`e2e`・`playwright.config.ts`・`src/test-support` を外す）を足し、
  `next.config.ts` の `typescript.tsconfigPath` からそれを指す。`ignoreBuildErrors` は `false` のまま
* `tsconfig.json` は変えていないので、`pnpm typecheck`（CI）とエディタは今までどおりテストまで型検査する
* Plugin のコードは、生成されたレジストリの import から辿られて**今までどおり型検査される**（Plugin に型の誤りを入れるとビルドが止まることをコンテナで確かめた）
* Dockerfile・entrypoint・CI・API・Plugin API は変えていない

## 3. 検証で確かめたこと

* `spec-verifier` は、ビルド用の設定と `next.config.ts` への変異 17 種（テストの除外を外す・`extends` を外す・`tsconfigPath` を外す・
  `ignoreBuildErrors` を true にする・本番コードから test-support や同梱 Plugin を import する・CI の手順を変える など）をすべて検出した。
  本物の `next build` でも、テストに型の誤りを入れても通り、Plugin に入れると止まることを確かめた
* `security-reviewer` は、Plugin のコードが型検査から外れていないこと（Plugin の型検査はセキュリティの境界ではないが、壊れた Plugin で再ビルドが止まる挙動は変わらない）、
  本番のコードがテスト支援を import していないこと、スクリプトとテスト支援に新しい危険が無いことを確かめた。**テストは実行していない**
* `boundary-guardian` は、契約面に差分が無いこと、Torifune 単体で動くこと、`050` とは衝突なくマージできること（`git merge-tree` で確認）を確かめた
