### テストの方法（設計書に無い、プラン側で決める手段）

**テスト支援 `build-typecheck.ts` が持つもの**（関数の名前は test-writer が決める。export するのはテストから使うものだけ）：

* **パス**：リポジトリのルート・`apps/web`・`plugins` の絶対パス。TypeScript に渡すパスは `/` 区切りに揃える（Windows の `\` を直す）。パスの比較は `ts.sys.useCaseSensitiveFileNames` が偽なら小文字に揃えて行う（§8 の 3）
* **設定の読み込み**：`ts.getParsedCommandLineOfConfigFile(<path>, {}, { ...ts.sys, onUnRecoverableConfigFileDiagnostic })` で「ビルドの設定」（`apps/web/tsconfig.build.json`）と「検査の設定」（`apps/web/tsconfig.json`）を読む。`errors` が空でなければ例外で落とす（ファイルが無いときも、何が無いかが分かる文で落とす）。読み込みには隠す前の `ts.sys` を使う（`plugins/` は `include` の外なので root files は隠すかどうかに左右されない）
* **プログラムの options**：読んだ `options` に `noEmit: true`・`incremental: false` を上書きし、`tsBuildInfoFile` を消す（設計 §10 の「プログラム」。ディスクへ書かない）
* **同梱 Plugin の列挙**：`plugins/` の直下のディレクトリで、`plugin.json` と `index.ts` または `index.tsx` を持つもの（設計 §10 の定義。名前を書き並べない）
* **レジストリの生成**：一時ディレクトリ（`mkdtempSync(join(tmpdir(), 'torifune-052-'))`）に `scripts/generate-plugin-registry.mjs` と、隠す Plugin を除いた `plugins/` の写し（`cpSync` の `recursive` と `filter`）を置き、`execFileSync(process.execPath, [<写しのスクリプト>])` で走らせ、写しの `apps/web/src/plugin/generated-registry.ts` を読んで返す。一時ディレクトリは `finally` で消す。**隠す集合ごとにメモ化する**（同じワーカーで同じ集合を 2 度生成しない）
* **CompilerHost**：`ts.createCompilerHost(options, true)` を包み、次を足す。
  * 「X を隠す」：`plugins/X` とその下のパスについて `fileExists`・`directoryExists` が `false`、`readFile`・`getSourceFile` が `undefined`、`getDirectories` の結果から除く（設計 §10 の定義）
  * レジストリの差し替え：`apps/web/src/plugin/generated-registry.ts` の `readFile`・`getSourceFile` が渡された中身を返す（`fileExists` は `true`）
  * 「F に型の誤りを足す」：F の中身の末尾に `\nexport const __guard052: number = 'x';\n` を足して返す（設計 §10 の定義）
  * **解析の使い回し**：`getSourceFile` は、モジュールの中の 1 つのキャッシュ（パス × 中身の文字列 → `SourceFile`）から返す。中身が同じなら同じ `SourceFile` を返し、2 つ目のプログラムからは解析をしない。`shouldCreateNewSourceFile` が真ならキャッシュを使わない（§8 の 2）
* **プログラムを作る**：`ts.createProgram({ rootNames, options, host, oldProgram })`。`oldProgram` は §8 の 2 の規則でだけ渡す。誤りは `ts.getPreEmitDiagnostics(program)` のうち `category === ts.DiagnosticCategory.Error` のもの（設計 §10 の「誤り」）。失敗の文に誤りの一覧（ファイル・code・文）を出す（`ts.formatDiagnostics`）
* **import 指定子の走査（#15）**：`ts.preProcessFile(text, true, true)` の `importedFiles`（静的 import・`export … from`・`import()`・`require()`、複数行を含む）を取り、相対指定子はファイルの場所から、`@/` は `apps/web/src` から `path.resolve` し、`<リポジトリ>/plugins/` の下かを見る（§8 の 6）

**各テストファイルでの使い方**：

* `program`：`beforeAll` で「ビルドの設定・何も隠さない」のプログラム P0 を 1 回作り、#7・#8・#9・#15 で共有する。#13 は P0 を `oldProgram` にして作る
* `hidden-plugins`：#10 は `it.each`（同梱 Plugin の列挙から作る）で 1 件ごとに 1 つのプログラム、#11 は 1 つ。P0 はこのファイルでは作らない（`oldProgram` を渡さない。§8 の 2）
* `check-config`：#12・#14 でそれぞれ 1 つ。`oldProgram` は渡さない
* プログラムを作る `it`・`beforeAll` には**明示のタイムアウト**（`120_000` ms）を付ける。プログラムは `it` の中の変数に置き、配列やモジュールの変数に溜めない（P0 を除く。メモリを返す）
* **リポジトリを書き換えないことの確かめ**：`hidden-plugins` と `check-config` は、`afterAll` で `apps/web/src/plugin/generated-registry.ts` の中身が `beforeAll` の時点と同じであることを見る（生成を写しの中で走らせたことの確かめ）

## 3. タスク分解

原則：**1 タスク = 1 コミット**。G1 の最後で `pnpm test` / `pnpm typecheck` / `pnpm lint` / `pnpm format:check` / `pnpm build` が通る。E2E とコンテナでの確認は T5 で全件流す（T2 の赤の確かめを除く）。

**test-writer → implementer への受け渡しの単位は G（まとまり）。** test-writer は G1 のテスト（T1 の Vitest・T2 のコンテナの検査）を先に書いて赤を確かめ、`test:` でコミットする。implementer は T3 で通す。
**implementer はテストを書き換えない。** テストが設計と食い違うと判断したら、設計書のどこと食い違うかを報告して止まる。

**着手順の骨子**：Vitest のテスト（赤）→ コンテナの検査（赤）→ ビルドの設定（緑）→ 文書 → 最終確認 → 3 つの検証。

  * **赤**（`tsconfig.build.json` が無い・`tsconfigPath` が無い）：#1・#2・#3・#7・#8・#9・#10・#11・#13・#15

| # | 論点 | プランでの扱い | 設計書の該当節 |
| --- | --- | --- | --- |
