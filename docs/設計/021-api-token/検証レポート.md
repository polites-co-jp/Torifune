### #8 について

Token 認証の失敗には、`defineRoute` の既定 Rate Limit（IP ＋ operationId ごとに
300回/分、`022-hardening`）がかかる。**Token 単位の失敗回数は数えていない。**

数えるには、存在しない Token のハッシュをキーにして記録することになるが、

* 存在しない Token は毎回違う値になりうるので、キーが無限に増える
* 総当たりの相手は Token 空間（256bit）であり、IP 単位の 300回/分で
  現実的な時間内には尽きない

いまの既定で足りていると判断した。**足りなくなる条件**は、
分散した多数のIPからの総当たりで、そのときは IP 単位ではなく
「認証失敗の総数」で絞る必要がある。共有ストアの話（`022-hardening` §3.2）と同じ。

## 残ること（意図的）

* Token の更新（名前・Scope の変更）は入れない。作り直せばよく、
  変更を許すと「いつからその Scope だったか」が追えなくなる
* 管理者による他人の Token の閲覧・失効は入れない。
  必要になったときの要求と合わせて設計する
* 設定画面のAPIタブ（`06_画面設計.md` §16）は `015b-settings`（T4）
