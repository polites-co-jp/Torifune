### 確定事項（設計書から。プランで蒸し返さない）

* **Core（`apps/web` / `packages/plugin-api` / `migrations`）に 1 行も足さない。** 作るのは `plugins/sns-x-manual/` の 5 ファイル、`plugins/sns-x-api/` の 7 ファイル、テスト 8 本とテスト支援 1 本、E2E の 1 件追加だけ（設計 §1 / §3 / §4.3 / §9）
* **ユーザー裁定（2026-09-23）：Plugin を 2 つに分ける。** `sns-x-manual`（`manual()` だけ、`credentialFields: []`、`limits` なし）と `sns-x-api`（`publish()` と `manual()`、OAuth 1.0a の 4 値、`limits: { mediaMax: 4 }`）。**どちらも `provider: 'x'` / `label: 'X'`**（設計 冒頭 / §3.1）
* **2 つは互いを知らない。** `dependencies` で結ばない。相互の import もしない。共有パッケージも作らない（設計 §4.1 / §4.2）
* **`x-text.ts` を 2 つの Plugin にバイト単位で同じ内容で置く**（設計 §4.2 の案 D）。一致は #9（静的）と #10（振る舞い）で固定する。**直すときは 2 ファイルを同じコミットで直す**
* **どちらも状態を持たない。** `store` を読みも書きもしない、`registerSettings` を呼ばない、`context.ui` / `context.data` を呼ばない。`extensions` は **`['social']` ちょうど**、`permissions: []`（設計 §5.3 / §7 / §8 / §8.1）
* **`sns-x-api` は OAuth 1.0a だけ。** OAuth 2.0 に対応しない。`rotatedCredential` を返さない（設計 §5.2 / §6.7）
* 署名は **Web Crypto（`crypto.subtle`）の HMAC-SHA1**。`node:crypto` の import も依存の追加もしない。R2（multipart）と R3（JSON）の本体は署名に含めない（設計 §6.3）
* 外へ出す要求は **R1（画像の GET）・R2（`POST /2/media/upload`）・R3（`POST /2/tweets`）の 3 種類だけ**。`sns-x-manual` は 1 本も出さない。`/2/users/me` を呼ばない（設計 §6）
* **`bodyMaxLength` を宣言しない。** 本文の判定は `x-text.ts` の `checkXText()`（重み付きの 280・intent URL の 2048）だけ（設計 §9.1 / §9.2）
* **`sns-x-manual` の `validate()` は `deliveryMode: 'auto'` を断る**（`draft` も断る。設計 §9.3 / §11 #1）
* `manual()` の URL は **`https://x.com/intent/tweet?text=<encodeURIComponent(composeXText(post))>`**。`url=` を使わない（設計 §9.4）
* `externalUrl` は **`https://x.com/i/status/<id>`**。tweet id が `^[0-9]{1,20}$` に合わなければ **`{ ok: true }` だけ**（設計 §6.7）
* **`retryable` の支配的な規則**：R3 の前は既定 `true`（直らないものは `false`）、R3 の後は既定 `false`（429 だけ `true`）（設計 §6.8）
* `reason` に載せてよいのは **固定の日本語・R2 / R3 の HTTP status・固定の案内文だけ**。**R1 の status は載せない。X API の応答の本体はエラーの分類に読まない**（設計 §6.5 / §6.9）
* **マイグレーションは無い。** テーブルもカラムも Permission も足さない（設計 §5 / §8）
* **SaaS 固有機能（テナント・課金・コンテナ管理）に触るタスクは本プランに無い**

### テストの方法（設計書に無い、プラン側で決める手段）

* **2 つの `x-text.ts` に同じ表を掛ける**：`import * as manualText from '…/plugins/sns-x-manual/x-text'` と `import * as apiText from '…/plugins/sns-x-api/x-text'` を
  `describe.each([['sns-x-manual', manualText], ['sns-x-api', apiText]])` に渡す。**表（入力と期待値の配列）はファイルに 1 つだけ**置き、#10 の 20 通り以上の組もこの表から作る
* **偽の X API（A 群）**：`fetch` の偽物は「要求の列（URL・メソッド・ヘッダ・本体・`init.redirect`・`init.signal`）を記録し、**URL のホストとパスで R1 / R2 / R3 を見分けて**、
  `test-support/x-api.ts` の応答例から `Response` を返す関数」を各ファイルにローカルで持つ。`createXApiPublisher({ fetch: fake, now, nonce })` に注入する（設計 §10.1）
* **偽の `fetch` の abort の振る舞い**：`init.signal` が発火したら **`signal.reason` で reject** する（本物と同じ。#56 が実測で固定する）。
  **本体は `test-support/x-api.ts` の関数が作る、signal と結びついた `ReadableStream`**（ヘッダの後に abort されると本体の読み込みも reject する。#57）
* **`now` の注入**：可変の時計（`let current = Date.parse('2026-09-23T12:00:00.000Z'); const now = () => new Date(current);`）。
  **偽の `fetch` の中で `current` を進める**と、「媒体の合計時間を使い切る」「R3 の前に残りが 10 秒を切る」を実時間を待たずに作れる（#41 の P1 / P3）
* **`nonce` の注入**：呼ばれるたびに `'nonce-0001'`, `'nonce-0002'`, … を返す偽物。#33 は同じ列を別に作り直して `buildOAuth1Header` を呼び、ヘッダと比べる
* **R1 の本体の打ち切り（#41 P1 / #54）**：`Content-Length` の無い `ReadableStream` を 64 KiB ずつ `pull` で出し、**`pull` の回数と `cancel` の呼び出し**を記録する。上限を超えた時点で `cancel` され、最後まで `pull` されていないことを見る
* **定数の結線（#60）**：`038` T18 の手を写す。`AbortSignal.timeout` を差し替えて**渡った ms の列**を記録し、偽の `fetch` が呼ばれた瞬間の「直前に作られた要求ごとの ms」と URL を組にする。
  入口で作られる `PUBLISH_TOTAL_BUDGET_MS` / `MEDIA_BUDGET_MS` は**列の先頭 2 つ**として見る（§8 の 5）
* **手で発火させる（#41 の「制限時間」/ #61 / #63）**：`AbortSignal.timeout` を「ms ごとに `AbortController` を作ってその `signal` を返す」実装へ差し替え、

## 3. タスク分解

原則：**1 タスク = 1 コミット**。各タスクは「テストを書いて失敗を確認 → 実装 → 通す」の順。
各まとまり（G1〜G9）の最後で **`pnpm generate:plugins`** → `pnpm test` / `pnpm typecheck` / `pnpm lint` / `pnpm format:check` が通る。
E2E（`pnpm test:e2e`）は **G1 の T2（#86 を先に確かめる）と G9 の T25** で全件流す。

**test-writer → implementer への受け渡しの単位は G（まとまり）**。test-writer は G の中の全タスクのテストを先に書いて失敗を確かめ、implementer が G の中のタスクを順に通す。

**着手順の骨子**：骨格 → **既存 E2E への影響を先に確かめる（#86）** → 純関数（`x-text.ts`・一致の固定）→ 2 つの `validate()` / `manual()` → 署名 → 外部 I/O の正常系 →
`retryable` と秘匿 → 偽物と本物の一致・定数の結線 → Core を通した結合と入れ替え → 文書と静的検査。

**`036` / `038` の検証で見つかった型を、ここでは最初から入れている**（設計 §10.12）：

| 型 | 見つかった所 | 本プランで潰すタスク | 受け入れ条件 |
| --- | --- | --- | --- |
| 1. 偽物が本物と違う振る舞い（`redirect: 'error'`、ヘッダ後の abort で本体が読めた） | `036` R-1 / `038` 軽微-2 | T10（`redirect: 'manual'` と signal に結んだ本体を最初から）、**T17（ループバック）** | #37、#52〜#59 |
| 2. 取得先の status を `reason` に反射（内部ネットワークの走査） | `036` 中-1 | T12（R1 の失敗は二分だけ）、T16（`reason` / `logger` の検査） | #47〜#50 |
| 3. 外部の文字列を Core の列へ載せる前に形と長さを見る（合わなくても失敗にしない） | `036` 低-1 | T11（tweet id）、T14（媒体 ID） | #64〜#67 |
| 4. 制限時間の定数がどの要求へ渡るかを見ていない／合計の期限が無く `budget` が死んでいた | `036` R-2 / R-3 | T10（入口で合計の期限）、T13 / T15（`now()` を進めて `budget` を踏む）、**T18（URL ↔ ms の突き合わせ）** | #41 P1 / P3、#60〜#63 |
| 5. テスト名と中身が別物・到達できない分岐を検証済みと名乗る | `038` 軽微-1 | T13〜T15（各テストが `fields.phase` をアサート）、T15（#45 の後半はテストを作らない） | #41、#45 |
| 6. 本物の `fetch` が外へ出る | `036` #52 / `038` #97 | 全タスク（`throwingFetch`）、T17（ラッパ）、T24（静的検査） | #89〜#92 |

## 7. リスクと注意点

1. **`fetch(` / `globalThis.fetch` の綴りを増やさない（T1 / T10 / #2 / #6）。** `xapi.ts` の内部は `impl(url, init)` で呼ぶ。
   `XApiPublisherOptions.fetch` の型は `FetchImpl`（`typeof globalThis.fetch` と書くと #2 が落ちる。§8 の 2）。**`sns-x-manual` にはコメントでも `fetch(` を書かない**
2. **`store.` / `console.` / `context.ui` という綴りをコメントにも書かない（全タスク / #8）。** #8 は字面で見る
3. **要求ごとの `AbortSignal.timeout` は `impl()` の直前に同期で作る（T10 / #60）。** 本件の 3 つの要求の定数はすべて 10 秒なので、**値の一致だけでは結線を確かめられない**。
   #60 は「生成の順と要求の順の対応」で見る。実装側で生成と呼び出しのあいだに `await` を挟むと、突き合わせが別の要求の ms を拾う
4. **abort の理由で分類を分ける（T10 / T15 / T17）。** `AbortSignal.timeout` 由来は `TimeoutError`、`input.signal` は `AbortError`。
   **「合計・媒体の期限は `timeout`」「`input.signal` はその場で抜ける」**を、`error.name` だけでなく**どの signal が `aborted` か**でも確かめて決める。偽物の reject の名前は #56 の実測に合わせる
5. **`budget` の判定は `now()`、打ち切りは `AbortSignal.timeout`（T12 / T13 / T15）。** 判定を実時間だけに預けると `budget` の分岐をテストが通せない（`036` R-2）。逆に `now()` だけにすると本番で打ち切りが効かない。**両方を持つ**
6. **R3 は外側の signal の下で送る（T11 / #61）。** 媒体の signal を渡すと、画像に 14 秒かかった配信の R3 が 1 秒で切られ、`retryable: false`（結果不明）を量産する
7. **R3 の後は疑わしきを `false` に倒す（T15）。** 5xx・JSON でない・`id` 無し・ヘッダの後の abort も `false`。401 / 403 も `false`。**SNS の投稿は取り消せない**
8. **201 を返した後は `ok: true` を覆さない（T11 / #64〜#66）。** tweet id の形が合わなければ `externalId` / `externalUrl` を省くだけ（`036` 低-1）
9. **R1 の status を外へ出さない（T13 / T16 / #48）。** `reason` の文と `logger` の `fields` のどちらにも。`retryable` の判断にだけ使う。**`fields` に `status: undefined` のキーを置くのも避ける**（#48 は「項目が無い」）
10. **資格情報の形を入口で見る（T11 / P0）。** 改行を含む値は `Authorization` を作れず `fetch` が同期で投げ、`network` に化けて `true` を繰り返す（`038` §6.2）
11. **偽物を本物に合わせる向きを間違えない（T10 / T17）。** 偽の本体は signal と結んだ stream、`redirect: 'manual'` の 3xx は `Response` として返す。**conformance が落ちたら実装を本物に合わせる**
12. **テスト名と通った分岐を一致させる（T13〜T15 / #41 / #45）。** 各テストは `fields.phase` をアサートする。**到達できない分岐（R3 の後の予期しない例外）を検証済みと名乗るテストを作らない**
13. **`x-text.ts` の複製を片方だけ直さない（T3〜T6 以降すべて）。** 直したら `cmp` で確かめてからコミットする。`prettier --write` / `eslint --fix` も 2 ファイルに同じく掛かることを確かめる（整形の差で #9 が落ちる）
14. **#86 が落ちたら既存の spec を直さない（T2）。** 「変更なしで通る」ことが条件。原因を特定し、**Plugin の `name` / `description` で避けられるか**を見たうえで、直す場所の判断を仰ぐ（本プランの範囲では Core の画面も既存 spec も変えられない）
15. **`plugins/` を変えたら `pnpm generate:plugins`（全タスク）。** `generated-registry.ts` は Git 管理外で、`pnpm typecheck` は生成を走らせない。先に叩かないと古いまま
16. **B 群は `globalThis.fetch` を差し替える（T19〜T22）。** `index.ts` は `fetch` を注入しない。**`afterEach` で必ず元へ戻す**。既定の nonce は本物の `crypto.getRandomValues`、既定の時計は実時間
17. **`\p{Extended_Pictographic}` の範囲（T3）。** この性質は `©` `®` `‼` のような U+10FF 以下の記号も含むので、設計 §9.4 の規則ではこれらが 2 と数えられる。
    公式の `twitter-text` と一致するかは本プランでは確かめていない。**設計の規則のまま実装し、テストで固定した表の外へ「直さない」**（食い違いが分かったら設計 §11 に足す）
18. **公開リポジトリである（T23 / 全コミット）。** README・コメント・コミットメッセージは第三者が読む。料金の数値・運営側の事情を書かない
19. **`scripts/verify-container-rebuild.sh` は Docker が要る（T25）。** 無い環境では飛ばし、**飛ばしたことを検証レポートへ申し送る**
20. **実機の X で一度も動かさない（設計 §11 #12）。** T17 が保証するのは「偽物が本物の `fetch` と同じに振る舞う」ことまで。
    署名が正しいことは公開の計算例で固定する（#27）が、`api.x.com` の v2 が同じ署名・multipart の形を受けること、`/intent/tweet` と `/i/status/<id>` が期待どおり開くこと（設計 §11 #7）は**運用者の実機確認**に残る
