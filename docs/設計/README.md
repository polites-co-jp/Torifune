# 機能別 詳細設計

`docs/仕様書/` がシステム全体の**上位仕様**（安定した基盤）であるのに対し、
このディレクトリには**機能単位の詳細設計**を積む。開発はここを起点に進める。

## 構成

機能ごとに1ディレクトリを作る。

```text
docs/設計/
├── 001-plugin-manager/
│   ├── 設計.md          design-writer が作成。以降すべての工程の唯一の入力仕様
│   ├── 実装プラン.md    impl-planner が作成
│   └── 検証レポート.md  検証3エージェントの結果をまとめたもの
└── 002-.../
```

* `<ID>` は3桁連番。既存の最大値+1
* `<slug>` は英小文字ケバブケース

## 開発フロー

```text
design-writer → impl-planner → test-writer → implementer → 検証3種
```

`/feature <機能名>` で一連の流れを起動できる。詳細はリポジトリルートの `CLAUDE.md` を参照。

## 上位仕様を変更したくなったら

`docs/仕様書/` は勝手に書き換えない。矛盾を見つけた場合は、
どの文書のどの節と食い違うかを明示して判断を仰ぐこと。
