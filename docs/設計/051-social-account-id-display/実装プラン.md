### テストの方法（設計書に無い、プラン側で決める手段）

* **単体の固定値**（#1〜#10）：アカウントは 2 つ。ID は UUIDv7 の形で**先頭 8 桁が同じ・末尾だけ違う**値（例 `0192b7a0-5c1e-7a3b-9f10-2d7c4e8a1b23` と `0192b7a0-5c1e-7a3b-9f10-2d7c4e8a1b9f`。英字 `a`〜`f` を含めて大文字・小文字の取り違えを見分けられるようにする）。表示名は `とりふね公式`（`bluesky`）ともう 1 つ（`x`）
* **行の切り出し**：`renderToStaticMarkup` の出力を `<tr` で区切り、`<th` を含む先頭（見出しの行）を除いた残りを行とする。どの行かは行の中の表示名で選ぶ（並びに頼らない）。「タグを外したテキスト」は `social-accounts.test.ts` の `textOf` を写す
* **ID の要素**：行の HTML から `<code[^>]*data-account-id="…"[^>]*>(…)</code>` を切り出す。#4 は中身の `<wbr/>` の数と、各 `<wbr/>` の直前の文字が `-` であることを見る（`renderToStaticMarkup` は `<wbr/>` と出す）
* **#7 の行**：既定の 2 行とは別に、provider `mastodon`（`providers` に無い）と `constructor` の行を持つ props で描く
* **クリップボードの偽物**（#11〜#15）：`{ writeText: vi.fn(async () => {}) }` の形。#13 は `new DOMException('denied', 'NotAllowedError')` で reject、#14 は同期で `throw`。`vi.stubGlobal` を使う件は `afterEach(() => vi.unstubAllGlobals())`
* **静的検査**（#16〜#19）：`stripComments`・`isHardCoded`・`isHardCodedShort` を `social-credential-static-checks.test.ts` から**写す**（テストファイルを import しない）。判別力の件（直書きを見分ける・コメントは数えない・短い語「コピー」が長い文言の部分文字列に反応しない）を同じ形で足す。#17 は `import { … copyText … } from '@/ui/client/clipboard'` を正規表現で見る。#18 は `ui/components/index.ts` の `export { … }` の名前を集めて `/Copy|Clipboard/i` に当たらないこと
* **E2E の補助**：`origin`・`unique`・`csrf`・`postJson`・`deleteJson` は `social-credentials.spec.ts`、閲覧者・権限なしの利用者のログインは `social-approval.spec.ts` の `viewerBrowserContext` を写して `roles` を引数にする。アカウントは provider `x`・資格情報なし・`status: 'disconnected'`、表示名 `E2E アカウントID ${unique()}`
* **E2E の行**：`page.getByRole('row').filter({ hasText: displayName }).filter({ has: page.locator('[data-account-id]') })`（閲覧者には「資格情報を設定」が無いので、`social-credentials.spec.ts` の `accountRow` の絞り方は使えない）。「コピー」は行の中で `getByRole('button', { name: accountIdCopyAriaLabel 相当の文字列, exact: true })`
* **E2E のクリップボード**：読む件は `context.grantPermissions(['clipboard-read', 'clipboard-write'])` の後に `page.evaluate(() => navigator.clipboard.readText())`。件の最初に `page.evaluate(() => window.isSecureContext)` を見て、false なら理由を付けて `test.skip`（設計 §10.4）
* **E2E の Toast**：`page.getByRole('status').filter({ hasText: 文言 })` で探す（ページに他の `status` があっても取り違えない）
* **E2E の掃除**：`afterAll` で作ったアカウント（#24 の画面で作った分も、`GET` で引いた `id` を記録する）と利用者（#25・#29）を消す。後の `social-approval.spec.ts` などの前提を壊さない

## 7. リスクと注意点

1. **見出しの直書き（T3）。** 「アカウントID」は `labels.ts` から引く（#19 が落ちる）。既存の列の見出し（「サービス」など）は本件で動かさない（触ると差分が広がる）
2. **ID の分割（T3）。** `<wbr>` は `id.split('-')` の区切りの間に入れる。区切りの `-` は文字として残す（#3 のテキストの一致・#27 の選択の文字列が 36 文字になる）。`key` の重複に気を付ける（各片と `<wbr>` に添字のキー）
3. **`globalThis.navigator?.clipboard`（T2）。** DOM の型では `navigator.clipboard` は省略不可なので、ESLint の型つきの規則が `?.` を「不要な条件」と言う場合がある。設計のコードは Node（テスト・Server Component の描画）で `navigator` が無い場合も守るためのもの。規則に当たったら、意味を変えない書き方（例：`typeof navigator === 'undefined' ? undefined : navigator.clipboard` を既定値の式にする）で通し、#15 で既定の経路を確かめる。**規則を止めるコメントは足さない**
4. **文書の静的検査（T4）。** `static-checks.test.ts` #81（`SNS投稿の外部連携.md`）、`text-input-docs-static-checks.test.ts` #54（`SNS投稿API仕様.md` §1.3・§1.4）、Plugin の README を読む `sns-x-static-checks.test.ts` #11・`help-guides-static-checks.test.ts` #69 などが文書の文字列を見る。**書き足す・言い換えるだけにし、既存の文を消さない**
5. **E2E の掃除（T1）。** このファイルは `social-approval.spec.ts` などより**前に**走る。作ったアカウント・利用者を `afterAll` で必ず消す。Plugin は導入しない
6. **E2E と `pnpm test` を同時に流さない（T5）。** どちらも postgres-test（21701）を使う
7. **公開リポジトリ（全コミット）。** コメント・コミットメッセージ・文書に外部の製品名や運営側の事情・作業機の事情を書かない
