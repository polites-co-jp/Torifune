# 051 SNS アカウントの ID の表示とコピー 検証レポート

外部アプリが `POST /api/v1/social/posts` で投稿先に指定する `socialAccountId`（アカウントの ID）を、管理画面 `/social` の
アカウント一覧で見て写せるようにした作業単位。画面で登録したアカウントの ID を、運用者が外部アプリへ伝える手段が画面に無かった。
**ユーザー裁定（2026-10-02）**：画面に ID の表示とコピーを足す。`050` を終えてから着手する。

実装完了時点（`74139d2`）に対し、3 つの検証エージェントを**互いの結果を見せずに独立して**走らせた。

| `boundary-guardian`（境界・公開 API） | **合格**（違反 0・軽微 2） |
| `security-reviewer`（セキュリティ） | **合格**（重大・中 0・低 2。どちらも念のための記載） |

## 1. 入れたもの

* `/social` のアカウント一覧に列「アカウントID」（ハンドルと資格情報の間）を足し、**ID を全桁**で出す。UUIDv7 は続けて登録すると先頭が揃うので、
  短くすると見分けられない。ハイフンの後でだけ折り返し、1 クリックで全体を選べる
* 各行に「コピー」ボタン。押すとクリップボードへ ID を写し、成功・失敗を Toast で知らせる。写せない環境では、ID を選んで写すよう案内する
  （古い写し方への切り替えは入れない。既存の「タグをコピー」と同じ扱い）
* 見えるのは `social.read` を持つ人（閲覧者を含む）。API の `GET /social/accounts` で同じ人がすでに読める値で、新しく露出する値は無い
* API・DB・OpenAPI・Permission・Plugin API・公開の UI 部品（`ui/components/index.ts`）は変えていない
* 文書：API 仕様書 §4.2・§4.4・§9、手順書（全体の流れ・§2「画面で登録したアカウントを使う」・§3）、X の 2 つの Plugin の README、035 §7.5、039 §7.3.1

## 2. 検証で確かめたこと

* `spec-verifier` は全件のテストを流し、`clipboard.ts`・一覧・文言へ変異を入れた。単体テストで落ちない変異は 4 つで、
  1 つは等価（`undefined` の早期の戻りを消しても例外が拾われて同じ結果）、2 つは E2E が担う（写す値・Toast の文言の入れ替え）、
  1 つは設計が目安とした列の幅だった。既存のテストは 1 件も変わっていない
* `security-reviewer` は、権限の無い人・未認証の人の HTML に ID が出ないこと、資格情報が新しいセルや属性へ漏れないこと、
  表示名やサービス名が属性や Toast で HTML にならないこと、クリップボードには ID だけを写し読み取りはしないこと、新しい書き込みの口が無いことを確かめた。
  **テストは実行していない**
* `boundary-guardian` は、契約面（API・Plugin API・公開の UI 部品）に差分が無いこと、新しい部品が UI 層の中で閉じていること、
  文書の書き戻しがコードと一致すること、SaaS の内部事情や外部の名前が混ざっていないことを確かめた

## 3. 指摘と対応

| 出所 | 指摘 | 対応 |
| --- | --- | --- |
| spec 軽微 1 | テストのハンドルに予約されていないドメイン（`example.social`）を使っている | **`social.example` に直した** |
| spec 軽微 2 | 単体テストで落ちない変異（写す値・Toast の文言・列の幅） | 記録のみ（E2E が担う／設計が目安とした値） |
| boundary 軽微 1 | 実装プランに作業機の事情（3000 番ポートが使えない・作業機の DB）が書かれている | **環境に依らない書き方に直した** |
| boundary 軽微 2 | 035・039 の追記で作業単位の番号にバッククォートが無い（表記の揺れ） | **揃えた** |
| security 低 | 表示名が `aria-label` に入る（React が属性値をエスケープするので XSS にならない）／E2E の使い捨ての利用者のパスワードの直書き（既存の E2E と同じ） | 記録のみ |
