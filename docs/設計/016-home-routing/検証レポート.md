### 個別の根拠

| # | 条件 | 根拠 |
| --- | --- | --- |
| 1 | 管理者0人 → `/setup` | 結合「管理者が0人のとき /setup へ送る」 |
| 2 | 管理者あり・未ログイン → `/login` | 結合「管理者がいてセッションが無いとき」＋ E2E「未ログインでトップページを開くと」 |
| 3 | ログイン済み → `/dashboard` | 結合「ログイン済みのとき」＋ E2E「ログイン済みでトップページを開くと」 |
| 4 | 無効・期限切れのセッション → `/login` | 結合2件（不正トークン／`expires_at` を過去へ更新） |
| 5 | 管理者0人ならセッションがあっても `/setup` | 結合「管理者が0人であれば、有効なセッションがあっても」 |
| 6 | 本文を描画しない | `HomePage` の戻り値が `Promise<never>`。JSX を返す経路が無い |
| 7 | 静的化されない | `export const dynamic = 'force-dynamic'` |
| 8 | リクエスト文脈なしで呼べる | 結合テストが `resolveHomeDestination` を直接呼べている（`cookies()` を内部で呼んでいたら呼べない） |
| 9 | Plugin を起動しない | `home-destination.ts` / `page.tsx` に `ensurePluginsStarted*` の呼び出しが無い |
| 10 | `/setup` は管理者がいるとき 404 のまま | E2E「管理者がいる状態では /setup が 404 になる」 |
| 11 | `/dashboard` は未認証で `/login` へ | E2E「未ログインでダッシュボードを開くとログイン画面へ送られる」 |
| 12 | ログイン後に `/dashboard` へ到達 | E2E「ログイン画面からログインしてダッシュボードへ行ける」 |

### 特筆すべき検証

* **#5 判定順序を固定した。** 「管理者0人＋有効なセッション」で `/setup` を期待する
  テストが1本ある。判定を逆順（セッション → セットアップ）に書いても他の5件は
  通ってしまうため、**この1本だけが設計 §4 の順序を守らせている**
* **#8 は「テストが書けたこと」自体が根拠になっている。** 判定を `page.tsx` に
  直接書いていたら Next.js のリクエスト文脈が要り、この6件を書けなかった

## 3. セキュリティ（security-reviewer 観点）

| 観点 | 結果 |
| --- | --- |
| 状態の露出が増えていないか | ✅ 下記のとおり、`/setup` の既存の可視性を超えない |
| 認証の判定を自前で書いていないか | ✅ `buildAuthorizationContext` に委ねる。トークンの検証を再実装していない |
| 期限切れ・失効セッションを通さないか | ✅ 結合テストで確認（期限切れ → `/login`） |
| 未認証で `/dashboard` へ送らないか | ✅ `identity === null` のとき `/login`。仮に誤って送っても `/dashboard` 側が弾く（多層） |
| 認可の判定を UI 層へ移していないか | ✅ Permission を見ていない。認可は遷移先の `requirePageSession` のまま |
| リクエスト由来の値を信用していないか | ✅ Cookie のトークンは検証を通す。`x-forwarded-for` / `user-agent` は監査情報として渡すだけ |
| 本文に内部状態を出していないか | ✅ 本文を描画しない |

### 状態の露出についての判断

`/` の遷移先から「セットアップ済みかどうか」が匿名の相手に分かるようになる。
これは**既存の可視性を超えない**と判断した。

`/setup` は管理者が0人なら誰にでも 200 を返し、1人でもいれば 404 を返す
（`auth.spec.ts` で確認済み）。したがって `/setup` を1回叩けば同じことが分かる。
`/` の振り分けは新しい情報を与えない。

なお `/` は「管理者の人数」「ログイン中のユーザー」を本文へ一切出さない
（そもそも本文を持たない）。

## 5. 既存テストへの影響と対応

実装の副作用で既存テストが2箇所影響を受けた。**いずれも実装前に直した。**

| ファイル | 影響 | 対応 |
| --- | --- | --- |
| `e2e/smoke.spec.ts` | 「トップページが『とりふね』を表示する」が意味を失う | 削除し、振り分けの2件へ差し替え |
| `e2e/ui-shell.spec.ts` | `loginViaUi` が `waitForURL('**/')` で待っており、`/dashboard` へ抜けると待ちが解けない | `waitForURL('**/dashboard')` へ変更 |

`smoke.spec.ts` の旧テストは、**リダイレクト後も偶然通ってしまう**点に注意が要った。
`/login` の見出しも「とりふね」であるため、残していれば緑のまま意図を失っていた。
