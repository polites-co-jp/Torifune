# 018-analytics 検証レポート

## 収集方式の裁定（この設計の主眼）

`02_データベース設計.md` §5.8 が「誰が集めるのか」を決めていなかった問題は、
**Torifune 自身が計測タグで集める**ことで決着した。
外部サービスの値も同じ受け皿へ入れられる（`source` で区別）。

判断の理由は設計 §2 に記録した。要点は
「アクセス解析のために別サービスを必須にするのは、
**マーケティング活動を一元管理する**という Torifune の目的に反する」。

## 受け入れ条件

| # | 条件 | 判定 | 根拠 |
| --- | --- | --- | --- |
| 1 | 計測タグを貼ったページからアクセスが記録される | ✅ | E2E「アクセスを集めて集計し、画面で見られる」（`/t.js` → `/api/v1/collect` → 集計 → 画面） |
| 2 | **IPアドレスと User-Agent の生値が保存されていない** | ✅ | 結合テスト「IPアドレスと User-Agent の生値を保存しない」（全行を文字列検索） |
| 3 | 訪問者ハッシュが日をまたぐと変わる | ✅ | `access-log.test.ts`「ソルトが変わると値が変わる」 |
| 4 | 不正なサイトキーでは記録されない | ✅ | 結合テスト ＋ E2E |
| 5 | Bot は記録されるが集計に含まれない | ✅ | 結合テスト2件 |
| 6 | ロールアップを2回流しても値が二重にならない | ✅ | 結合テスト「2回流しても値が二重にならない」 |
| 7 | 画面で期間とサイトを絞って日次の値を見られる | ✅ | E2E |
| 8 | Plugin が集計値を読み書きできる。生ログは読めない | ✅ | `PluginDataApi.analytics` に `list` / `record` のみ。**生ログは型として存在しない** |
| 9 | `analytics.read` が無ければ 403 | ✅ | 結合テスト ＋ E2E（未認証は 401） |

## 実装中に見つけて直したこと

### `pgcrypto` を要求していた

公開キーの生成に `gen_random_bytes` を使っており、これは pgcrypto 拡張が要る。
**拡張を入れられない環境（管理された PostgreSQL など）を排除してしまう。**

組み込みの `gen_random_uuid()`（PostgreSQL 13以降、暗号論的に安全）を
2つ繋いで64桁の16進にする形へ直した。

### 計測の受け口が CSRF で必ず落ちていた

E2E が 403 で捕まえた。計測ビーコンは**測定対象サイトのブラウザから**
送られるため、Origin 検証も double-submit cookie も通らない。

CSRF は「ブラウザが Cookie を自動送信すること」への対策であり、
セッションに紐づく操作をしないこの口では守るものが無い。

`defineRoute` に `csrfExemptReason` を足した。
**理由を書かないと外せない**（空文字は定義時に例外）。
`permission: null` に `reason` を要求しているのと同じ形にそろえた。

### アナリティクス画面が 500 になっていた

`Table` は Client Component で、列定義の `render` は関数。
**Server Component から関数を渡せない**（React が拒否する）。
画面を Client Component にして直した。理由をファイル先頭に書いた。

### 新しいAPIが仕様書に載っていなかった

`api/endpoints.ts`（OpenAPI 生成のためにルートをまとめて読み込むファイル）へ
登録し忘れていた。**T3〜T5 で足した口も同様に漏れていた**ので、
まとめて登録した。E2E が実測で捕まえた。

## 意図的に残した限界

1. **大量の書き込みを捌く作りではない。** `access_logs` へ素直に INSERT する。
   高トラフィックのサイトでは足りない。足りなくなったら受け口とDBの間に
   キューを挟む（`POST /api/v1/collect` の形は変えずに済む）
2. **日をまたぐと同じ訪問者を数え直す。** ソルトを日ごとに変えるため。
   追跡できないことのほうが重要という判断（設計 §3.2）
3. **プロセスを再起動するとその日のソルトが変わる。** その日の訪問者が
   二重に数えられる。避けるにはソルトの保存が要るが、保存すると
   過去のソルトで追跡できてしまう
4. **`sessions` は「訪問者 × 日」。** 30分区切りのセッション定義は
   滞在時間を持たせないと出せず、いま必要な精度ではない。
   定義を変えるときは指標名も変える（過去の値と混ぜない）
5. **チャートを出していない。** 共通部品は `014-dashboard` で作る
