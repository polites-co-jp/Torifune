### 確定事項（設計書から。プランで蒸し返さない）

* **ユーザー裁定 1**：手順書は Torifune の中で表示する。各 Plugin が自分のフォルダに Markdown で同梱し、Manifest の省略できる項目 `help` で宣言する。外部サイトへのリンクで済ませない
* **ユーザー裁定 2**：ヘルプボタンは `/social` の 2 つの Modal（アカウント追加・「資格情報を設定」）と Plugin の設定画面（`/plugins/<id>/settings`）。**`/plugins` のカードには置かない**
* **ユーザー裁定 3**：`/plugins` の「設定」の 404 を直す。行き先は `/plugins/<id>/settings` だけ、`/plugins/<id>` へのリンクを出さない
* **オーケストレーター判断（2026-09-24、4 件とも (a)）**：設定画面は「設定か手順書を持つ、読み込まれた Plugin」に出す／`react-markdown` ＋ `remark-gfm` ＋ `rehype-slug`（MIT）を足す／`sns-x-manual` に手順書を付けない／有効にする前の Plugin の手順書に画面の入口を作らない（URL で読め、README にその URL を書く）
* **Plugin API は追加だけ**：`PluginHelpDoc`・`PluginManifest.help?`・`PLUGIN_HELP_LIMITS`・`ManifestValidation` の `ok: true` の `warnings?`。**`PLUGIN_API_VERSION` は `1` のまま**（設計 §9）
* `help` の形の誤りは **Manifest を拒否しない**。`help` 全体を無いものとして扱い（`manifest` に `help` のキーを持たせない）、`warnings` に `{ field: 'help' }` を 1 件。誤りが無ければ `warnings` のキーごと省略（設計 §6.1 / §9.2）
* ファイルは**要求のたびに実行時に読む**。埋め込み・キャッシュをしない。`realpath` で Plugin のフォルダの外へ出ないこと・256 KiB・UTF-8 を確かめる。**例外を投げず理由のコードだけを返す**（設計 §4.1 / §6.2）
* 認可：**読み込まれた Plugin の手順書は認証済みなら誰でも**。読み込まれていない Plugin は `plugin.manage` を中で求め、無ければ **404（`NotFoundError`）**。UseCase は `permission: null` と理由（設計 §6.3 / §8）
* 描画は **Server Component の中で React の要素に**。`rehype-raw` を入れない、`dangerouslySetInnerHTML` を使わない、生の HTML はエスケープして見せる、画像は `［画像：alt］` の文字、リンクは `resolveHelpLink` で `external` / `internal` / `none`（設計 §7.3）
* ヘルプボタンは**新しいタブ**（`target="_blank" rel="noopener noreferrer"`）。手順書の画面の中の Torifune 内のリンクは同じタブ（設計 §7.3.1 / §7.4.2）
* `/api/v1`・OpenAPI・`migrations`・Domain・Infrastructure・`scripts/generate-plugin-registry.mjs` を変えない（設計 §5 / §6 / #71）
* 手順書は 4 本（`sns-bluesky` / `sns-x-api` / `sns-instagram` / `sns-threads`）、いずれも `id: 'credentials'`・`path: 'help/credentials.md'`・`help` はこの 1 件だけ。`example-plugin` に見本 2 本（`usage` / `markdown`）。**スクリーンショットを載せない**（設計 §12）
* 文言は `ui/help/labels.ts` に置き、部品に直書きしない（設計 §7.7 / #73）
* 検証は **`spec-verifier` / `boundary-guardian` / `security-reviewer` の 3 つ**（Core と公開 Plugin API を変えるため。設計 冒頭）
* **SaaS 固有機能（テナント・課金・コンテナ管理）に触るタスクは本プランに無い**

## 3. タスク分解

原則：**1 タスク = 1 論理変更**。各タスクは「テストを書いて失敗を確認 → 実装 → 通す」の順。
各まとまり（G1〜G10）の最後で **`pnpm generate:plugins`** → `pnpm lint` / `pnpm format:check` / `pnpm typecheck` / `pnpm test` が通る（`DATABASE_URL` は試験用の PostgreSQL、`TORIFUNE_ENCRYPTION_KEY` は CI の試験用の鍵）。

**test-writer → implementer への受け渡しの単位は G（まとまり）。** test-writer は G の中の全タスクのテストを設計書だけを見て書き、**失敗を確かめて**からコミットする（`037`〜`040` と同じ運用）。

### G3. Plugin 層：ファイルの読み出しと警告のログ

#### T4. `readPluginHelpFile`

* **何をするか**：`help-files.ts` に設計 §6.2 の 6 段：`realpath(pluginDirectory)` → `resolve(base, relativePath)` が `base + sep` で始まらなければ `outside_plugin_dir`（ファイルに触れない）→ `realpath(candidate)`（無ければ `not_found`）が `base + sep` で始まらなければ `outside_plugin_dir` →
  `stat` が通常のファイルでなければ `not_file`、大きさが `maxFileBytes` 超えなら `too_large` → 読んで `TextDecoder('utf-8', { fatal: true })`（失敗で `invalid_encoding`）、先頭の U+FEFF を除く → 読んだバイト数も上限と比べる。
  **例外を投げない**（上に無い失敗は `not_found`）。戻り値は `{ ok, markdown }` か `{ ok: false, reason }` だけ
* **テストを先に書く**：`help-files.test.ts`（#8〜#15）
* **対象**：`apps/web/src/plugin/help-files.ts`
* **完了条件**：#8〜#15（#10 / #11 は作れない環境で飛ばしたことが出力に残る）
* **依存**：T2（`PLUGIN_HELP_LIMITS`）
* **注意**：
  * `base + sep` との比較は**大文字・小文字を区別する**（Windows でも `realpath` の結果どうしを比べるので揃う）。`base` そのもの（`relativePath` が空）も外として扱う
  * 読み出しは `readFile` を 1 回（`stat` の後に大きくなった場合は 6 段目で `too_large`）。ストリームにしなくてよい（上限 256 KiB）
  * `TextDecoder` の `ignoreBOM` を既定のままにすると BOM は消える。**#8 は BOM を除いた本文ちょうど**を見るので、既定の振る舞いに任せても自前で除いてもよいが、二重に除かない（本文の先頭が U+FEFF の 2 つ目なら 1 つだけ除く）

**破壊的変更は無い。**

## 7. リスクと注意点

1. **`PluginRow` に必須の項目を足すと既存のテストが型で落ちる（T16）。** `plugin-manager.test.ts` は `BASE_ROW: PluginRow` を型注釈付きで組む。UI の型では省略可にする（§8 の 1）。`PluginSummary`（Application）は必須のまま
2. **本物の `discoverPlugins` を通さないと #38 のログが見えない（T10）。** `@/plugin/loader` を差し替える `plugin.integration.test.ts` の手を写さず、`@/plugin/generated-registry` を差し替える
3. **先頭の見出し 1 を消す場所（T8）。** `rehype-slug` より**前**（remark の段）で消すと、題名と同じ文言の見出しの番号（`-1`）が GitHub と食い違う。`rehype-slug` の**後**で木から外す
4. **`react-markdown` の既定の `urlTransform`（T8）。** 既定は危ないスキームを `''` に変えてから `components.a` へ渡す。`resolveHelpLink('')` は相対パスとして宣言と一致せず `none` になるので #25 は通る。**`urlTransform` を差し替えない**（二重の守り。§8 の 8）
5. **Windows でシンボリックリンクを作れない（T4）。** 飛ばしたことを出力に残す。CI（Linux）では走る。フォルダは `junction` を先に試す
6. **`discoverPlugins` の警告は呼ぶたびに出る（T5）。** 形の誤った Plugin があるとログが増える。設計 §9.2 は回数を決めていない。1 回に絞る仕組み（プロセスの状態）を足さない
7. **Server Component とクライアントの境界（T8 / T9 / T17）。** `social-accounts.tsx` は `'use client'`。`HelpLink` と `labels.ts` は import してよいが、`markdown-view.tsx` と `react-markdown` 系を**直接も間接にも**持ち込まない。#65 は直接の import だけを見るので、**`help-link.tsx` から `markdown-view` を import しない**ことは T27 の 2（バンドルの grep）で裏づける
8. **`ui/` から `node:` を import しない（T6）。** `help-links.ts` の POSIX の正規化は自前で書く
9. **Prettier が Markdown を整形する（T19・G8）。** 表の桁揃え・`*` → `-`・`_` のエスケープ。`--write` の後に語の検査（#67）と見本の意図を読み直す
10. **手順書の中身は公式の説明と突き合わせてから（G8）。** 開けない頁（JavaScript で描く頁）がある。**推測で埋めない**。確かめられなかった手順は本文に明記し、確認記録に残す。第三者のブログを使わない
11. **E2E の実行環境（T20 / T27）。** 作業機の 3000 番が別のアプリに使われていることがある（`reuseExistingServer` がそれを Torifune と思って使う）。塞がっていれば Playwright のコンテナで流す（`039` §8 の 35）。**`git archive HEAD` は未コミットの変更を含まない。E2E を `pnpm test` や `verify-container-rebuild.sh` と同時に流さない**
12. **`verify-container-rebuild.sh` はスクリプトを変えずに使う（T27）。** 手順書のファイルがイメージに入っているかは、残ったイメージに対する別のコマンドで確かめる。Docker が無ければ飛ばして申し送る
13. **新しいテストファイルの名前を `sns-` で始めない（G8）。** `sns-threads` / `sns-x` の本数を固定する検査が落ちる
14. **`plugins/` を変えたら `pnpm generate:plugins`（全タスク）。** `generated-registry.ts` は Git 管理外で、`pnpm typecheck` は生成を走らせない。`help` の宣言はここに埋め込まれる
15. **公開リポジトリである（全タスク）。** 手順書・README・コミットメッセージは第三者が読む。手順書に自分のアカウント名・App の ID・トークンの一部を書かない（見本の値は `xxxx-xxxx-xxxx-xxxx`・`17841400000000000` のような明らかな例にする）
16. **読み込まれていない Plugin の手順書を URL で読めるのは `plugin.manage` だけ（T10）。** 画面からの入口を作らない（オーケストレーター判断 #4）。README に URL を書く（T25）
