### 確定事項（設計書から。プランで蒸し返さない）

* **ユーザー裁定 1**：手順書は Torifune の中で表示する。各 Plugin が自分のフォルダに Markdown で同梱し、Manifest の省略できる項目 `help` で宣言する。外部サイトへのリンクで済ませない
* **ユーザー裁定 2**：ヘルプボタンは `/social` の 2 つの Modal（アカウント追加・「資格情報を設定」）と Plugin の設定画面（`/plugins/<id>/settings`）。**`/plugins` のカードには置かない**
* **ユーザー裁定 3**：`/plugins` の「設定」の 404 を直す。行き先は `/plugins/<id>/settings` だけ、`/plugins/<id>` へのリンクを出さない
* **オーケストレーター判断（2026-09-24、4 件とも (a)）**：設定画面は「設定か手順書を持つ、読み込まれた Plugin」に出す／`react-markdown` ＋ `remark-gfm` ＋ `rehype-slug`（MIT）を足す／`sns-x-manual` に手順書を付けない／有効にする前の Plugin の手順書に画面の入口を作らない（URL で読め、README にその URL を書く）
* **Plugin API は追加だけ**：`PluginHelpDoc`・`PluginManifest.help?`・`PLUGIN_HELP_LIMITS`・`ManifestValidation` の `ok: true` の `warnings?`。**`PLUGIN_API_VERSION` は `1` のまま**（設計 §9）
* `help` の形の誤りは **Manifest を拒否しない**。`help` 全体を無いものとして扱い（`manifest` に `help` のキーを持たせない）、`warnings` に `{ field: 'help' }` を 1 件。誤りが無ければ `warnings` のキーごと省略（設計 §6.1 / §9.2）
* ファイルは**要求のたびに実行時に読む**。埋め込み・キャッシュをしない。`realpath` で Plugin のフォルダの外へ出ないこと・256 KiB・UTF-8 を確かめる。**例外を投げず理由のコードだけを返す**（設計 §4.1 / §6.2）
* 認可：**読み込まれた Plugin の手順書は認証済みなら誰でも**。読み込まれていない Plugin は `plugin.manage` を中で求め、無ければ **404（`NotFoundError`）**。UseCase は `permission: null` と理由（設計 §6.3 / §8）
* 描画は **Server Component の中で React の要素に**。`rehype-raw` を入れない、`dangerouslySetInnerHTML` を使わない、生の HTML はエスケープして見せる、画像は `［画像：alt］` の文字、リンクは `resolveHelpLink` で `external` / `internal` / `none`（設計 §7.3）
* ヘルプボタンは**新しいタブ**（`target="_blank" rel="noopener noreferrer"`）。手順書の画面の中の Torifune 内のリンクは同じタブ（設計 §7.3.1 / §7.4.2）
* `/api/v1`・OpenAPI・`migrations`・Domain・Infrastructure・`scripts/generate-plugin-registry.mjs` を変えない（設計 §5 / §6 / #71）
* 手順書は 4 本（`sns-bluesky` / `sns-x-api` / `sns-instagram` / `sns-threads`）、いずれも `id: 'credentials'`・`path: 'help/credentials.md'`・`help` はこの 1 件だけ。`example-plugin` に見本 2 本（`usage` / `markdown`）。**スクリーンショットを載せない**（設計 §12）
* 文言は `ui/help/labels.ts` に置き、部品に直書きしない（設計 §7.7 / #73）
* 検証は **`spec-verifier` / `boundary-guardian` / `security-reviewer` の 3 つ**（Core と公開 Plugin API を変えるため。設計 冒頭）
* **SaaS 固有機能（テナント・課金・コンテナ管理）に触るタスクは本プランに無い**

**検証の後の改訂（`c238a15`）で確定したこと**

* **ユーザー裁定 U1**：`sns-instagram` の「Instagram ユーザー ID」の欄に **`auto`**（`/^auto$/i`、前後の空白は不可）を入れられる。配信の入口（準備の最初）で R0 `GET /<v>/me?fields=user_id` を **Bearer** で送り、数字の ID を得て使う。公開（R4）に成功したときだけ `rotatedCredential` の 3 項目で書き戻す。**数字の ID のときの挙動は 041 より前と同じ**。`ME_TIMEOUT_MS = 3_000`、形の誤りは `ID_UNRESOLVED_REASON`（`retryable: false`）。手順書から「トークンをアドレス欄に入れる確かめ方 B」と Graph API の版の表記を消す（設計 §6.4 / §12.4、D5）

* **どちらも Plugin の中だけ。Core・Plugin API・`039` の画面は変えない**
* **D1〜D11**：`help-files` の手順 2 の判別（D1）、上へ出る `..` を丸めない（D2）、X の 402 と未確認の 403（D3）、Threads の 90 日（D4）、Instagram の版を書かない（D5）、Threads の上級者向けの禁止の書き方（D6）、4 本にクリップボードと画面の写真の注意（D7）、Manifest の警告のログは**プロセスごと・Plugin ごとに 1 回**（D8）、**`helpDocPathsOf` を消し `getPluginHelpDoc` の結果の `docs` に `path` を含める**（D9）、GFM の脚注のリンクを `resolveHelpLink` に通さない（D10）、予約パスと「再ビルドの後から」の記述・`ui.ts` の JSDoc（任意。D11）。D12〜D14 は設計への書き戻しと記録だけ（コードの変更なし）

### テストの方法（設計書に無い、プラン側で決める手段）

* **一時フォルダ（A 群 `help-files` / B 群）**：`mkdtemp(join(tmpdir(), 'torifune-help-'))` に `<plugin-id>/help/*.md` と `<plugin-id>/plugin.json` を書く。`afterEach` / `afterAll` で `rm(…, { recursive: true, force: true })`
* **シンボリックリンク（#10 / #11）**：`symlink(target, path)` が `EPERM` / `EACCES` で失敗したら、その 1 件を `it.skip` ではなく**実行の中で `console.info` に「シンボリックリンクを作れないため飛ばした」と残して `return`** する（設計 #10 の注。飛ばしたことを出力に残す）。

1. **`PluginRow` に必須の項目を足すと既存のテストが型で落ちる（T16）。** `plugin-manager.test.ts` は `BASE_ROW: PluginRow` を型注釈付きで組む。UI の型では省略可にする（§8 の 1）。`PluginSummary`（Application）は必須のまま
