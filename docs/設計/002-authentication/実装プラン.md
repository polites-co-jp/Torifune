## 3. 設計上の判断

### 3.1 Argon2id のパラメータ

`@node-rs/argon2` の既定（OWASP 推奨相当）を使う。
自前でパラメータをひねらない。**弱くする方向の間違いのほうが起きやすい**。

パスワードの長さ上限は 1024 バイト。
上限を設けないと、長大な入力でハッシュ計算に時間を使わされる（DoS）。

### 3.2 セッショントークン

* 32 バイト（256bit）の乱数を base64url で表現する
* **DB には SHA-256 ハッシュを保存する**
* Argon2 ではなく SHA-256 にする理由：トークンは十分な長さの乱数であり、
  総当たりが成立しない。毎リクエストの検証に Argon2 を使うと遅すぎる

### 3.3 ログイン失敗の応答を揃える

「存在しないID」と「パスワード違い」で応答を分けない。
**さらに、存在しないIDのときもダミーのハッシュ検証を実行する。**
応答時間の差からアカウントの存在を推測されないようにするため。

### 3.4 CSRF：Origin 検証 ＋ 二重送信トークン

```text
1. Origin / Sec-Fetch-Site を検査する（同一オリジンでなければ拒否）
2. Cookie の csrf トークンと、ボディ or ヘッダのトークンが一致するか検査する
```

1 だけにしない理由：古いブラウザや特殊な経路で Origin が落ちることがある。
2 だけにしない理由：サブドメインからの Cookie 書き込みで破られうる。

CSRF トークンの Cookie は **`HttpOnly` にしない**（JavaScript が読む必要がある）。
セッション Cookie とは別の Cookie にする。

### 3.5 ログイン試行制限の閾値

| 対象 | 閾値 | 時間窓 |
| --- | --- | --- |
| アカウント単位 | 10 回 | 15 分 |
| IP 単位 | 30 回 | 15 分 |

IP を緩くしているのは、NAT の内側から複数人が使う環境で巻き添えを避けるため。
アカウント単位のほうを主な防御にする。

**成功したらそのアカウントの失敗記録を消す。** IP 側は消さない
（1つのアカウントに成功しただけで、他アカウントへの総当たりを許すことになるため）。

### 3.6 `/setup` の競合

管理者が0人であることの確認と作成を、**1つのトランザクションで行う**。
さらに「`administrator` ロールを持つユーザーは同時に1人しか作れない」を
DB 側でも担保するため、`users` への INSERT と `user_roles` への INSERT を同じ
トランザクションに入れたうえで、**トランザクション内で `administrator` ロールの
保持者数を `SELECT ... FOR UPDATE` 相当で数える**。

実装としては、`roles` の administrator 行を `SELECT ... FOR UPDATE` でロックし、
そのうえで保持者数を数える。行ロックにより、同時実行が直列化される。

### 3.7 Notifier

パスワードリセットの通知先を抽象化する。

```text
Notifier
└── send(notification): Promise<void>
```

本設計ではログ出力実装のみ。**ログにトークンを出さない**
（開発時に必要なら、開発環境限定でリセットURLを出す口を別途用意する）。

### 3.8 認証の検証を毎リクエストで行う

セッション Cookie → `sessions` を引く → `users` を引く、を毎リクエスト行う。

キャッシュしない理由：ユーザーを無効化した直後に、キャッシュが生きている間だけ
操作できてしまう。速度が問題になるまで素直な実装にする。

## 4. テストの方針

| 種類 | 対象 |
| --- | --- |
| ユニット | password / session-token / csrf / rate-limit の判定ロジック |
| 結合 | Repository、Provider、UseCase、API ルート |
| E2E | `/setup` → ログイン → ログアウトの流れ |

API ルートのテストは Route Handler を直接呼ぶ。
HTTP サーバーを立てずに Request / Response を組み立てられるため、速い。

**テスト間の独立性**：認証のテストは users テーブルを触るため、
テストごとに一意の login_id を使い、`afterEach` で消す。

## 6. リスク

| リスク | 対応 |
| --- | --- |
| Argon2 のネイティブモジュールがコンテナで動かない | `@node-rs/argon2` は prebuilt を持つ。Docker ビルドで確認する |
| Argon2 の計算がテストを遅くする | テストでは弱いパラメータを使えるよう、パラメータを引数で受け取れる形にする |
| `/setup` の競合対策が効いているかテストしにくい | 行ロックを使い、同時実行テストで検証する |
| CSRF Cookie とセッション Cookie の取り違え | 名前を明確に分ける（`torifune_session` / `torifune_csrf`） |
