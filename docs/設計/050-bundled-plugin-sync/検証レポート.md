# 050 同梱 Plugin を起動時に plugins の Volume へ反映する 検証レポート

コンテナの更新のたびに、イメージに同梱した Plugin を plugins の Volume へ反映する仕組みを入れた作業単位。
実際の環境で「同梱 Plugin の手順書を読み込めない」ことから見つかった（Volume は初回作成時にしかイメージの中身を受け取らない）。
**ユーザー裁定（2026-10-02）**：新しい作業単位として入れる。同梱 Plugin だけを更新し、利用者が入れた Plugin は触らない。
コンテナを作り直すと利用者の Plugin がビルドから消える関連の穴（設計 §1.3）も含める（§11.1 #1 の (a)）。

実装完了時点（`479df44`）に対し、3 つの検証エージェントを**互いの結果を見せずに独立して**走らせた。

| 担当 | 判定 |
| --- | --- |
| `spec-verifier`（設計との整合） | **条件付き合格**（重大 0・軽微 6。受け入れ条件 #1〜#53 はすべて対応するテストがあり、変異 72 件のうち 66 件を検出。生き残った 6 件はテストの判別力の不足） |
| `boundary-guardian`（境界・公開 API） | **合格**（違反 0・低 4） |
| `security-reviewer`（セキュリティ） | **合格**（重大・中 0・低 4） |

指摘はすべて直した（`6d9e5b8`〜`1023a20`）。セキュリティの指摘を直した差分は `security-reviewer` に改めて見せ、見つかった直し漏れ 2 件も直した（`2b08f16`〜`80cd1e6`。§3）。

---

## 1. 入れたもの

* **同梱 Plugin の正本**をイメージの中、Volume の外（`/app/.torifune-bundled-plugins`、`TORIFUNE_BUNDLED_PLUGINS_DIR`）に置く
* 起動時に `torifune plugins sync-bundled` が正本と Volume を突き合わせる。同梱 Plugin の版は中身が変わっても上がらないので、
  **版ではなく木のハッシュ**で判定し、Volume の各フォルダに印（`.torifune-bundled`）を残す
  * 前回の同期のままのもの → 新しい版に入れ替える
  * 利用者が更新・編集したもの（中身が印と違う）・自分で入れた Plugin・隔離中のもの → 触らない
  * 050 より前の Volume（印が無い）→ Volume の版が新しければ触らない。同じか古ければ退避してから入れ替える
  * 消えた同梱 Plugin → 戻す（DB に行が無いので「検出済み」に出るだけ）
* 入れ替えは作業用のフォルダへ写してハッシュを確かめ、rename 2 段で行う。失敗したら元に戻し、残骸は次の起動で片付ける
* **起動時の突き合わせ**（裁定 (a)）：Plugin のソースの指紋と、ビルドに記録した指紋が違えば、起動の前に 1 回だけ再ビルドする。
  同梱 Plugin だけの環境は再ビルドしない
* データモデル・HTTP API・OpenAPI・Permission・Plugin API は変えていない（`PLUGIN_API_VERSION` は 1）。
  `apps/web` の本番コードの変更は、Package の検査で `.torifune-` で始まる項目を断る 1 か所だけ（§2 の security 低-2）

## 2. 指摘と対応

| 出所 | 指摘 | 対応 |
| --- | --- | --- |
| spec 軽微 1 | 木のハッシュと指紋の行の形・並べ替えを固定するテストが無く、並べ替えを外す・`f` と `l` を区別しない・行からパスやフォルダ名を落とす変異が生き残った | **テストを足した**（既知の答えのハッシュ、readdir の順を逆にしても同じ値、並びを変えない改名、ファイルとリンクの区別、中身の入れ替え）。生き残った変異をすべて検出することを確かめた |
| spec 軽微 2 | 「同期 → 起動時の突き合わせ」の順を固定していない | **テストを足した** |
| spec 軽微 3 | 同梱の `plugin.json` が読めない・Volume の `<id>` がディレクトリでない・`plugins fingerprint` の失敗、の経路にテストが無い | **テストを足した** |
| spec 軽微 4 | 設計 §10.6 #46 の手順の順序が、直した検証スクリプトと合っていない | **注記を足した**（利用者の Plugin を導入してから、作り直しの直前に消す） |
| spec 軽微 5 | 運用文書の参照先の見出しの名前が違う | **直した** |
| spec 軽微 6 | テストの型が実装と結び付いていない（動的 import） | 記録のみ（実装プラン §8 の 21 で承知のうえ。パリティテストは静的 import に直した） |
| security 低-1 | 印を書くときにシンボリックリンクを辿り、リンク先のファイルを root で上書きしうる | **直した**（先にリンクそのものを消し、新規作成だけを許して書く）。リンクのときに外のファイルが変わらないテストを足した |
| security 低-2 | Package の中に `.torifune-` で始まる印を入れられ、偽の印で利用者が更新した版を同梱の版へ戻させうる | **直した**（Plugin のフォルダの直下に `.torifune-` で始まる項目を持つ Package を断る）。Plugin 開発ガイド・012 設計を更新 |
| security 低-3 | 同期のログに Volume のフォルダ名をそのまま出し、偽の行を差し込める | **直した**（Plugin の ID の形でない名前は引用符で囲み、表示できない文字を `\uXXXX` にする） |
| security 低-4 | 隔離の印の判定が、指紋（lstat）とビルドの生成（リンクを辿る）で食い違う。指紋を計算できないと再ビルドの確認を黙って飛ばす | **直した**（生成も lstat で判定する。飛ばしたことをログにはっきり出す）。ファイルを丸ごと読んでハッシュする点は記録のみ（設計 §11.2 の 6） |
| boundary 低 1 | `TORIFUNE_PLUGINS_DIR` を `/app/plugins` 以外に変えると、起動のたびに再ビルドが走り続けうる（050 より前から再ビルドが成り立たない構成） | **運用文書に「変えない」と書いた** |
| boundary 低 2 | README の「利用者が入れた・直した Plugin は触らない」が、050 より前の Volume の扱いと少し食い違う | **補足した**（日本語・英語） |
| boundary 低 3 | パリティテストの説明が古い | **直した** |
| boundary 低 4 | 新しい環境変数の説明が薄い | **運用文書に環境変数の節を足し、entrypoint にコメントを足した** |

| 項目 | 結果 |

| `./scripts/verify-container-rebuild.sh` | 実装完了時点で **#30〜#33 通過**。修正は entrypoint のログの文言とコメントだけなので流し直していない |
| `./scripts/verify-bundled-plugin-sync.sh`（新規） | 実装完了時点と修正の後のどちらも **#43〜#49 通過**。古い Volume ＋新しいイメージで同梱 Plugin が更新されて手順書が読めること、手で直した同梱 Plugin が残ること、消した同梱 Plugin が戻ること、利用者の Plugin が 1 バイトも変わらず作り直しの後も動くこと、その後の再ビルドが更新後のソースを使うこと |
| `security-reviewer` の再確認（`479df44..1023a20` だけ） | 重大・中 0。**直し漏れの低 2 件**：(a) Package の予約名の検査が、空の要素や `.` の要素を挟んだパス（`x//.torifune-bundled`・`x/./.torifune-bundled`）で素通りできた → 空の要素と `.` の要素を持つパスを断り、予約名は大文字小文字を区別せずに断るよう**直した**。(b) 同期のログに Volume の `plugin.json` の版の文字列をそのまま出していた → 版の形でなければ引用するよう**直した**（どちらも先にテストを書き、直す前に落ちることを確かめた）。印の書き込み・退避先の扱いは外へ書く経路が無いこと、生成スクリプトが ENOENT 以外で止まるようにした点は起動を止め続ける DoS にならないことを確かめた |

## 4. 残るもの

| # | 内容 |
| --- | --- |
| 1 | **同梱 Plugin のフォルダが Volume から消えると、コンテナ内の再ビルドが失敗し続ける**（050 より前から。web のビルドが、同梱 Plugin のソースを読むテストまで型検査するため。前のビルドに戻るので動き続ける）。050 が入れば、次の起動で戻る。**ユーザー裁定（2026-10-02）：051 の後に別の作業単位で直す** |
| 2 | ファイルを丸ごと読んでハッシュする（巨大なファイルでメモリを使う。設計 §11.2 の 6） |
| 3 | 設計 §11.2 の 1〜5（同梱 Plugin の版の上げ方、DB の版とのずれ、一覧の文言、起動時の再ビルドを壊した Plugin の隔離、Package の展開が古いファイルを残す） |
| 4 | 起動猶予が短い基盤では、起動前の再ビルドの途中で止められ続けて起動できなくなりうる（設計 R2・R3。運用文書に記載） |
