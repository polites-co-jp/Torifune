### 確定事項（設計書から。プランで蒸し返さない）

* **ユーザー裁定（2026-10-02、設計 §11.1 #1）：(a) 起動時の突き合わせと再ビルド（設計 §6.7）を `050` に含める。** よって §6.7 に属する条件（#36〜#42、#43 の `.next/torifune-plugin-sources` の比較、#48 の後半、#49 の最後の文）も**すべて範囲に入る**。受け入れ条件は **53 件すべて**
* 同梱 Plugin の写しを**Volume の外**の `/app/.torifune-bundled-plugins` にイメージのビルドで残し、`ENV TORIFUNE_BUNDLED_PLUGINS_DIR` で宣言する。写しのトップレベルの、名前が `.` で始まらないディレクトリが「同梱 Plugin」（設計 §6.1）
* 見分け方は**同期が書いた印（`.torifune-bundled`）と木のハッシュ**。版番号は印の無い古い Volume に限って補う（設計 §6.2・§6.3）。判定は §6.3 の表を**上から順に最初に当たった行**
* 置き換えは作業用ディレクトリへ写し、ハッシュを確かめてから **rename の 2 段**（設計 §6.4.1）。作業用・退避は `<plugins>` 直下の `.` で始まるディレクトリ
* 同期は `entrypoint.sh` の監視ループの**前に 1 回**、CLI `torifune plugins sync-bundled` で行う。**失敗しても起動は止めない**（設計 §6.5）
* 指紋（設計 §6.7.1）はトップレベルの `.` で始まらず隔離されていないディレクトリの木のハッシュを名前順に連結したもの。ビルドの指紋は **`.next` の中**（`apps/web/.next/torifune-plugin-sources`）。起動時に食い違えば**多くても 1 回**再ビルドする。監視ループの中の再ビルドは**指紋を見ずに必ず走る**（設計 §6.7.3）
* `generate-plugin-registry.mjs` は名前が `.` で始まるディレクトリを飛ばす（設計 §6.4.3）
* **データモデル・マイグレーション・HTTP API・OpenAPI・Permission・公開 Plugin API・画面は変えない。** `apps/web` の本番コードは 1 行も変えない（テストだけ足す）。`PLUGIN_API_VERSION` は `1` のまま（設計 §4〜§9）
* CLI は `apps/web` に依存しない。版の比較は CLI の中に同じ規則で置き、一致を `apps/web` 側のテストで確かめる（設計 §4・#20）
* 既存のテストは**書き換えない**（設計 §10.8）。`verify-container-rebuild.sh` は**スクリプトを変えずに**通る（#50）
* 文書の書き戻しは設計 §12 の範囲。`docs/仕様書/`・OpenAPI・`docs/Eventリファレンス.md`・`docs/UI Componentリファレンス.md` は変えない
* 設計 §11.2 の 5 件（同梱 Plugin の版の付け方、DB の版のずれ、一覧の文言、起動時の再ビルドを壊した Plugin の隔離、Package の展開の残りファイル）は**本プランに入れない**
* **SaaS 固有機能（テナント・課金・コンテナ管理）に触るタスクは本プランに無い。** コンテナイメージの起動手順は D-02 の再ビルドのために本リポジトリが持つもので、デプロイ基盤には踏み込まない（設計 §2）

**モジュールの形（test-writer と implementer の共通の約束。§8 の 2）**：

```ts
// tree-hash.ts
export const BUNDLED_MARKER = '.torifune-bundled';
export const QUARANTINE_MARKER = '.torifune-quarantine';
export function hashPluginTree(dir: string): Promise<string>;      // 'sha256:<64 桁>'
export function fingerprintPlugins(pluginsDir: string): Promise<string>;

// version.ts
export function compareVersions(a: string, b: string): number;     // 1 / -1 / 0

// sync-bundled.ts
export function parseMarker(raw: string): string | null;           // 有効な印の hash。無効なら null
export type VolumeState =
  | { readonly kind: 'missing' }
  | {
      readonly kind: 'present';
      readonly quarantined: boolean;
      readonly hash: string;                 // H
      readonly markerHash: string | null;    // M（有効な印が無ければ null）
      readonly version: string | null;       // Volume の plugin.json の version（読めない・文字列でなければ null）
    };
export type BundledDecision =
  | { readonly result: 'restored' }
  | { readonly result: 'unchanged' }
  | { readonly result: 'adopted' }
  | { readonly result: 'updated'; readonly backup: boolean }      // backup: true が legacy
  | { readonly result: 'skipped'; readonly reason: 'quarantined' | 'modified' | 'unreadable manifest' }
  | { readonly result: 'skipped'; readonly reason: 'newer version'; readonly installedVersion: string };
export function decideBundled(input: {
  readonly bundledHash: string;              // I
  readonly bundledVersion: string;
  readonly volume: VolumeState;
}): BundledDecision;
export function decideUnbundled(markerHash: string | null): 'kept' | 'untouched';
export interface SyncFileOps {
  copyDir(from: string, to: string): Promise<void>;   // §6.4.1 の 1。シンボリックリンクは辿らず写す
  rename(from: string, to: string): Promise<void>;
  remove(path: string): Promise<void>;                // 無くても失敗しない再帰削除
  writeFile(path: string, data: string): Promise<void>;
}
export const nodeFileOps: SyncFileOps;
export interface SyncSummary {
  readonly updated: number; readonly restored: number; readonly adopted: number; readonly unchanged: number;
  readonly skipped: number; readonly kept: number; readonly failed: number; readonly untouched: number;
}
export function syncBundledPlugins(options: {
  readonly bundledDir: string;
  readonly pluginsDir: string;
  readonly stdout: (text: string) => void;   // RunIo と同じく改行込みの文字列
  readonly stderr: (text: string) => void;
  readonly ops?: SyncFileOps;                // 既定は nodeFileOps
  readonly now?: () => Date;                 // 印の syncedAt
}): Promise<{ readonly exitCode: 0 | 1; readonly summary: SyncSummary }>;

// command.ts
export function parseSyncBundledArgs(argv: readonly string[], env: Readonly<Record<string, string | undefined>>):
  ParseResult<{ readonly bundledDir: string | null; readonly pluginsDir: string }>;
export function parseFingerprintArgs(argv: readonly string[], env: Readonly<Record<string, string | undefined>>):
  ParseResult<{ readonly pluginsDir: string }>;
export function runPlugins(argv: readonly string[], io: RunIo): Promise<number>;
```

`ParseResult` と `RunIo` は `index.ts` の既存の型を使う。`command.ts` は `import type` で読み、`index.ts` は `command.ts` の `runPlugins` を読む（型だけの import なので実行時の循環は生じない）。

## 3. タスク分解

原則：**1 タスク = 1 コミット**。G1 の終わりと G2 の終わりで `pnpm test` / `pnpm typecheck` / `pnpm lint` / `pnpm format:check` が通る。E2E とコンテナでの検証の最終の通しは T13 でだけ流す。

## 7. リスクと注意点

1. **写しでシンボリックリンクの文字列を変えない（T4）。** Node の `fs.cp` は既定で相対リンクを絶対パスへ書き換える。`verbatimSymlinks: true`（かつ `dereference: false`）で写さないと、`T` の木のハッシュが `I` と合わず、リンクを含む同梱 Plugin が毎回 `FAILED` になる。#17 の配置にリンクを 1 つ含める件を `it.skipIf` つきで足してよい
2. **`set -eu` とコマンド置換（T9）。** `fp=$($CLI plugins fingerprint ...)` が失敗すると entrypoint ごと落ちる。`if fp=$(...); then ... else ... fi` の形にし、同期・指紋の失敗が起動を止めないこと（#35・#39）。`$CLI` は既存の `$START_CMD` と同じく引用せずに展開する（`TORIFUNE_CLI_CMD` に引数を含められるように）
3. **S のテストを Windows で動かす（T7）。** `sh` は Git for Windows のもの。パスは `/` 区切りにし、スタブは `sh <path>` で呼ぶ（実行ビットに頼らない）。`cp -a` は Git Bash にある。`sh` が無い環境では飛ばし、CI（Linux）では必ず走る
4. **C のログ待ちの取り違え（T7）。** 既存の `wait_for_log` はログに印が一度でも出れば返る。作り直した後のコンテナでは起動前の再ビルドで `rebuild succeeded` が既に出ているので、#49 の削除の後の再ビルドを待つには**出現回数が増えるまで待つ**関数を使う（§8 の 12）。起動前の再ビルドは数分かかるので、`wait_for_app` の前に `rebuild succeeded` を待つ
5. **指紋はビルドの前に計算する（T9）。** `next build` は `.next` を消してから作るので、指紋の書き込みはビルドの**後**。`pnpm build` は CLI の `dist` も作り直すので、指紋の計算（CLI を使う）はビルドの**前**に済ませる。ビルドが成功しても `$NEXT_DIR` が無ければ書かない（`mkdir` で作らない。次の起動で食い違いとして扱われ、もう一度ビルドされる）
6. **イメージをビルドするスクリプトを同時に流さない（T7・T11・T13）。** `verify-container-rebuild.sh` と `verify-bundled-plugin-sync.sh` は既定で同じイメージ名を使う。新しいスクリプトのネットワーク・コンテナ・Volume の名前は既定で `torifune-verify-bundled` から作り、既存のものと重ねない。`MSYS_NO_PATHCONV=1` を既存と同じく立てる
7. **文書の静的検査の文字列を消さない（T12）。** `apps/web/src/application/social/static-checks.test.ts` #81 などが `docs/Plugin開発ガイド.md` を読む。§10 に書き足すだけにし、既存の文を消さない
8. **置き換えの失敗で前の退避を失う（T4・T5）。** legacy は「既存の退避を消す → `D` を退避へ → `T` を `D` へ」の順なので、最後の rename で失敗すると `D` は戻るが前の退避は消えている。設計 §6.3 の「ID ごとに最新の 1 つだけ」の範囲で、置き換え前の中身は `D` に残るので受け入れる
9. **`TORIFUNE_PLUGINS_DIR` を `/app/plugins` 以外へ向けた構成。** 生成スクリプトは `repoRoot/plugins` を読み、同期と指紋は `TORIFUNE_PLUGINS_DIR` を見る。今のイメージは `/app/plugins` に固定しているので食い違わない。`050` より前からの前提で、本件では変えない
10. **公開リポジトリ（全コミット）。** コメント・コミットメッセージ・文書に外部の製品名・運営側の事情・作業機固有の事情を書かない
11. **新しいシェルスクリプトの実行ビット（T7）。** Windows で作ると実行ビットが立たない。`git add --chmod=+x scripts/verify-bundled-plugin-sync.sh` で `100755` にし、CI の `./scripts/...` で動くことを確かめる（§2 の差分の確かめ）
