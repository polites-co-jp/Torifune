# 053 SNS アカウントと API トークンを Web サイトに紐づける 検証レポート

SNS アカウントを Web サイトごとに紐づけて管理し、外部アプリが API で投稿するときは、そのサイトのアプリ（API トークン）から送られてきたときに限る作業単位。
**ユーザー裁定（2026-10-08）**：アカウントはサイトに 0〜1 個紐づく（紐づけたものはそのサイトからだけ、紐づけないものは何にでも使える）。
「そのアプリから」はトークンをサイトに紐づけて決める。読み取りも限定する。サイトに紐づけない既存のトークン・アカウントは従来どおり。
設計の要裁定 ①〜⑥ の裁定（5〜10）と、検証で出た裁定 11 は設計の冒頭の表にある。

実装完了時点（`17802c4`）に対し、3 つの検証エージェントを**互いの結果を見せずに独立して**走らせた。

| 担当 | 判定 |
| --- | --- |
| `spec-verifier`（設計との整合） | **条件付き合格**（重大 0・軽微 6。受け入れ条件 #1〜#93 と裁定 1〜10 のとおり。変異 84 件のうち 77 件を検出し、残る 7 件は同じ結果になるもの 4 件と未検証 3 件） |
| `boundary-guardian`（境界・公開 API） | **合格**（違反・破壊的変更 0。低 3） |
| `security-reviewer`（セキュリティ） | **合格**（重大 0・中 1・低 4） |

指摘はすべて直すか記録した（`81a4c1a`〜`86e398a`）。セキュリティの中 1 はユーザーの裁定（裁定 11）を受けて直し、直した差分を `security-reviewer` に改めて見せて**合格**を得た（§3）。

## 1. 入れたもの

* **区画**：要求ごとに `all`（画面・配信ジョブ・Plugin）／`common`（サイトに紐づけていないトークン）／`site:X`（サイト X のトークン）のどれかに分け、
  SNS のアカウントと投稿の見え方と操作をこの 1 つの規則で決める。範囲の外は存在しない ID と同じ 404（他のサイトのものがあるかどうかも漏れない）
* サイトに紐づけないアカウントはどの区画からも使える（サイトのトークンは読み・投稿はできるが、更新・削除は 403）。紐づけたアカウントとその投稿は、そのサイトのトークンと画面からだけ見える（裁定 5）
* サイトのトークンに付けられる権限は SNS の 4 つだけ（裁定 6。発行・使用時・DB の CHECK の 3 か所で守る）。アーカイブしたサイトのトークンは 401（裁定 8）
* トークンのサイトは後から変えられる（`PATCH /api-tokens/{id}`、画面だけ。裁定 7）。そのトークンが共通のアカウントへ登録した投稿も一緒に移る（裁定 10）
* 紐づけたアカウントがあるサイトは削除できない（409）。サイトを消すと、そのサイトのトークンは同じトランザクションで失効する
* マイグレーション `026`（`social_accounts.site_id`・`api_tokens.site_id` / `site_scoped`・`social_posts.origin_site_id` / `origin_site_scoped`）。既存の行はすべて共通になり、振る舞いは変わらない
* 画面：`/social` のアカウント一覧に「サイト」の列・紐づけの変更・絞り込み（裁定 9）、設定 → API にサイトの選択・列・「サイトを変える」
* 人をサイトに結び付けることはしない（マルチテナントにはしない。設計 §2）。Plugin API・イベント・Webhook・`PLUGIN_API_VERSION` は変えていない

## 2. 指摘と対応

| 出所 | 指摘 | 対応 |
| --- | --- | --- |
| security 中-1 | 共通のトークンが、サイトのトークンの投稿が載った共通のアカウントを削除（投稿も消える）・資格情報の差し替え（予約投稿が別の SNS アカウントから出る）できる | **ユーザー裁定 11「そのときだけ断る」で直した**。見えない投稿が載った共通のアカウントへの、トークンからの削除と資格情報の変更を 403 にする（本文は他の 403 と同じで、件数も理由も出さない）。表示名・ハンドル・状態の変更と画面からの操作は今までどおり。アカウントの行を `FOR UPDATE` でロックして数えるので、同時の投稿の登録とも食い違わない。受け入れ条件 #94〜#99 |
| security 低-1 | Repository の区画の引数の既定が「全件」で、渡し忘れると全部見える | **必須にした**（#100） |
| security 低-2 | `scopeOf` がサイトの無いトークンを一律に共通と読む | **文脈に `siteScoped` を積み、サイトのトークンなのにサイトが無ければ 401 にした**（#101） |
| security 低-3 | `token.manage` を持ち `site.read` を持たない人が、トークンの発行・変更の 422 の文言からサイトの有無とアーカイブを判別できる | **受け入れて記録した**（設計 §17 R12。ID は UUIDv7 で、文言を 1 つにすると直し方が分からなくなる） |
| security 低-4 | 冪等な登録の競合の経路で、既存の投稿を区画で確かめずに返す | **区画を掛けて引き直し、見えなければ 422 `externalRef` にした**（#102） |
| spec 軽微 1〜3 | サイトのトークンの権限を SNS の 4 つに絞る配線・アーカイブしたトークンで `last_used_at` が進まないこと・監査の例外が数のときだけ残すこと、が未検証 | **テストを足した**。サイトの削除で外部キーに当たった後の数え直しは、確実に割り込ませる手段が無く未検証のまま（実装プラン §8 の 33） |
| spec 軽微 4・5 | 実装プランと設計書の記録の遅れ（既存の E2E の追従、`AccountRowWithSite`、既存テストの影響の表） | **書き戻した** |
| spec 軽微 6 | `SiteGoneError` の JSDoc の位置 | **直した** |
| boundary 低 1 | 公開の UI 部品 `Modal` が画面より高いときに縦に動くようになった（ダイアログの欄が増えて高さ 720px に収まらなくなったため）ことが設計に無い | **設計 §11.1 に書いた**（Props・入口は不変） |
| boundary 低 2 | Plugin の Data API のサイトの削除に、新しい断り方と副作用（トークンの失効）が加わったことが Plugin 向けの文書に無い | **設計 §11.1・`plugin-api` の JSDoc・Plugin 開発ガイドに書いた**（サイトを使ったときにだけ起きる） |
| boundary 低 3 | `051` との重なりの見込みの誤り（API 仕様書 §4.2 と関連文書の行も衝突する） | **設計 §16 を直した**（どれも両方を残せば済む） |
