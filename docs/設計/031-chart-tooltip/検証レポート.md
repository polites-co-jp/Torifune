## 3. 指摘事項

### 3.1 「条件付き」の理由（3 点）

### 3.2 テストの穴・将来の壊れ方

1. **D5 が `ChartHoverLayer` 自身の空ガードを通っていない。** D5 の 3 入力はいずれも
   `chart.tsx` の早期 return で `<figure>` ごと出ないため、`points.length === 0 → null` は未検査。

### 6.2 §7.5 の導出をやり直した（左右と上下で非対称になる）

当初「上下も同じ論法で `calc(50% - var(--tf-space-2))`」としていたが、**これは誤りだった。**

`chart-hover.tsx` の配置は、左右が `left`/`right` ＋ `marginLeft`/`marginRight`（`--tf-space-2`）、
**上下は `top`/`bottom` だけでマージンが無い**。したがって導出は上下では差し引く量が 0 になる。

| 置き方 | 外側の端 |
| --- | --- |
| 左半分：`left: x%` ＋ 8px、幅 ≤ `50%W − 8` | 右端 = `xW + 0.5W` ≤ `W` |
| 右半分：`right: (100−x)%` ＋ 8px、幅 ≤ `50%W − 8` | 左端 = `xW − 0.5W` ≥ `0` |
| 上半分：`top: y%`、マージン 0、高さ ≤ `50%H` | 下端 = `yH + 0.5H` ≤ `H` |
| 下半分：`bottom: (100−y)%`、マージン 0、高さ ≤ `50%H` | 上端 = `yH − 0.5H` ≥ `0` |

**上下に `calc(50% - 8px)` を当てると実際に壊れる。** ポップアップの自然な高さは実測 79.19px、
`--tf-size-chart-md` は 160px なので上限は 72px となり **7px はみ出す**（`overflow` は `visible`。
`hidden` にすれば数値が隠れて機能の目的を壊す）。実装は `maxWidth: calc(50% - var(--tf-space-2))` /
`maxHeight: 50%` で、導出とも実データとも一致する。

**「上下にも離し幅を設ける」も採らない。** 離しの目的は「ポップアップが指している点を隠さない」ことだが、
マーカーは 8px を `translate(-50%,-50%)` で置くので**半径 4px**、ポップアップの左端は点から 8px 右。
**横方向の離しだけで重なりは既にゼロ**（4px < 8px）で、縦の離しは何も足さない。

### 6.3 §7.5 の保証の範囲（軸で強さが違う）

* **左右は厳密。** 上限に達した内容は折り返す（`nowrap` にしない）ので、**箱も文字も**枠内に収まる
* **上下は「箱」まで。** 折り返しに当たる機構が高さには無く、`overflow` を書いていないので、
  内容が上限を超えると**箱は枠内のまま文字だけが枠外へ出る**

余裕は薄い。`--tf-size-chart-md`（160px）で上限 80px に対し内容 79.19px ＝ **余裕 0.81px**。
`--tf-size-chart-sm`（120px → 60px）、それより小さい数値の `height`、系列名が 2 行に折り返す場合は超える。
**`height` は `ChartProps` として Plugin へ公開されている**ので、呼び出し元を本体の 2 箇所に限って
考えてはならない。今回は直さず、手当ての 3 方向とともに設計 §15.1 #14 に記録した。
