# 031 折れ線グラフのプロット点のポップアップ — 要件と裁定

設計書（`設計.md`）を書くための入力。ユーザーの要望と裁定をまとめる。
**この裁定は決定事項であり、設計書はこれに従う。**

## 1. 要望（2026-09-05）

> 線グラフ上のプロット点の近くにマウスカーソルが来たとき、
> その点が持っている値（X 軸・Y 軸両方の値）をポップアップして表示したい。

いまは折れ線を見ても、ある日の実際の値が読めない。Y 軸の目盛りは上限・中間・0 の 3 つしか無く、
X 軸の目盛りも間引かれているため、線の高さから値を目分量で読むしかない。

## 2. 着手前に確認した現状（2026-09-05 時点）

* 対象は `apps/web/src/ui/components/chart.tsx`（289 行）。座標計算は
  `chart-geometry.ts` の `chartLayout` / `chartPolyline`（純関数・テスト済み）が持つ
* **いまは点を描いていない。** `<polyline>` だけなので、**ホバーの当たり判定になる要素が存在しない**。
  当たり判定用の要素を足すことが実装の中心になる
* `preserveAspectRatio="none"` で `viewBox`（600×160）が非等比に伸びる。
  マウス位置からデータ点を引くには、実寸ではなく**割合**で解く必要がある
* `chart.tsx` に `'use client'` は無い。利用側の `overview-tab.tsx` は `'use client'`
* `Chart` には 2 つの経路がある
  * `series`（複数系列）— アナリティクス概要とダッシュボードが使う。どちらも 2 系列
    （ページビュー・訪問者）
  * `points`（1 系列・従来契約）— **リポジトリ内に利用箇所は無い**。
    `chartPolyline` は「Plugin から使われる公開契約」と `chart-geometry.ts` に明記されている
* アクセシビリティの先例がある。`role="img"` ＋ `aria-label` に加え、`<figcaption>` へ
  **同じ値を表として出している**（「SVG は読み上げも拡大も効かない。同じ値を表としても出す。
  『見えている人にだけ伝わる』画面にしない」06_画面設計.md §2）

## 3. 裁定（2026-09-05）

### 3.1 実現方式 — `'use client'` にして自前のポップアップを出す

SVG の `<title>` によるブラウザ既定のツールチップは採らない。

* 理由：`<title>` は表示まで約 1 秒待たされ、スタイルを当てられず、タッチでは出ない
* `chart.tsx` を `'use client'` にする。利用側（`overview-tab.tsx` / `core-widgets.tsx`）は
  既に client なので、実害は小さい

### 3.2 出す内容 — **カーソルに最も近い 1 点だけ**

同じ X の全系列をまとめて出す案は採らない。**指した 1 点の値を出す。**

* 出すもの：**その点の X 軸の値（日付などのラベル）と Y 軸の値**、および**どの系列の点か**
  （2 系列あるので、系列名が無いと「128」がページビューか訪問者か分からない）
* 「最も近い」の決め方（2 次元の距離か、X で絞ってから Y か、当たり判定の半径をいくつにするか）は
  設計で決める

### 3.3 点のマーカー — 常時は描かず、ホバー中の 1 点だけ強調する

* いまの見た目を変えない
* 90 日の期間では点が 90 個並ぶ。常時描くと線の形が読みにくくなる

## 4. 制約

* **`chartPolyline` の出力を変えない。** Plugin から使われる公開契約である
  （`chart-geometry.ts` に明記）。`chartLayout` の既存の出力も、既存の描画が変わらない範囲に留める
* **`<figcaption>` の表を消さない・弱めない。** ポップアップは
  「見えている人にだけ伝わる」情報になりうる。06_画面設計.md §2 の原則を満たし続けること
* 新しい依存を増やさない（UI ライブラリもチャートライブラリも導入しない。`CLAUDE.md` 技術スタック）
* マイグレーション・新しい Permission・新しい環境変数を増やさない
* 公開リポジトリである。特定の導入環境を指す記述を書かない

## 5. 設計で決めること（裁定していない）

1. **`points`（1 系列・従来契約）の経路にもポップアップを出すか。**
   リポジトリ内に利用箇所は無いが、Plugin が使っている可能性がある
2. **`bar-chart.tsx`（時間帯別など）を対象に含めるか。** 要望は「線グラフ」なので既定は対象外だが、
   同じ画面に並ぶ以上、片方だけ出る状態をどう扱うかは決める必要がある
3. **タッチ端末とキーボードでの到達性。** `024-responsive` の方針に揃えること。
   マウスが無い環境で値を読む手段は `<figcaption>` の表で足りるのか、別に要るのか
4. **「最も近い点」の判定規則**（3.2 のとおり）
5. **ポップアップが枠の外へはみ出すときの寄せ方**（X 軸ラベルが端で内側へ寄る既存の扱いに揃えるか）

## 6. 設計後の追加裁定（2026-09-05）

`設計.md` を受けて確認した事項。**これも決定事項であり、実装プラン以降はこれに従う。**

1. **裁定 §3.1 を変更する。`chart.tsx` は Server Component のまま据え置き、
   `'use client'` は新しい子モジュール `chart-hover.tsx` に閉じ込める。**
   `ui/plugin/plugin-boundary.tsx` が「Plugin 作者に『Client Component で書くこと』を要求しない」と
   定めており、`chart.tsx` を client にすると Plugin の Server Component から `<Chart>` を使うときの
   制約が増える。渡すのは文字列と数値だけなので、裁定 §3.1 の狙い
   （`<title>` を採らず自前のポップアップを出す）はそのまま満たせる。
2. **キーボード操作は新設しない**（`設計.md` §12）。値を読む手段としては `<figcaption>` の表が
   既にあり、今回もそれを弱めないことを受け入れ条件にしている。90〜180 個の tabstop は
   改善ではなく妨害になる。
3. `設計.md` §12 のその他の決定（`points` 経路も対象に含める / `bar-chart` は対象外 /
   タッチは出して指を離しても消さない / 最も近い点は「X で列を決めてから列内で Y が最も近い系列」・
   半径は設けない / はみ出しは左右・上下の振り分けと `max-width: 50%` で規則から保証）を
   そのまま採る。
