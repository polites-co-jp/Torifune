## 4. 判断が要るところ

### 4.1 テスト用の ZIP を自前で書く

**拒否したい形を作れる書き出しライブラリが無い。**
シンボリックリンク、`..` を含むパス、絶対パスを含む zip を作れなければ、
拒否できていることを確かめられない。

`test-support/zip.ts` に無圧縮の ZIP 書き出しを置く。
外部属性（Unix のファイルモード）を指定できるようにする。

### 4.2 名前の検証を yauzl に任せない

yauzl は既定で不正なパスを弾くが、**任せると拒否の理由が2箇所に分かれ、
こちらの検証が試されないまま残る。**

`decodeStrings: false` で yauzl の検証を外し、`isUnsafePath` で一括して見る。
展開時にも `startsWith` で二重に確かめる。検証を1箇所に頼ると、
そこを直したときに気づけない。

### 4.3 検証と導入を分ける

要求 Permission を導入前に見せる（`06_画面設計.md` §39）ためには、
「展開して Manifest を読む」段階と「導入を確定する」段階を分ける必要がある。

`inspect` は**ファイルシステムに何も書かない**。
`install` は zip をもう一度検証し、**同意した Plugin ID と一致することを確かめる**。
確かめないと、同意の直後に別の Plugin へ差し替えられる。

### 4.4 レジストリの生成をアプリでやらない

アプリは `plugins/` へファイルを置き、sentinel を書いて落ちるだけ。
レジストリの再生成とビルドは `docker/entrypoint.sh` が行う。

生成の実体が2箇所にあると必ずずれる。
`entrypoint.sh` の既定ビルドコマンドを `pnpm build`（`generate:plugins` を含む）に変えた。

### 4.5 ビルドを壊した Plugin を隔離する

隔離しないと、**次の再ビルドも同じ Plugin で失敗し続ける。**
`plugins/<id>/.torifune-quarantine` を置き、生成スクリプトがそれを飛ばす。

ファイルは消さない。消すと原因を調べられなくなる。

### 4.6 応答を返してから落とす

`scheduleRestart()` はタイマーで少し待ってから `process.exit(75)` する。
先に落とすと、要求した側は何が起きたか分からない。

### 4.7 開発環境では落ちない

`next dev` には監視ループが無い。落としても誰も起こしてくれない。
`TORIFUNE_SELF_RESTART=1` のときだけ落ちる。
そうでなければ画面に「`pnpm dev` を再起動してください」と出す。

## 5. やらないこと

* Plugin Registry（マーケット）／Git からの取得と、署名検証
* Plugin の更新（バージョン上げ）
* 実際の Plugin を伴う導入の E2E（→ `013-example-plugin`）
