### 確定事項（設計書から。プランで蒸し返さない）

* **ユーザー裁定（2026-09-24）「①〜④を直す」。対象は SNS のエンドポイントだけ**（設計 冒頭）。`/sites`・`/users`・`/campaigns` の一覧、Plugin の Data API、Repository の `accountId` の守り、SNS 以外の 404・409 の宣言、Bluesky の `auto` の片割れは**触らない**（設計 §3「やらないこと」、§11）
* ② は **422 にせず丸める**。`paginationSchema` の規則（`page` は 1 以上、`perPage` は 1〜100、整数でなければ 422）。`meta.page` / `meta.perPage` は丸めた後の値（設計 §6.2）
* ② の OpenAPI：`page` / `perPage` の parameter は `type: 'integer'`、`description` に「丸める」、**`minimum` / `maximum` を書かない**（設計 §6.2 末尾、#25）
* ③ は **UUID の形（8-4-4-4-12 の 16 進、大小文字を問わない、版と variant を見ない）でなければ 422 `accountId`**、空文字も 422、文言は `UUID の形で指定してください。`。`z.uuid()` は使わない（`z.guid()` はよい）（設計 §6.3）
* ① は **手動投稿のときだけ** #7（片割れのサロゲート → `本文に扱えない文字が含まれています。`）と #8（intent URL が 2048 文字を超える → `投稿画面の URL が長くなりすぎます。本文を短くしてください。`）を足す。#8 は grapheme 数・バイト数の問題と**重ねて返す**、#7 に当たったときは #8 を数えない。URL は `validate()` と `manual()` が**同じ関数 `buildBlueskyIntentUrl`** で組み立てる。片割れは U+FFFD に置き換えてからエンコードする。2048 は `plugins/sns-bluesky/text.ts` の `MANUAL_URL_MAX_LENGTH`（Core の定数を import しない）（設計 §4 / §9.2）
* ④ は `RouteDefinition` / `EndpointSpec` に任意の `additionalResponses`（`status: 200 | 404 | 409`、`description`）。200 の `content` は成功の応答スキーマ、404 / 409 は `errorEnvelopeSchema`。`defineRoute` は (a) `successStatus` と同じ `status`、(b) 同じ `status` の重複、(c) `response` の無い 200 で `RouteDefinitionError`。**欄を書かない操作の `responses` は変わらない**（設計 §6.4）
* 書く値は設計 §6.4 の表のとおり（8 操作。`listSocialAccounts`・`listSocialPosts`・`createSocialAccount` は無し）。`posts/route.ts` の「`successStatus` は 1 つしか宣言できないので、OpenAPI は 201 のまま。」のコメントを直す。`RESPONSE_SCHEMA_PENDING` は変わらない
* **API Version は v1 のまま**（設計 §6.5）。**データモデル・画面・Permission・公開 Plugin API（`packages/plugin-api`）は変えない**（設計 §5 / §7 / §8 / §9.1）
* **既存テストで変えてよいのは `sns-bluesky.test.ts` の #21 の 1 件だけ**（設計 §10.7）。ほかに変えないと通らないテストが見つかったら、実装者は直さずに報告する
* 検証は **`spec-verifier` / `boundary-guardian` / `security-reviewer` の 3 つ**（API・OpenAPI と `RouteDefinition` を変えるため）
* **SaaS 固有機能（テナント・課金・コンテナ管理）に触るタスクは本プランに無い**

## 3. タスク分解

原則：**1 タスク = 1 コミット**。各タスクは「テストを書いて失敗を確認 → 実装 → 通す」の順。
**test-writer → implementer への受け渡しの単位は G（まとまり）。** test-writer は G の中の全タスクのテストを先に書いて失敗を確かめてコミットし（1 G = 1 コミット）、implementer が G の中のタスクを順に通す。
**implementer はテストを書き換えない。** テストが設計と食い違うと判断したら、設計書のどこと食い違うかを報告して止まる。
各 G の最後で `pnpm test` / `pnpm typecheck` / `pnpm lint` / `pnpm format:check` が通る。

**着手順の骨子**：Plugin の純関数と検査（Core に依存しない）→ 一覧の `page` / `perPage` → `accountId` → OpenAPI の追加の応答 → 文書の書き戻し → 最終確認と 3 つの検証。
G1 と G4 は他の G に依存しないが、**G2 → G3 は同じスキーマとテストファイルを触るので、この順に直列で行う。** 推奨の順は G1 → G2 → G3 → G4 → G5 → G6。

## 7. リスクと注意点

1. **Zod の `.int()` が `minimum` / `maximum` を出す（T4 / #25）。** 設計 §6.2 は「書かない」と決めているが、いまの生成でも安全な整数の範囲が出ている。`openapi.ts` の生成の規則で一律に消すと SNS 以外の parameter の文書まで変わる（裁定の範囲外）。`social.ts` の中で消す。#25 は `Object.keys` で見るので、値が `undefined` のキーを残す実装は通らない
2. **`paginationSchema` の形のままでは OpenAPI の `default` が消える（T4）。** §8 の 1 の読み。`paginationSchema` を変えずに規則を写すと、将来 `paginationSchema` だけが変わったときにずれる。#16 で `paginationSchema.parse` との一致を見て固定する
3. **`accountId` の `.max(64)` の消し忘れ（T5 / #27）。** 65 文字で Zod の英文が `details.accountId` に並ぶ
4. **`accountId` の検査を Infrastructure から引かない（T5）。** `UUID_PATTERN` は `infrastructure/social-repository.ts` の非公開の定数。API 層から import するとレイヤの向きが増える。`z.guid()` か同じ正規表現を API 層に書く。OpenAPI の `pattern` は正規表現のフラグ（`/i`）を運ばないので、自前の正規表現なら `[0-9a-fA-F]` と書く
5. **URL の数えと実際の URL のずれ（T1 / T2 / #10）。** `validate` と `manual` が別々に組み立てると境界で食い違う。`buildBlueskyIntentUrl` の 1 か所だけで組み立てる（設計 §13 の 3）
6. **片割れの置き換えで長さが変わる（T2 / #5）。** #7 に当たったら #8 を数えない。置き換えた後の URL で数えると、片割れの本文で URL の問題が誤って重なる
7. **`manual()` は 042 より前の投稿でも呼ばれる（T1 / #8）。** `validate()` を通っていない本文（片割れ・長すぎる本文）でも投げない。長すぎる URL を返すのは従来どおり（Core の `isValidManualUrl` が断る）
8. **C 群の件数の検査の干渉（G2 / G3）。** 同じファイルの前のテストが作った投稿・アカウントが `meta.total` に混ざる。`afterEach` で消す
9. **G2 と G3 は同じファイルを触る。** 並行して進めない（§3 の順）。test-writer は G3 で G2 のテストを書き換えない（件を足すだけ）
10. **`additionalResponses` の書き忘れを検査で守らない（設計 §13 の 4）。** 将来 SNS に `{id}` の操作を足しても #34 は既存の 6 操作だけを見る。本件では足さない
11. **`#38` の登録簿の汚れ。** 投げない側の `defineRoute` は登録簿に残る。`social-openapi.test.ts` と別ファイルにし、`resetEndpointRegistry()` で戻す
12. **Bluesky の C 群で本物の `fetch` を呼ばない（T3）。** `sns-bluesky.integration.test.ts` と同じく `beforeEach` で「呼ばれたら投げる」`fetch` を置く（`auto` の登録は配信しないので呼ばれないはずだが、呼ばれたら落ちる形にしておく）
13. **Plugin の README は公開文書（T10）。** 作業単位の番号・内部の事情を書かない
14. **公開リポジトリである（全コミット）。** コミットメッセージ・コメントに運営側の事情を書かない
