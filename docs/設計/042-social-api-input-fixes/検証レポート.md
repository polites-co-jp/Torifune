## 1. 直したもの

| # | 変更前 | 変更後 |
| --- | --- | --- |
| ① | Bluesky の手動投稿は、日本語で約 224 文字以上でも登録が通り、予約時刻に「投稿画面を開く」が失敗した | 手動投稿のとき、投稿画面の URL が 2048 文字を超える本文と対になっていないサロゲートを **422 `body`**（X / Threads と同じ）。`manual()` は片割れを U+FFFD に置き換えて例外を投げない |
| ② | SNS の一覧の `perPage=-1`・`page=0` が **500**、`perPage=1000` がそのまま通る | 共通の規則（`paginationSchema`）どおり丸める。`page` は 1 以上、`perPage` は 1〜100。丸めた値が `meta` に返る |
| ③ | `GET /social/posts?accountId=` が UUID の形でないと絞り込みが黙って外れ、**全アカウントの投稿**が返った | **422 `accountId`**（空文字も）。存在しない UUID は従来どおり 200 で空 |
| ④ | OpenAPI に再送の 200・404・409 が宣言されていない | ルートの定義に `additionalResponses` を足し、SNS の 8 操作に宣言した |

**外部アプリから見た動作の変更は 2 つ**（仕様書 §9 の変更履歴に名指しした）：`perPage` を 101 以上で送ると 100 件まで、`accountId` の形の誤りは 422。
API のバージョンは v1 のまま（どちらも仕様書が初版から禁じていた送り方で、従来の応答が誤りだった。API もまだ公開していない。設計 §6.5）。

## 2. 検証で確かめたこと

* `spec-verifier` は全件のテストを流し、**15 種類 20 件の変異**を入れて判別力を確かめた（生き残りは 1 件。§3 の 1 で処置）
* さらに**本物のルートを叩いて**、`page` / `perPage` の 25 通りの値で状態コードと `meta` が `paginationSchema` と全件一致すること、`accountId` の 12 通り、
  SNS の 11 操作の OpenAPI の `responses` が設計の表と一致することを確かめた
* `security-reviewer` は、丸めた後の値で `LIMIT` / `OFFSET` に負の値が届かないこと、OFFSET の最大値が Postgres の bigint に収まること、
  `accountId` の検査が認証と権限の検査の後にあること、422 の文言が入力を反射しないこと、Bluesky の投稿画面の URL に別の引数を差し込めないことを確かめた
* `boundary-guardian` は、公開 Plugin API・Domain・Application・Infrastructure・マイグレーションに差分が無いこと、`additionalResponses` が Core の API 層に閉じていること、
  OpenAPI の変更が生成クライアントに与える影響を確かめた
* `boundary-guardian` と `security-reviewer` は**テストを 1 本も実行していない**（DB の競合を避けるため）

## 3. 指摘と処置

| # | 指摘 | 処置 |
| --- | --- | --- |
| spec 軽微-1 | `accountId` の検査を `z.guid()` から `z.uuid()` に替えても全件緑だった（テストの nil UUID と v7 の値は `z.uuid()` でも通る） | 版 0・variant 0 の値を 1 件足した（`82a8b7a`） |
| spec 文書-1 | 変更履歴の「従来は 0 以下が 500」が不正確（`perPage=0` は空の 200） | 直した（`22bf3c7`） |
| spec 文書-2 | 設計 §6.2 の 422 の文言が実際と違う（`abc` は Zod の既定の英文） | 直した。042 の前後で振る舞いは同じ |
| boundary 軽微-1 | OpenAPI の `accountId` に `format: uuid` が付き、生成クライアント（Java の `UUID`、C# の `Guid` など）で引数の型が変わりうることが仕様書に無い | 仕様書 §3.7 と変更履歴に書いた |
| boundary 軽微-2 | v1 のまま出す判断の、いちばん強い根拠（API がまだ公開されていない）が記録に無い | 設計 §6.5 に足した |
| boundary 判断-2 | 手動投稿の URL の上限 2048 が公開 Plugin API（`ManualHandoff.url` の説明）に書かれていない。042 より前からの問題 | `043` で扱う（文書だけの変更） |
| security 情報-1・2 | SNS 以外の一覧・Plugin の Data API に同じ種類の穴が残る | 裁定どおり `043` |
| security 情報-3 | `page=Infinity` などの 422 の文言が Zod の既定の英文 | 記録のみ（変更前からの振る舞いで、入力を反射しない） |
