# 033 アクセスログの除外IP設定 — 要件と裁定

設計書（`設計.md`）を書くための入力。ユーザーの要望と裁定をまとめる。
**この裁定は決定事項であり、設計書はこれに従う。**

## 1. 要望（2026-09-06）

> 設定画面に、ログに入れないIPを設定できるようにし、
> それをアクセスログから除外する仕組みを実装する。

## 2. 着手前に確認した現状（2026-09-06 時点）

### 2.1 `visitor_hash` は IP ではない（要望の前提の確認）

`access_logs` に **IP の生値は 1 バイトも入っていない**（`migrations/014_analytics.sql` §access_logs）。
入っているのは `sha256(日次ソルト + siteId + IP + UA)` の先頭 32 桁で
（`domain/analytics/access-log.ts` の `visitorHash`）、しかも日次ソルトは
**プロセス内の `Map` にしか持たず保存しない**（`application/analytics/collect.ts` の `dailySalt`）。

したがって次が成り立つ。

* ハッシュから IP を逆算できない
* 過去のログに対して「この IP のハッシュ」を再計算して突き合わせることもできない
  （その日のプロセスが生きている間を除く）
* **「後から特定 IP のログを探して消す」は原理的にできない。**
  除外は**記録する前に落とす**しかない

### 2.2 IP が取れている場所

`api/cookies.ts` の `requestInfoOf` が `x-forwarded-for` の先頭要素、無ければ `x-real-ip` を読む。
`app/api/v1/collect/route.ts` がそれを `collectAccess` へ渡し、`collect.ts` が
`visitorHash` の材料にしている。**受け口には生の IP が届いている。**

### 2.3 設定の置き場と前例

* `system_settings`（`key` / `value jsonb`）。型付けは `domain/system-settings.ts`
* **032-timezone-setting が「画面から設定し、`collect` のホットパスで参照する」前例**を作ってある
  * `application/analytics/timezone.ts` … `processState` 上の TTL キャッシュ。DB を毎回読まない
  * `domain/system-settings.ts` の `PublicSystemSettings` … **未認証で読んでよい項目の射影**。
    ここに載せないことが「公開しない」という判断そのもの
* 画面は `ui/settings/*` を `app/settings/page.tsx`（「一般」タブ）が並べる

## 3. 裁定（2026-09-06、AskUserQuestion）

### 3.1 適用範囲 — **システム全体で 1 つ**

サイトごとではなく、インスタンスに 1 つのリストを持つ。設定画面の「一般」タブに置く。

* 「社内・自宅からのアクセスを数えない」という典型的な用途はこれで足りる
* 基準タイムゾーン（032）と同じ `system_settings` に載るので、画面も実装も最小で済む
* サイトごとの指定が要るとわかった時点で、**この設定を残したまま**サイト個別の
  リストを足せる（全体を先に作っても行き止まりにならない）

### 3.2 指定形式 — **完全一致＋CIDR**

`203.0.113.10` のような単体アドレスに加え、`203.0.113.0/24` `2001:db8::/32` を書ける。
IPv4 / IPv6 の両方。判定は **Domain 層に自前で実装**する（外部依存を増やさない）。

* オフィスの固定 IP 帯・VPN の出口帯をまとめて除外できる
* 完全一致だけだと、複数の出口 IP を持つ回線で設定を足し続けることになる

### 3.3 設定画面に「現在あなたのアクセス元 IP」を出す — **出す**

入力欄の近くに、いまその画面を見ている人のアクセス元 IP を表示し、
1 クリックでリストへ足せるようにする。

* これが無いと「自分の IP を除外したい」人が外部サイトで自分の IP を調べる必要がある
* 出す先は `system.manage` を持つ管理者が見る設定画面に限る

### 3.4 ブランチ — `feature/032-timezone-setting` から派生

`feature/033-analytics-ip-exclusion` を 032 から切る。032 は `main` へ未マージで、
今回触る `collect.ts` / `domain/system-settings.ts` は 032 の変更と同じ箇所に重なる。

## 4. この機能で満たすこと

1. `system.manage` を持つ管理者が、設定画面から除外 IP のリストを編集・保存できる
2. 保存されたリストに一致する送信元からの `POST /api/v1/collect` は、
   **`access_logs` に 1 行も残さない**
3. 除外されたことを送信側へ伝えない（従来どおり 204 を返す）
4. リストは**未認証で読めない**。`GET /api/v1/settings`（`permission: null`）に載せない

## 5. この機能で満たさないこと（明示）

* **過去のログの遡及削除**（§2.1 のとおり原理的にできない）。
  設定を入れる前に記録された分は残る。画面でその旨を断る
* **保存済み集計値の再計算。** 除外は今後の記録にだけ効く。
  032 の洗い替えのような重い処理は起こさない
* **監査ログ・認証のレート制限など、アクセス解析以外での IP の扱い。**
  この設定はアクセス解析の記録だけに効く
* **IP の偽装への防御。** `x-forwarded-for` は信頼できるリバースプロキシの背後にいることが
  前提の値であり、直接叩かれれば詐称できる。この設定は
  「自分たちのアクセスを数えない」ためのものであって、防御の仕組みではない
