# 026 実装プラン

入力は `設計.md` のみ。順番は「DB → Domain → Infrastructure → Application → API → UI → Plugin API → 仕様書」。

## S1. マイグレーションとスキーマ型

1. `migrations/NNN_campaign_social_posts.sql`（NNN は追加時点で空いている次の連番）
   * `campaign_social_posts` テーブルと逆引き索引
   * `social_posts.failed_at` 追加、配信結果の並び用の部分索引
2. `apps/web/src/database/schema.ts`
   * `CampaignSocialPostsTable` を追加し `Schema` へ登録
   * `SocialPostsTable.failed_at` を追加

## S2. Domain

1. `domain/campaign/campaign.ts`
   * `Campaign.socialPostIds: readonly string[]`
   * `analysisRange(startsOn, endsOn, today)` — 分析期間の算出（400日で切り上げ）
2. `domain/campaign/campaign-repository.ts`
   * `NewCampaign.socialPostIds` / `CampaignUpdate.socialPostIds`
3. `domain/social/social.ts`
   * `SocialPost.failedAt: Date | null`
   * `DELIVERED_STATUSES = ['published', 'failed']`
4. `domain/social/social-repository.ts`
   * `SocialPostListQuery.status` → `statuses: readonly PostStatus[]`
   * `SocialPostListQuery.orderBy: 'created' | 'delivered'`
   * `SocialPostUpdate.failedAt`
   * `SocialRepository.findPostsByIds`

## S3. Infrastructure

1. `infrastructure/campaign-repository.ts`
   * `socialPostIdsOf` / `replaceSocialPosts`（`siteIdsOf` / `replaceSites` と対称）
   * `list` / `findById` / `insert` / `update` を追随
2. `infrastructure/social-repository.ts`
   * `failed_at` を列と `toPost` へ
   * `statuses` 絞り込みと `orderBy` の実装
   * `findPostsByIds`

## S4. Application

1. `application/campaign/campaign-use-cases.ts`
   * `CreateCampaignInput.socialPostIds` / `UpdateCampaignInput.socialPostIds`
   * `payloadOf` に `socialPostIds`
2. `application/social/social-use-cases.ts`
   * `ListPostsInput.status` → `statuses` へ畳む（入力の形は変えない）
   * `UpdatePostInput.failureReason`、`failed` へ移すとき `failedAt` を記録
   * `listSocialPostHistory`（`social.read`）
   * `listSocialPostsByIds`（`social.read`）
3. `plugin/data-api.ts`
   * `markFailed(id, reason)` が理由を渡す
   * `SocialPostView.failureReason` を返す
   * キャンペーンの `socialPostIds` を入出力に通す

## S5. API スキーマとルート

* `api/schemas/campaign.ts` … `socialPostIds`（作成・更新・応答）
* `api/schemas/social.ts` … `updatePostSchema.failureReason`、`postResponseSchema.failedAt`
* `app/api/v1/campaigns/route.ts` / `[id]/route.ts` … `socialPostIds` を素通し
* `app/api/v1/social/posts/[id]/route.ts` … `failureReason` を素通し
* `endpoints.ts` は変更しない（新しい経路を作らないため）
