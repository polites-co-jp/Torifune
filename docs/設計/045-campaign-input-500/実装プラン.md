### 確定事項（設計書から。プランで蒸し返さない）

* `activeOn` の暦の検査は **UseCase `listCampaigns`** に置く（`isValidDateOnly`）。Zod の正規表現は変えない。文言は `存在しない日付です。`（設計 §6.2）
* `siteIds` / `socialPostIds` の規則は **Domain の純関数 `normalizeCampaignLinkIds`**（配列 → **件数を先に**（1000 件まで）→ 要素が `isUuidShape` → 小文字・重複除去・昇順）。戻り値は `{ ok: true; ids } | { ok: false; reason: 'shape' | 'tooMany' }`（設計 §4・§6.3）
* 存在の確かめは **`CampaignRepository.lockExistingLinks`**（`FOR KEY SHARE`）を、書き込みと**同じトランザクション**で呼ぶ。外部キー違反を 422 へ写す仕組みは作らない（設計 §6.4）
* 文言：形 `UUID の形で指定してください。`、件数 `1000件以内で指定してください。`、存在 `存在しないWebサイトが含まれています。` / `存在しないSNS投稿が含まれています。`。値を `details`・`message` に載せない（設計 §6.3）
* 順序：認証 → Permission → Zod → `assertValid` / `assertPeriod`（既存）→ 形と件数 → （トランザクション）`PATCH` はキャンペーンの存在（404）→ 紐づけ先の存在 → 書き込み。同じ段の誤りは `details` にまとめる（設計 §6.3）
* Zod は `siteIds` / `socialPostIds` に `.max(1000, '1000件以内で指定してください。')` と `.describe()` だけ。要素は `z.string()` のまま。`activeOn` に `.describe()`（設計 §4）
* Data API は **`data-api.ts` を変えない**（UseCase の `ValidationError` がそのまま reject になる）。公開 Plugin API は `CampaignInput` の TSDoc だけ（設計 §9）
* 画面は `campaign-form.tsx` の 2 つの `FormField` に `fieldErrors['siteIds']` / `fieldErrors['socialPostIds']` を渡すだけ（設計 §7）
* **`additionalResponses` を足さない**（`043` #39 の網羅の表は変わらない）
* **既存テストを変えない**（設計 §10.8）。変えないと通らないテストが見つかったら、実装者は直さずに報告する
* D を足すので **E2E を流す。コンテナで流す**（設計 §10.9）
* §1.3 の B1〜B4（NUL 文字など）は**触らない**（設計 §3・§11 の 1 の裁定待ち）

## 7. リスクと注意点

1. **T8 の `updateCampaign` の順序**：紐づけを指定したときの 404 はトランザクションの中の `findById(tx, id)` で判定する（既存の期間の検査のための `findById` はトランザクションの外のまま動かさない）。紐づけを指定しない `PATCH` の振る舞い（404 の出方を含む）を変えない
2. **正規化した ID を Repository へ渡す**：`insert` の戻り値の `siteIds` は渡した値から作られる。正規化前の値を渡すと #14 の「応答が小文字」が崩れる
3. **`ValidationError` の `details`**：`route.ts` は `details` があればそれだけを返す。`field` / `detail` には先頭のキーと文言を入れ、`details` に全部を入れる（#16）
4. **#24 の書き方**：トランザクションのコールバックの中で別の `pg.Client` を待つ。コールバックの外で待つとコミット済みになり、ロックを確かめられない。別の Client は必ず `end()` する（`finally`）
5. **#31・#32 の共有 DB**：他の spec が作った行が残る。作るサイト・投稿・キャンペーンの名前に一意の接尾辞を付け、チェックボックスはその名前（ラベル）で引く。#32 の投稿は作成画面の候補（新しい順に 100 件）に入るよう、直前に作る
6. **E2E のファイル名の順**：`workers: 1` でファイル名の順に走る。`campaign-link-errors.spec.ts` は `campaigns.spec.ts` より前に走るが、自分で作ったものだけを消すので影響しない
7. **§1.3 の B1〜B4 に手を広げない**：`name` の NUL などは本件で直さない（裁定待ち）。テストにも入れない
