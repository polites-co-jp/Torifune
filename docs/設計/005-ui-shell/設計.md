# UI 基盤 設計

## 1. 目的

機能を載せるための最低限の器を作る。

満たすべきことは4つ。

1. **後からデザインを差し替えられる形にする。**
   色・余白・角丸をトークンに集約し、コンポーネントは変数しか参照しない
2. **Loading / Empty / Error / 権限なし の4状態を最初から用意する。**
   後から差し込むのが最も高くつく
3. **Plugin が使う公開契約として成り立たせる**（`06_画面設計.md` §32）
4. **UI の表示制御を、認可そのものと取り違えない構造にする**（同 §29）

方針の詳細は `docs/実装計画/001-Torifune単体稼働/02_画面デザイン方針.md`。

## 3. スコープ

### やること

* デザイントークン（CSS 変数）と Tailwind の接続
* 共通レイアウト（Header / SideNav / Main / Footer）
* 共通コンポーネント 13 種
* Loading / Empty / Error / 権限なし の4状態
* 共通 API Client（エラーコード → 表示文言の変換を1箇所に）
* Permission による表示制御のヘルパ
* ナビゲーションの定義（Plugin からの追加は `011` で繋ぐ）
* `/setup` `/login` を共通コンポーネントへ載せ替える

### やらないこと

* ブランディング、アイコンセット、アニメーション
* レスポンシブの作り込み（PC 幅のみ）
* ダークモード
* `DatePicker` / `Chart`（必要になった時点で追加する）
* Plugin の UI 拡張点の実装（`011-plugin-runtime`）

```text

├── tokens.css              デザイントークン
├── components/
│   ├── button.tsx / input.tsx / textarea.tsx / select.tsx / checkbox.tsx
│   ├── form-field.tsx / card.tsx / table.tsx / pagination.tsx
│   ├── modal.tsx / confirm-dialog.tsx / alert.tsx / toast.tsx
│   ├── empty-state.tsx / spinner.tsx / secret-field.tsx

├── layout/
│   ├── app-shell.tsx       Header / SideNav / Main / Footer
│   └── navigation.ts       ナビゲーション定義
├── states/
│   └── async-state.tsx     Loading / Empty / Error / 権限なし

**UI から Database へ直接アクセスしない**（ESLint で検査済み）。

```

ナビゲーション項目には**必要な Permission を持たせる**。
持たないユーザーには表示しない。ただし**それは認可ではない**（同 §29）。

## 8. 権限（Permission）

このスプリントは新しい Permission を追加しない。

ナビゲーションと操作ボタンの表示制御に、既存の Permission を使う。

**表示制御のコードには「これは認可ではない」と明記する。**

## 9. Plugin API への影響

共通コンポーネントは `06_画面設計.md` §32 により **Plugin から利用される公開契約**になる。

`ui/components/index.ts` を唯一の入口とし、S10 で `packages/plugin-api` から
この型を参照できるようにする。

**個別ファイルへの直接 import を Plugin に許さない。** 内部の再編で壊れるため。

## 10. 受け入れ条件

### トークン

1. すべてのコンポーネントが色を CSS 変数経由で参照している（生の hex が無い）
2. すべてのコンポーネントが余白を CSS 変数経由で参照している（px 直書きが無い）
3. トークンの値を差し替えるだけで見た目が変わる

### レイアウト

4. ヘッダーに「とりふね」が表示される
5. ナビゲーションに主要項目が並ぶ
6. **Permission を持たない項目が表示されない**
7. ログイン中のユーザー名が表示される
8. ログアウトの導線がある

### コンポーネント

9. `Button` が primary / secondary / danger / ghost の4種を持つ
10. `Button` が disabled のときクリックできない
11. `FormField` がラベル・説明・エラー文言を表示する
12. `FormField` のエラーが `aria-invalid` と結び付く
13. `Table` が列定義から表を描く
14. `Pagination` が現在ページと総ページ数を表示する
15. `Pagination` が最初/最後のページで端のボタンを無効にする
16. `Modal` が Escape で閉じる
17. `ConfirmDialog` が確認するまで実行しない
18. `Toast` が一定時間で消える
19. `EmptyState` が次の操作への導線を持つ
20. `SecretField` が値をマスク表示する
21. **`SecretField` が平文を DOM に出さない**

### 4状態

22. `AsyncState` が Loading を描画できる
23. Empty を描画でき、次の操作への導線を出せる
24. Error を描画でき、**内部例外の詳細を出さない**
25. 権限なしを描画できる
26. 正常時は子要素を描画する

### API Client

27. 成功応答から `data` を取り出す
28. エラー応答からエラーコードと表示文言を取り出す
29. **内部例外の詳細を画面へ渡さない**
30. 401 のときログイン画面へ誘導できる
31. CSRF トークンを自動で付ける
32. ネットワーク障害を「通信に失敗しました」に変換する
33. **エラーコードに対応する日本語文言が全コードぶん定義されている**

### 表示制御

34. Permission を持つときだけ要素を描画するヘルパがある
35. **そのヘルパのコードに「認可ではない」旨が明記されている**
