# 015b-settings 設計

## 1. 目的

`001` から送られた設定画面の残り（`06_画面設計.md` §16）と、
S-7 が拾いきれなかった項目。`002-Torifune機能完成` T4。

ID は `015b`。**コードのコメントが `015b` を参照している**ため
（`app/settings/page.tsx`）、繰り上げない。

## 2. 対象

| 対象 | 仕様 | 現状 |
| --- | --- | --- |
| 設定画面の 一般 / 認証 / API タブ | `06` §16 | ユーザー・権限の2タブのみ |

## 3. 決めたこと

### 3.1 一般タブに何を置くか

**仕様は §16 にタブ名しか書いていない。** 中身を決める必要がある。

置くもの：**サービス表示名**（既定「とりふね」）。

理由は、

* 自己ホストで複数環境（本番・検証）を並べたとき、**どれを見ているか
  分からないのが実害**として最も大きい
* `system.manage` の消費先が必要（S-7）。表示名の変更は
  「システム全体に効く設定」であり、この権限にふさわしい

**置かないもの**：セッション有効期限やアイドルタイムアウトの変更。
値を画面から変えられるようにすると、**短くしすぎて自分を締め出す**、
長くしすぎて放置端末が生きる、といった事故が起きる。
運用で変える必要が出た時点で、要求と合わせて設計する。
いまは 認証タブに**現在値を表示するだけ**にする。

### 3.2 設定の置き場は key-value にする

`system_settings(key, value jsonb, updated_at)`。

1行1カラムの固定テーブルにすると、設定が増えるたびにマイグレーションが要る。
**設定は増える。** Plugin の設定（`plugin_store`）と同じ形にそろえる。

読み出しは型付きのアクセサ経由にして、呼び出し側が生の JSON を触らない。

### 3.3 Remember Me はセッション延長（`015-settings` §9 の決定に従う）

ログイン画面のチェックボックスで `expires_at` を長くする。
別テーブルの永続トークンは作らない。

**トレードオフは記録済み**（`015-settings` §9）：別トークン方式なら
使うたびにローテーションして盗難を検知できる。セッション延長にはそれが無い。

追加で決めること：

* 長期セッションの期間は **30日**
* **アイドルタイムアウトは短いまま**（12時間）にしない。
  それでは「長期ログイン」にならない。長期セッションでは
  アイドルタイムアウトを期間と同じにする
* Remember Me を使うかは 認証タブで切り替えられる（`system.manage`）。
  組織の方針で禁止したい場合があるため

### 3.4 「Permission変更」の監査は Plugin の権限登録で発火させる

`04` §26 が挙げる「Permission変更」に対応する操作は、
**ロールの編集**を入れていないため（`015-settings` §8：自分へ権限を足す
経路を作らない）本体に無い。

しかし **Plugin の有効化・無効化は Permission の集合を変える。**
Plugin が宣言した Permission が登録・取り下げされるのがそれにあたる。
ここで `permission.changed` を残す。

### 3.5 「外部認証連携設定変更」は Provider の差し替えで発火させる

`setAuthenticationProvider` が呼ばれたとき（Plugin の有効化・無効化）に
`auth.provider.changed` を残す。**認証方式が変わったことは、
何より先に記録されるべき**で、Plugin の有効化ログだけでは弱い。

### 3.6 API タブの内容

* API Token の一覧・発行・失効（`021-api-token` の UI）
* OpenAPI ドキュメント（`/api/v1/openapi.json`）への導線
* CORS の現在の設定（**読み取り専用**。環境変数で決まるため）

CORS を画面から変えられるようにしない。設定を誤ると外部から叩けるようになり、
その変更が環境変数と食い違うと、どちらが効いているのか分からなくなる。

### 3.7 Data API の Users は読み取りだけ

Plugin が「誰がやったか」を表示するために要る。
**作成・更新・削除は出さない。** Plugin がユーザーを作れると、
Plugin の導入がそのまま管理者の追加になりうる。

## 5. 受け入れ条件

1. 5タブすべてが Permission で出し分けされ、権限なしは 403
2. サービス表示名を変えると、画面のヘッダとタイトルに反映される
3. `system.manage` が無いユーザーは一般・認証タブを保存できない
4. Remember Me を有効にしたログインのセッションが、既定より長く生きる
5. 認証タブで Remember Me を無効にすると、チェックしてもログインが延びない
6. Plugin の有効化・無効化で `permission.changed` と
   `auth.provider.changed` が監査ログに残る
7. Plugin が Data API から Users を読める。宣言外は `PluginPermissionError`
8. Plugin から Users を作成・更新・削除する口が無い
