## 設計から変えたこと

### タブごとに要る権限を変えた

設計 §5 は「5タブすべてが Permission で出し分けされる」とだけ書いていたが、
実装時に**画面全体を `user.manage` で塞いでいた**ことに気づいた
（`015-settings` の実装。ユーザー・権限タブしか無かったので当時は正しい）。

一般・認証タブは `user.manage` と関係が無い。塞いだままだと、
システム管理者だがユーザー管理をしない人が一般設定を触れない。

タブごとに判定を分けた。

| タブ | 見るのに要る | 変えるのに要る |
| --- | --- | --- |
| 一般 | 認証のみ | `system.manage` |
| ユーザー / 権限 | `user.manage` | `user.manage` |
| 認証 | 認証のみ | `system.manage` |
| API | `token.manage` | `token.manage` |

### アイドルタイムアウトをセッションの期間から導く

設計 §3.3 は「長期セッションではアイドルタイムアウトを期間と同じにする」
とだけ書いていた。実現方法として**列を足さずに、セッション自身の期間から
判断する**形にした（`sessionIdleTimeoutMs`）。

期間そのものが答えを持っているので、二重に持って食い違わせる理由が無い。

### `--tf-border-emphasis` トークンを足した

共通 Tabs を作ったところ、既存のテスト
「コンポーネントに px の直書きが無い」に引っかかった（選択中のタブの下線が 2px）。

**テストが正しい。** トークンを足して直した。
1px では選択が読み取りにくいので、太さ自体は変えていない。

## 残ること（意図的）

* ロールの編集は入れない（`015-settings` §8 の判断を変えない）。
  自分へ権限を足す経路を作らない
* CORS は画面から変えられない。環境変数と食い違うと、どちらが効いているか
  分からなくなる
* Remember Me を無効にしても、発行済みの長期セッションは期限まで有効。
  画面にその旨を出している（切りたければパスワード変更で全失効）
