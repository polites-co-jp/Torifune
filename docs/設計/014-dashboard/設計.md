# 014-dashboard 設計

## 1. 目的

ダッシュボードの中身（`06_画面設計.md` §9-10）と、
不足している共通コンポーネント（同 §32）。`002-Torifune機能完成` T7。

`001` の「次の計画に送るもの」で最初に挙がっていながら、
`015-settings` と `016-home-routing` に飛び越されて器だけが残っていた。

**いま作れるのは、`018-analytics` でデータが揃ったから。**
先に作っていたら、数字の出ない枠を並べることになっていた。

## 2. 対象

| 対象 | 仕様 | 現状 |
| --- | --- | --- |
| Core Widget：KPI | `06` §9-10 | 「ようこそ」カードのみ |
| Core Widget：アクセス推移 | 同 | 無い |
| Core Widget：最近の投稿 | 同 | 無い |
| Core Widget：最近の活動 | 同 | 無い |
| Chart コンポーネント | `06` §32 | 無い |
| DatePicker コンポーネント | 同 | 生の `datetime-local` |

## 3. 決めたこと

### 3.1 Chart はライブラリを入れず、インラインSVGで描く

`CLAUDE.md` は「UIライブラリは導入しない」としている。チャートも同じ。

必要なのは**折れ線1本**（日次の推移）であり、そのために
数百KBの依存を足す理由が無い。**軸・凡例・目盛りを持つ汎用チャートは作らない。**
必要になったらそのとき作る。

* SVG の `polyline` と `viewBox` だけで描く
* データ点にアクセシブルな代替（表）を必ず添える。
  **SVG だけだと読み上げも拡大も効かない**

### 3.2 DatePicker は `<input type="date">` を包むだけ

ブラウザ標準の日付入力を置き換えない。置き換えると、
キーボード操作・IME・地域ごとの表記を全部自前で持つことになる。

共通化するのは「ラベル・エラー・トークンに沿った見た目」だけ。

### 3.3 Widget は Permission で出し分ける

`analytics.read` が無ければアクセス系の Widget を出さない。
**空の枠を出さない。** 権限が無い人に「読み込めない箱」を見せない。

### 3.4 「最近の活動」は監査ログから作る

`022-hardening` で `audit_logs` を入れたので、そこから引く。
**専用のテーブルを作らない。**

ただし監査ログは操作の記録であって、活動の要約ではない。
出すのは「誰が・何を・いつ」だけにする。

### 3.5 KPI の期間は「直近7日」に固定する

期間を選べるようにしない。ダッシュボードは**開いてすぐ分かる**ことが役目で、
細かく見るための画面は `/analytics` にある。

## 4. 構成

```text
apps/web/src/
├── ui/components/chart.tsx        Chart（新規）
├── ui/components/date-field.tsx   DatePicker（新規）
├── ui/dashboard/core-widgets.tsx  Core Widget（新規）
└── app/dashboard/page.tsx         Widget を並べる
```

## 5. 受け入れ条件

1. KPI（直近7日のページビュー・訪問者・投稿数）が出る
2. アクセス推移が折れ線で出て、同じ値が表としても読める
3. 最近の投稿と最近の活動が出る
4. `analytics.read` が無い人にアクセス系の Widget が出ない
5. データが無いときに空状態が出る（壊れて見えない）
6. Plugin Widget が Core Widget と同じ枠組みで並ぶ
7. Chart と DatePicker が共通コンポーネントの入口から使える
