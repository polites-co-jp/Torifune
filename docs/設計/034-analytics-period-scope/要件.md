## 2. 着手前に確認した現状（2026-09-09 時点）

`main`（033 マージ済み）を読んだ結果。**想像ではなく実物の確認結果**なので、設計はここを前提にしてよい。

### 2.1 期間はすでに画面全体へ効いている（要望の 2 点目の前提の確認）

`app/analytics/page.tsx` は `resolvePeriod` が決めた 1 つの期間（`period.from` / `period.to`）を
**すべての問い合わせに渡している**。

| 表示 | データ源 | 期間の渡り方 |
| --- | --- | --- |
| 上部 5 カード（PV / 訪問者 / セッション / 直帰率 / 平均滞在） | `currentPoints` | `keyless(period.from, period.to)` |
| 日次の推移 | 同じ `currentPoints` | 同上 |
| 上位ページ / 参照元（概要） | `breakdownOf('path_pageviews' / 'referrer')` | `breakdown(context, {...range})`（`range = {siteId, period.from, period.to}`） |
| 時間帯別 / デバイス | `breakdownOf('pageviews_hour' / 'pageviews_device')` | 同上 |
| ページタブ / 参照元タブ / 訪問者タブ | 同じ `breakdownOf` / `valuesByKeyOf` / `currentPoints` | 同上 |

Repository（`infrastructure/analytics-repository.ts`）も
`metric_date >= from` / `metric_date <= to` で必ず絞っている。
**したがって「日次の推移にしか効いていない」という状態はコード上には無い。**

### 2.2 では何が起きていたか — 期間を画面に出しているのが 1 か所だけ

期間（`YYYY-MM-DD 〜 YYYY-MM-DD`）を文字として出しているのは、
**概要タブの「日次の推移」カードの見出し右**（`OverviewTab` の `SectionHeader aside={rangeText(from, to)}`）だけ。

* 画面上部の見出し行（`analyticsHeaderText`）は「**前期間**（…）と比較 · 集計は前日まで · 日付の区切りは …」で、
  **当期そのものの日付は出していない**
* 上位ページ・参照元・時間帯別・デバイス・ページ／参照元／訪問者タブには期間の表示が無い
* 日付入力（`DateField` 2 つ）は `period` がプリセットのとき**当期の日付が入っている**が、
  期間セグメントの右にある小さな入力なので「どこに効いているか」を示す表示としては読まれない

「どの数字がどの期間のものか」を画面から確かめられるのが 1 枚のカードだけ、という状態である。

### 2.3 期間プリセットの現状

* `domain/analytics/day.ts` の `PeriodPreset` = `'7d' | '30d' | '90d' | 'month' | 'prev-month'`、
  `PERIOD_PRESETS` がその並び。`presetRange(preset, today)` が `DateRange | null` を返す
  （`null` は「確定値のある期間が無い」＝今月 1 日の `month` だけ）
* `ui/analytics/labels.ts` の `AnalyticsPeriod` = `PeriodPreset | 'today' | 'custom'`、
  `ANALYTICS_PERIODS` が**画面に並ぶ順**（`'7d','30d','90d','month','prev-month','custom'`）、
  `PERIOD_LABEL` が表示名
* 「当日」（`today`）は `PeriodPreset` に**入っていない**。確定値ではなく生ログから出す別経路なので、
  「`presetRange` で確定値のある期間が求まる」という `PeriodPreset` の契約に入れられない（030 §7.1.2）
* 画面では「当日」だけを持つ `SegmentedControl` を、期間の `SegmentedControl` の**左**に置いている
* すべてのプリセットは**末尾が昨日**（030 の裁定。進行中の日を確定値に混ぜない）

## 3. 裁定（2026-09-09、AskUserQuestion）

### 3.1 「昨日」を期間プリセットとして足す — 位置は「7日」の左

`昨日` = `[昨日, 昨日]` の 1 日。**確定値**（`analytics`）から出す。

* 既存プリセットはすべて末尾が昨日なので、`昨日` は「その末尾の 1 日だけを見る」もので矛盾しない
* 「当日」（生ログ・速報値）とは別物である。**当日の `SegmentedControl` には入れない。**
  期間の `SegmentedControl` の先頭（＝「7日」の左）に入れる

### 3.2 期間の適用範囲 — **データの取得範囲は変えない。表示で分かるようにする**

2.1 のとおりサーバー側ではすでに全体へ効いているので、**問い合わせは変えない**。
変えるのは「効いていることが画面から分かるか」である。

* 画面上部に、**いま適用されている期間**を明記する（1 か所で全体に効いていると読める位置）
* 上位ページ・参照元・時間帯別・デバイス、およびページ／参照元／訪問者タブにも期間を添える
* あわせて、**全カード・全タブが選択期間で絞られること**をテストで固定する
  （今後この認識の食い違いが再発しないように、テストを根拠にできる状態にする）

### 3.3 進め方

フル `/feature` 流れ（設計 → プラン → テスト → 実装 → 検証）。028〜033 と同じ品質水準。
ブランチは `feature/034-analytics-period-scope`（`main` から分岐済み）。

   `custom` で `from = to` にすると現状は 1 点の折れ線が出る（E2E の `todayUrl` がまさにその形）。

   **`SectionHeader` の `aside` は多くのカードで既に埋まっている**
   （上位ページ・参照元は「すべて →」、ページタブは「N ページ · ページビュー順」、
   参照元タブは説明文、Bot のアクセスは Bot スイッチの状態）。
   上書きせずに期間を添える形を決める
4. 「当日」のときに何を出すか（日付 1 つか、「当日（YYYY-MM-DD）」か）
5. `previousRange('昨日','昨日')` は一昨日になる。前期間比のラベル・注記が
   「昨日 vs 一昨日」で読めるか
6. `PeriodPreset` に `yesterday` を足すことによる影響範囲
   （`presetRange` の呼び出し元、`isPeriodPreset` を通る URL、API 側に期間プリセットの概念があるか）
