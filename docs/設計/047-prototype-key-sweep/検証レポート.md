## 1. 確かめたこと

* **`role-repository.ts` は実際に落ちる。ただし外からは届かない。** ロールは初期データの 3 つだけで、作ったり改名したりする経路が無い。`roles.name` の CHECK は原型の名前のうち `constructor` だけを通す。
  運用者が DB に直接 `constructor` のロールを作ると、`/settings?tab=permissions` が 500 になっていた
* **HTTP から届く同種の不具合が 1 つあった。** `POST /api/v1/social/accounts` に `provider: "constructor"` を送ると作れてしまい、`/social` ほか 4 画面でアカウント名が「とりふね（function Object() { [native code] }）」と表示され、一覧の「サービス」列が空欄になっていた
* 洗い出した 21 か所（K1〜K21）のうち、不具合が実際に出るのは 5 か所。`Object.prototype` そのものを汚す経路（深いマージなど）は無かった

## 2. 直したもの

外から影響を受けるキーで辞書を引くときは自分のプロパティだけを見る（新しい部品 `ownValue`、または `Map`）。辞書を作るときは `Map` か `Object.fromEntries` で作る。

| # | 場所 | 直し方 |
| --- | --- | --- |
| K1・K2 | ロールの権限の読み出しと権限マトリクス | `Map` で積む／`ownValue` で引く |
| K3・K4 | SNS の provider の表示名（部品 2 か所を含む） | `ownValue` |
| K5 | SNS 投稿の画面の `publisherProviders` | `ownValue`（今は偶然正しいが規則に揃える） |
| K6 | 権限の説明 | `ownValue` |
| K17 | OpenAPI の組み立て | `Map`（出力は同じ） |

静的検査で、テスト以外のソースに `]` の直後の `??=` / `||=` で空の配列・オブジェクトを置く書き方を禁じた。
名前の拒否リスト（`constructor` を断る）は採らず、読む側を直した（原型の名前は JavaScript の版で増えうるため。設計 §11 の 1）。

## 3. 検証で確かめたこと

* `spec-verifier` は全件のテストを流し、K1〜K6・K17 を 1 つずつ元に戻す変異、`ownValue` の書き換え、別のファイルへの禁止形の追加（改行を挟む形を含む）を入れ、**すべて検出**された（K5 だけは静的検査が守る。§4）。
  さらに**独自に 367 ファイルを洗い出し直し**、K1〜K21 から漏れていて外から届くものは無いことを確かめた
* `security-reviewer` は、権限の判定（Permission・ロール・API トークンの Scope・Plugin の Manifest・CSRF の除外など）がすべて `Set`・`Map`・`includes` で行われていて、**原型の名前で判定を通したり迂回したりできる箇所が無い**こと、
  汚染の受け皿（深いマージ・`Object.assign`・reviver）が無いこと、Next / React の版が既知の原型汚染の修正版より新しいことを確かめた。**テストは実行していない**
