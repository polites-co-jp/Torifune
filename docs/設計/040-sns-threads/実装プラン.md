### 確定事項（設計書から。プランで蒸し返さない）

* **Core（`apps/web` / `packages/plugin-api` / `migrations`）に 1 行も足さない。** 作るのは `plugins/sns-threads/` の 7 ファイル、テスト 7 本とテスト支援 1 本、E2E の 1 件追加だけ（設計 §3.1 / §4 / §4.3）
* **ユーザー裁定（2026-09-24）：Core の `KNOWN_PROVIDERS` / `PROVIDER_LABELS` に `threads` を足さない。** Plugin が無効な間は表示が生の値「threads」になるのを許容する（設計 冒頭 / §7 / §11 #1。#20 がこれを固定する）
* **オーケストレーター判断**：本文の数え方の非公開部分は**多めに数える**（設計 §9.4）。公開前の待ちは**固定の 30 秒ではなく状態のポーリング**で、準備に使えるのは 15 秒（設計 §6.4 / §6.8）
* **この Plugin は状態を 1 つも持たない。** `store` を読みも書きもしない、`registerSettings` を呼ばない、`context.ui` / `context.data` を呼ばない。`createThreadsPublisher` は **`store` を受け取らない**（`fetch?` / `now?` / `wait?` だけ。設計 §5.3 / §10.1）
* `plugin.json` は `permissions: []`、`extensions: ['social']` ちょうど、`dependencies` なし。**`name` / `description` に「Bluesky配信」「Instagram配信」「X配信」「Instagram」を含めない**（設計 §8.1）
* `credentialFields` は **`threadsUserId`（text）/ `accessToken`（secret）/ `accessTokenExpiresAt`（text）の 3 つで確定**。後から足せない（設計 §5.1）
* `limits` は **`{ mediaMax: 10 }` ちょうど**。`bodyMaxLength` と `mediaRequired` を宣言しない（設計 §9.1）
* **`manual()` を持つ。** 宛先は `https://www.threads.com/intent/post?text=<encodeURIComponent(toWellFormed(composeThreadsText(post)))>`。`url=` / `tag=` を使わない（設計 §9.5）
* 外へ出す要求は **R1〜R6 の 6 種類だけ**。宛先は `https://graph.threads.net`、版は `THREADS_API_VERSION = 'v1.0'`、どちらも `threads-api.ts` の定数（設計 §6.1）
* **トークンは `access_token` の引数で渡す**（POST は form の本体、GET はクエリ）。**`Authorization` ヘッダを付けない**（設計 §6.2。#13 / #52）
* **動画・`link_attachment`・`auto_publish_text`・`threads_publishing_limit` を使わない**（設計 §3.2）。`alt_text` は送る（設計 §6.12）
* **延長（R6）は公開（R4）に成功した後だけ**、残り 30 日未満か期限不明のとき。`rotatedCredential` は 3 キーを明示して組む（設計 §6.7）
* **`retryable` の支配的な規則**：R4 の前は既定 `true`（直らないものは `false`）、R4 の後は既定 `false`（レート制限だけ `true`）、R4 の成功後は `ok: true` を覆さない（設計 §6.9）
* `reason` に載せてよいのは **固定の日本語・HTTP status・既知の `code` / `error_subcode`・固定の案内文だけ**。自由文・URL・本体・例外の文面を載せない（設計 §6.11）
* **`sns-instagram` とコードを共有しない**（import も、バイト単位の一致の強制もしない）。`token.ts` の先頭に相互参照のコメントを置く（設計 §4.2）
* **マイグレーションは無い。** テーブルもカラムも Permission も足さない（設計 §5 / §8）
* **SaaS 固有機能（テナント・課金・コンテナ管理）に触るタスクは本プランに無い**

### テストの方法（設計書に無い、プラン側で決める手段）

* **偽の Threads API（A 群）**：`fetch` の偽物は「要求の列（URL・メソッド・ヘッダ・本体・`init.redirect`・`init.signal`）を記録し、
  **URL のパスとメソッドで R1〜R6 を見分けて**（`/threads` の POST の本体の `media_type` で R1 と R2、`/threads_publish` で R4、`fields=status` で R3、`fields=permalink` で R5、`/refresh_access_token` で R6）、
  `test-support/threads-api.ts` の応答例から `Response` を返す関数」を各ファイルにローカルで持つ。`createThreadsPublisher({ fetch: fake, now, wait })` に注入する（設計 §10.1）
* **form の本体を読む**：記録した `init.body` を `new URLSearchParams(String(body))` で読み、キーの有無と値を見る（#46 の「`alt_text` のキーが無い」は `has('alt_text') === false`）
* **偽の `fetch` の abort の振る舞い**：`init.signal` が発火したら **`signal.reason` で reject** する（本物と同じ。#90 が実測で固定する）。
  **本体は `toResponse(example, signal)` が作る、signal と結んだ `ReadableStream`**（ヘッダの後に abort されると本体の読み込みも reject する。#91）
* **`now` の注入**：可変の時計（`let current = Date.parse('2026-09-24T12:00:00.000Z'); const now = () => new Date(current);`）。
  **偽の `fetch` や偽の `wait` の中で `current` を進める**と、準備期限・R4 の残り・R6 の残りを実時間を待たずに作れる

## 3. タスク分解

原則：**1 タスク = 1 論理変更**。各タスクは「テストを書いて失敗を確認 → 実装 → 通す」の順。
各まとまり（G1〜G9）の最後で **`pnpm generate:plugins`** → `pnpm lint` / `pnpm format:check` / `pnpm typecheck` / `pnpm test` が通る。
E2E（`pnpm test:e2e`）は **G1 の T2（#105 を先に確かめる）と G9 の T29** で全件流す。

**test-writer → implementer への受け渡しの単位は G（まとまり）。** test-writer は G の中の全タスクのテストを設計書だけを見て書き、**失敗を確かめて**からコミットする（`037`〜`039` と同じ運用）。
implementer は G の中のタスクを順に通し、**G の検証がすべて緑になってから**コミットする。テストが設計と食い違うと判断したら、テストを直さず「設計書のどこと食い違うか」を報告して止まる（`CLAUDE.md`）。

**着手順の骨子**：骨格 → **既存 E2E への影響を先に確かめる（#105）** → 純関数（`threads-text.ts`）→ `validate()` / `manual()` / `token.ts` → `threads-api.ts` の純関数 →
外部 I/O の正常系 → `retryable` と秘匿 → 偽物と本物の一致・定数の結線 → Core を通した結合 → 文書と静的検査・最終確認 → 検証。

## 7. リスクと注意点

1. **`fetch(` / `globalThis.fetch` の綴りを増やさない（T1 / T10 / #2）。** `threads-api.ts` の内部は `impl(url, init)` で呼ぶ。`ThreadsPublisherOptions.fetch` の型は `FetchImpl`
2. **禁止の綴りをコメントにも書かない（全タスク / #3 / #7 / #8 / #13）。** `store.` / `console.` / `context.ui` / `Authorization` / `Bearer` / `Date.now` / `new Date(` は字面で見られる。
   「Bearer を使わない」と書きたくても書かない（「`access_token` の引数で渡す」と書く）
3. **要求ごとの `AbortSignal.timeout` は `impl()` の直前に同期で作る（T10 / #80）。** carousel の子と R3 は並行に走るので、生成と呼び出しのあいだに `await` を挟むと「直前に作られた controller」が別の要求のものになる。
   **R1 / R2 / R4（10 秒）と R5 / R6（3 秒）は値が同じ**なので、値の一致だけで結線を見たつもりにならない
4. **abort の理由で分類を分ける（T10 / T18 / T22）。** 本物の `fetch` は `signal.reason` で reject する。`AbortSignal.timeout` 由来は `TimeoutError`、子どうしの打ち切りと `input.signal` は `AbortError`。
   **「子どうしの打ち切りは失敗に数えない」「合計・準備の期限は `timeout`」「`input.signal` はその場で抜ける」**を、`error.name` だけでなく**どの signal が `aborted` か**でも確かめて決める。偽物の reject の名前は #90 の実測に合わせる
5. **`budget` の判定は `now()`、打ち切りは `AbortSignal.timeout`（T12 / T19）。** 判定を実時間だけに預けると `budget` の分岐をテストが通せない（`036` R-2）。逆に `now()` だけにすると本番で打ち切りが効かない。**両方を持つ**。
   既定の `now()` は壁時計（設計 §11 #15。時計が戻っても合計の期限が R4 を打ち切り、`false` に倒れる）
6. **R4 は外側の signal の下で送る（T10 / #81）。** 準備の signal を渡すと、準備に 14 秒かかった配信の R4 が 1 秒で切られ、`retryable: false`（結果不明）を量産する
7. **R4 の後は疑わしきを `false` に倒す（T20）。** `transient`・5xx・200 以外の 2xx・JSON でない・`id` 無し・ヘッダの後の本体の打ち切りも `false`。**SNS の投稿は取り消せない**
8. **R4 の成功後は `ok: true` を覆さない（T14 / T15）。** R5 / R6 の失敗・形の不一致・例外は `externalUrl` / `rotatedCredential` を省くだけ
9. **トークンは URL と本体に載る（T10 / T21）。** `sendThreadsRequest` の結果に URL・本体・例外の文面を持たせない。**例外の `message` をログに渡さない**（本物の `fetch` の例外の文面に URL が入ることがある）。
   計測のために要求を包むラッパを足さない
10. **外部の ID は形を見てからパスへ入れる（T10 / T13 / T14）。** container ID・子の ID・media ID は `isValidThreadsId` を通したものだけを次の要求のパスに使う。合わない R1 / R2 の `id` は P1 の `true`（次の要求を出していない）、合わない R4 の `id` は `{ ok: true }`
11. **`rotatedCredential` を `...credential` で組まない（T15 / #57 / #64）。** Core が将来 `credential` に何かを足しても書き戻さないため
12. **テスト名と通った分岐を一致させる（T11 / T17〜T20 / #65）。** 各テストは `fields.phase` をアサートする。**到達できない分岐（R4 の後の予期しない例外）を検証済みと名乗るテストを作らない**
13. **#105 が落ちたら既存の spec を直さない（T2）。** 「変更なしで通る」ことが条件。原因を特定し、**Plugin の `name` / `description` で避けられるか**を見たうえで、直す場所の判断を仰ぐ
14. **`plugins/` を変えたら `pnpm generate:plugins`（全タスク）。** `generated-registry.ts` は Git 管理外で、`pnpm typecheck` は生成を走らせない。先に叩かないと古いまま
15. **`plugins/sns-instagram/token.ts` のコメント（T8）。** `sns-instagram-static-checks.test.ts` は `token.ts` の字面を見る（#3：`Date.now` / 引数なしの `new Date(`、#7：`store.` ほか）。コメントに禁止の綴りと相対パスを書かない。**コードは 1 文字も変えない**
16. **B 群は `globalThis.fetch` を差し替える（T24〜T26）。** `index.ts` は `fetch` を注入しない。**`afterEach` で必ず元へ戻す**。既定の `wait` は本物の `setTimeout` なので偽の R3 は最初から `FINISHED`
17. **テストの値（全テスト）。** 資格情報に `torifune` を含めない、トークンに符号化で形の変わる文字を含める、先頭 8 文字を固定文の部分文字列にしない（§2 のテストの方法）
18. **E2E の実行環境（T2 / T29）。** 作業機の 3000 番が別のアプリに塞がれていることがある（`reuseExistingServer` がそれを使ってしまう）。塞がっていれば Playwright のコンテナで流す（`039` §8 の 35）。
    **E2E を `pnpm test` や `verify-container-rebuild.sh` と同時に流さない**（Windows でソケットの資源が尽きる）
19. **`scripts/verify-container-rebuild.sh` は Docker が要る（T29）。** 無い環境では飛ばし、**飛ばしたことを検証レポートへ申し送る**
20. **公開リポジトリである（T27 / 全コミット）。** README・コメント・コミットメッセージは第三者が読む。運営側の事情・公開数の上限の数値を書かない
21. **実機の Threads で一度も動かさない（設計 §11 #11）。** T22 が保証するのは「偽物が本物の `fetch` と同じに振る舞う」ことまでで、「偽の Threads API が本物と同じ」ことではない。
    `access_token` を引数で渡す形・`permalink` のドメイン・延長の振る舞い・エラーの封筒・テキストの処理待ち・`v1.0` のパスは**運用者の実機確認**に残る
22. **公式の文書は変わる（設計 §12）。** 実装の着手時（T9 の前）に F1〜F21 を読み直し、食い違いがあれば**実装より先に設計を直す**（判断を仰ぐ）
