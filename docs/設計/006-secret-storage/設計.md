# Secret 保管 設計

## 1. 目的

Secret を平文で持たない共通基盤を作る。
SNS の Access Token（`009-social`）と Plugin の Secret 設定（`011-plugin-runtime`）が共用する。

満たすべきことは3つ。

1. **DB 上で平文にしない。**
2. **型レベルで、平文が API レスポンスや画面へ出ないようにする。**
   「気をつける」に頼ると、いつか出る
3. **鍵が未設定・不正なら起動に失敗する。** 黙って平文保存へ落ちない

## 2. 上位仕様との対応

| 文書 | 節 | 具体化する内容 |
| --- | --- | --- |
| `02_データベース設計.md` | §13 | 機密情報を平文で保存しない。暗号鍵を DB へ保存しない |
| `04_認証設計.md` | §22 | Token の用途を区別する |
| `05_API設計.md` | §18 | Access Token 等を Response へ返さない |
| 〃 | §25 | Plugin Configuration の一般設定と Secret を区別する |
| `06_画面設計.md` | §38 | Secret を画面へ平文で再表示しない |
| `07_開発者向けガイド.md` | §35-36 | Secret をコミットしない・ログへ出さない |

実装計画の決定事項：D-13（AES-256-GCM、鍵は環境変数、暗号文に鍵IDを併記）。

## 3. スコープ

### やること

* 暗号化・復号（AES-256-GCM）
* 鍵の読み込みと検証（起動時に失敗させる）
* 鍵IDの併記（ローテーションの余地）
* `Secret<T>` 型。JSON 化しても平文が出ない
* マスク表示のための「設定済みか」だけを返す口

### やらないこと

* 鍵管理サービス（KMS）連携。環境変数のみ
* 実際の鍵ローテーション手順（`08_運用設計` 相当。器だけ用意する）
* Secret の失効・世代管理

## 4. レイヤ配置

```text
apps/web/src/
├── infrastructure/
│   └── crypto/
│       ├── key.ts       鍵の読み込みと検証
│       └── cipher.ts    暗号化・復号
└── domain/
    └── secret.ts        Secret 型（平文を外へ出さない）
```

`domain/secret.ts` は**暗号方式を知らない**。「平文を持つが外へ出さない箱」だけを定義する。

## 5. データモデル

暗号文は1つの文字列に収める。カラムを増やすと、テーブルごとに同じ設計を繰り返すことになる。

```text
v1.<keyId>.<iv(base64url)>.<authTag(base64url)>.<ciphertext(base64url)>
```

* `v1` は形式のバージョン。将来アルゴリズムを変えるときの目印
* `keyId` は鍵の識別子。**鍵そのものは含まない**
* GCM の認証タグを含めるため、改ざんを検出できる

## 6. API

このスプリントは HTTP API を持たない。

## 7. 画面

なし。`SecretField` コンポーネントは `005-ui-shell` で作る。

## 8. 権限（Permission）

なし。

## 9. Plugin API への影響

`011-plugin-runtime` の Configuration API が、一般設定と Secret 設定を型で分けるときに使う。

**Plugin に復号済みの値を渡す**のは避けられない（外部 API を叩くのは Plugin だから）。
ただし「読み出したこと」を監査できる形にする余地を残す。

## 10. 受け入れ条件

### 暗号化

1. 暗号化した値が元の平文を含まない
2. 同じ平文を2回暗号化すると異なる暗号文になる（IV が毎回変わる）
3. 暗号文から元の平文へ復号できる
4. 空文字を暗号化・復号できる
5. マルチバイト文字を正しく往復できる
6. 長い値（1MB）を往復できる

### 改ざん検出

7. 暗号文の1文字を変えると復号に失敗する
8. 認証タグを変えると復号に失敗する
9. IV を変えると復号に失敗する
10. 形式が壊れた文字列の復号が失敗する
11. **復号の失敗が例外ではなく結果として返る**（呼び出し側が握り潰さないように）

### 鍵

12. 鍵が未設定なら例外になる
13. 鍵が 32 バイトでなければ例外になる
14. Base64 として不正なら例外になる
15. 暗号文に鍵IDが含まれる
16. **暗号文に鍵そのものが含まれない**
17. 別の鍵で暗号化した値は復号できない
18. 鍵IDが一致しない暗号文の復号が失敗する

### Secret 型

19. `Secret` を `JSON.stringify` しても平文が出ない
20. `String(secret)` しても平文が出ない
21. `console.log` 相当（`util.inspect`）でも平文が出ない
22. `secret.expose()` で明示的に取り出せる
23. テンプレートリテラルへ埋め込んでも平文が出ない

### 設定済み判定

24. 値が設定されていれば「設定済み」を返す
25. 未設定なら「未設定」を返す
26. **設定済み判定の結果に平文が含まれない**
