| --- | --- | --- |
| T1 | `Secret` 型 | `domain/secret.ts` |

## 2. 設計上の判断

### 2.1 平文を隠すのは型の責務にする

「Secret はログに出さない」を規約にすると、いつか出る。
`toString` / `toJSON` / `util.inspect` / `Symbol.toPrimitive` のすべてを塞ぎ、
**取り出すには `expose()` を明示的に呼ぶ**形にする。

`expose()` の呼び出し箇所は grep でき、レビューできる。

### 2.2 平文フィールドを private class field にする

`#value` にすることで、スプレッドや `Object.keys` でも見えない。
`private` キーワードだけでは、実行時には普通のプロパティなので漏れる。

### 2.3 復号の失敗を例外にしない

例外にすると、呼び出し側が `try/catch` で握り潰して
「復号できなかったのに処理が続く」状態を作りやすい。
結果型で返し、`ok` を見ないと値が取れない形にする。

### 2.4 失敗理由を3つに分ける

| 理由 | 意味 | 呼び出し側の行動 |
| --- | --- | --- |
| `malformed` | 形式が壊れている | データが壊れている。復旧が要る |
| `wrong_key` | 鍵IDが違う | ローテーション中なら旧鍵で試す |
| `tampered` | 認証タグが合わない | 改ざんか鍵の取り違え。信用しない |

`wrong_key` を分けているのは、ローテーションを実装するときに必要になるため。

### 2.5 暗号文を1つの文字列に収める

`v1.<keyId>.<iv>.<authTag>.<ciphertext>`

カラムを分けると、Secret を持つテーブルごとに同じ設計を繰り返すことになる。
文字列1つなら、既存のテーブルへ列を1つ足すだけで済む。

## 3. 影響範囲

| 対象 | 影響 |
| --- | --- |
| `009-social` | SNS の Access Token 保存に使う |
| `011-plugin-runtime` | Plugin の Secret 設定に使う |
| マイグレーション | 不要（このスプリントでは列を追加しない） |

**破壊的変更：なし**

## 4. リスク

| リスク | 対応 |
| --- | --- |
| 鍵を失うと復号できない | 運用の問題。`.env.example` に「失うと復号できない」旨を書く |
| `expose()` が乱用される | 呼び出し箇所をレビュー対象にする。将来 ESLint 規則を検討 |
| base64 の末尾文字を書き換えても値が変わらず、改ざんテストが不安定になる | バイト列で操作するテストヘルパを用意した |
