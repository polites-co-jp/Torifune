### 確定事項（設計書から。プランで蒸し返さない）

* **当たり判定**：`Table` の `Column.onCellClick?: (row: T) => void`。渡した列の `<td>` に `onClick` と `cursor: pointer`。セルの中の操作できる要素（`CELL_CLICK_IGNORE_SELECTOR`）からのクリックでは呼ばない（`isCellClickIgnored`）。
  付けるのは**選択の列のセルと状態のセル**（送信待ち・投稿の両タブ）。キーボードは今のチェックボックスのまま、セルに `tabindex`・`role` を足さない（ユーザー裁定 2。設計 §5.1）
* **送信待ちタブの帯は「一括投稿…」「一括取り消し…」**。「一括送信（承認）…」「選んだ手動投稿を順に投稿…」は出さない。**投稿タブは 054 のまま**（ユーザー裁定 3。設計 §7.2）
* 一括投稿の振り分けは `bulkPostPlanOf`（設計 §5.2 の表）。承認待ちは `canApprove` で承認（即投稿）し、手動は `canWrite` も要る（ユーザー裁定 4）。手動の予約に `publish-now` を掛けない。時機は即投稿だけ
* 呼び順：（同期）先頭が予約済みの手動なら窓を開く → `bulk/approve`（`publishTiming: 'now'`）→ `bulk/publish-now` → 承認できた手動ごとに `GET manual-handoff`（並行）。順に開くのは予約済みの手動（表の順）→ 承認できて URL の取れた手動（表の順）（設計 §7.4）
* **承認した手動の URL は新しい画面専用の `GET /api/v1/social/posts/{id}/manual-handoff`**（`sessionOnly`・`social.read`・`operationId` `getSocialPostManualHandoff`・既存の `resolveManualHandoff` を `deadline` なしで呼ぶ。新しい UseCase は作らない）（設計 §5.3・§6）
* 記録の `expectedUpdatedAt` は、承認した手動では承認の結果の `post.updatedAt`（設計 §5.3）
* **窓の開き方は変えない**（`openManualWindow`・`noopener=yes,noreferrer=yes`）。`win.closed` を見ない・`setInterval` を使わない。「戻ってきた」＝開いた後に `blur` か `hidden`、その後 `focus` か `visible`。段は `ready`・`opened`・`returned`（純関数 `windowStageAfter`）。「記録へ進む」で戻らずに `returned`（設計 §5.4）
* 次の窓は「投稿した」「失敗にする」のクリックの同期処理の中で、**記録の要求より先に**開く。最後の件では開かない。記録が失敗しても次の窓は開いたままで、「飛ばして次へ」は開き直さない（設計 §5.4・§7.5）

## 3. タスク分解

原則：**1 タスク = 1 コミット**。各タスクは「テストを書いて失敗を確認 → 実装 → 通す」の順。

**test-writer → implementer への受け渡しの単位は G。** test-writer は G の中の全タスクのテスト（と既存テストの追従）を先に書き、新しいテストが**期待どおりの理由で**赤いことを確かめて `test:` でコミットする（`pnpm typecheck` / `pnpm lint` / `pnpm format:check` は通る状態で。未実装のモジュールは動的 import、未実装の props は型をテストの中で写す）。implementer は G の中のタスクを順に通し、タスクごとに `feat:` でコミットする。
**implementer はテストを書き換えない。** 食い違いは設計書のどこと食い違うかを報告して止まる。

**プッシュの約束**：プッシュの前に `pnpm test` を**全件**流す（postgres-test、`DATABASE_URL=postgresql://torifune:torifune@localhost:21701/torifune_test`、`TORIFUNE_ENCRYPTION_KEY=dGVzdC1vbmx5LWtleS1kby1ub3QtdXNlLWluLXByb2Q=`）。赤くてよいのは、いま取り組んでいる G のまだ実装していないタスクのテスト（と、その G で追従した既存テストのうち実装を待つもの）だけ。`main` へプッシュしない、マージしない、`--force` は使わない。

**着手順の骨子**：当たり判定（独立して先に出せる）→ 取得の口（API）→ 純関数 → 画面（部品の作り直しと組み込み）→ 文書 → 最終確認と 3 つの検証。G2 は G1 と独立だが順に進める。G4 は G2・G3 に依存する。

## 7. リスクと注意点

1. **セルの `onClick` の二重の切り替え（T2・T3）。** チェックボックスのクリックはセルへ泡立つ。`isCellClickIgnored` は `event.target` から `closest` で操作できる要素を探し、**それがセル（`event.currentTarget`）の中にあるとき**だけ無視する。`label` を選択子に含めるので、将来セルの中に `<label>` を置いても二重にならない
2. **描画器のフック（T10・T11）。** 描画器が差し替えるのは `useState`・`useRef`・`useId` だけで、`useEffect` は走らない。部品の新しい状態は `useState` / `useRef` で持ち、`useCallback`・`useMemo`・`useReducer`・`useTransition` を使わない（使うと描画器の中で本物のフックが呼ばれて落ちる）。聞く処理は `useEffect` の中なので単体では走らず、段の移り方は #21 の純関数と #30〜#31 のボタンで見る
3. **聞き始める前の `blur`（T10）。** 窓はクリックの中で同期で開くので、`blur` は `useEffect` が付く前に届きうる。付けた時点で `document.hidden || !document.hasFocus()` なら `left` を 1 回送る（設計 §5.4）
4. **記録の前に次を開く（T10）。** 押した処理の最初の同期の部分で `openManualWindow(next.url, props.open)` を呼び、その後に `await apiRequest(...)`。開いたかどうか（`nextOpened`）を状態に持ち、記録が失敗した後の「飛ばして次へ」はそれを見て `opened` か `ready` を決める
5. **`SocialPending` の `initialDialog` の型（T11）。** 送信待ちタブに 054 の一括送信が無くなるので `'send'` を受けない。既存のテストの写し（`PendingProps`）も直す（§2）。`BulkPostActions` は投稿タブのために `'send'` を受け続ける
6. **終わりの表示の後の読み込み直し（T11）。** `BulkPostActionsApi.reload`（選択を空にして `RefreshOnMount`）を使う。Toast は出さない（設計 §7.5）
7. **E2E の窓（T9・T11）。** `example-plugin` の URL は同じオリジンなので子のページで `evaluate(() => window.opener)` が読める（#53）。本文は 100 字以内（`example-plugin` の上限。056 プラン §8 の 10）
8. **E2E の「戻ってきた」（T9）。** Playwright はページを切り替えても `focus`・`blur` を起こさない。とりふねのページで `page.evaluate(() => { window.dispatchEvent(new Event('blur')); window.dispatchEvent(new Event('focus')); })` を呼ぶ。もし環境で本物の `blur`・`focus` が起きて「戻る前は投稿したが無い」（#53）が揺れたら、#53 の確かめを子の窓が開いた直後（`waitForEvent('page')` の解決の直後）に置く
9. **E2E の DB の共有（T9）。** 送信待ちの 1 ページ目に前の spec の予約が並びうる。一括投稿の対象は自分で作った行のチェックだけで選び（「このページの投稿をすべて選択」を使わない）、確認の内訳の件数で見る
10. **`openapi-additional-responses.test.ts` の数（T4・T5）。** `GET` に本文が無いので 422 が既定の応答に入らない前提で `additionalResponses` に 422 を宣言する。既定に入る作りなら 404 だけを宣言し、表の行を `[404]` にする（T5 で `route.ts` を読んで決め、§8 に記録する）
