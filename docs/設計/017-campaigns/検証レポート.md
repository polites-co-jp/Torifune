## 実装中に見つけて直したこと

### `date` 型がタイムゾーンで1日ずれていた

node-postgres は `date` を**ローカルタイムゾーンの0時**として `Date` にする。
それを `toISOString()` で `YYYY-MM-DD` にすると、UTC より東のタイムゾーンでは
**1日前になる**（JST で `2026-04-01` を保存して `2026-03-31` が返る）。

テストが実測で捕まえた（`expected '2026-03-31' to be '2026-04-01'`）。
ローカルの年月日をそのまま取り出す形へ直した。

**同じ罠を `018-analytics` でも踏むところだった**ので、そちらの
`toDateOnly` にも同じ注意を書いてある。

### E2E がデータの蓄積で壊れた

`global-setup.ts` の後始末に `campaigns` が無く、実行のたびに一覧へ
積み上がって、同名の行が複数一致するようになった。

**テストが実行回数に依存していた。** 後始末へ `campaigns` /
`system_settings` / `api_tokens` を足した（`api_tokens` と
`system_settings` は T3・T4 で足したときの漏れ）。
