# 実装計画 002 — Torifune機能完成

## 1. この計画のゴール

`docs/仕様書/` が実装を要求する **193§ をすべて満たす**。

2026-09-01 時点で、実装済み133・部分的49・未実装11。
この計画の完了をもって、部分的・未実装を 0 にする。

`001-Torifune単体稼働` は「単体で動く」ことをゴールにしており、
マーケティング機能そのもの（キャンペーン・アナリティクス）と、
外部クライアント向けの口（API Token・Webhook）を意図的に外していた。
それらを含めて仕様どおりにする。

## 2. なぜこの計画が要るのか

`001` の「次の計画に送るもの」に7件が積まれていたが、
**それを受け止める計画が作られないまま `015-settings` と `016-home-routing` が
実装された。** その結果、

* `014-dashboard` は番号を振られたまま飛ばされ、ダッシュボードは器だけが残った
* API Token に割り当てられた `016` は `016-home-routing` と衝突した
* 仕様書にありながらどの計画にも載らない欠落が19件たまった
  （`001/03_リスクと未決事項.md` S-8）

計画の外に落ちたものは誰も拾わない。この計画がその受け皿になる。

## 3. この計画に含めないもの

### 責務としてTorifuneに入れないもの（`CLAUDE.md`「絶対に守る境界」）

マルチテナント、SaaSとしてのユーザー登録・管理、テナントDB管理、課金、コンテナ運用基盤。
すべて TorifuneHub の責務。

### 仕様が「将来」としているもの

* Plugin のサンドボックス実行（`03_プラグイン設計.md` §23）
* Cursor Pagination（`05_API設計.md` §33。Offset で足りている間は作らない）
* OIDC Plugin 本体（`04_認証設計.md` §17。Core は差し替え口までを持つ）

これらは仕様自身が「初期実装で必須としない」としており、
**達成条件から外す**。外したことをここに書いておく（また落ちないように）。

## 4. 完了条件

1. `docs/仕様書/` の実装対象193§が、すべて「実装済み」であること
2. 各スプリントに `docs/設計/<ID>-<slug>/` の設計・実装プラン・検証レポートが揃っていること
3. `pnpm lint` / `typecheck` / `test` / `test:e2e` / `format:check` がすべて緑
4. `001/03_リスクと未決事項.md` S-8 の19件すべてに決着がついていること
   （実装した／仕様を改訂した／明示的に将来送りにした、のいずれか）

## 6. 進め方

`001` と同じ。1スプリント = `/feature` 1回 = `docs/設計/<ID>-<slug>/` 1ディレクトリ。
design-writer → impl-planner → test-writer → implementer → 検証3種の順を守る。

**この計画は完走する**（`~/.claude/CLAUDE.md`「実装計画があるものは完走する」）。
スプリントが1つ終わっても指示を待たず次へ進む。
スコープから外す判断はユーザーの裁定を要する。

## 7. 採番について

`001` の「次の計画に送るもの」が付けた想定IDを**原則そのまま使う**。
コードのコメントが `015b` と `019-notification` を参照しており、
繰り上げると参照が壊れるため（`改訂履歴.md` 2026-08-24 の欠番と同じ判断）。

例外は API Token のみ。想定IDの `016` は `016-home-routing` が使用済みのため
**`021-api-token` へ改番する**。コードからの参照は無く、壊れるものが無い。
