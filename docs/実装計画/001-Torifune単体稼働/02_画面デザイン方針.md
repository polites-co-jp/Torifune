# 画面デザイン方針（最低限デザイン）

この計画では、画面デザインを**機能を操作できる最低限**に留める。
見た目の詳細は後から詰めるため、ここでは「今やらないこと」と
「後から詰めるために今だけは守ること」を明確にする。

---

## 1. 今回やらないこと

* ブランディング（ロゴ、配色設計、タイポグラフィの作り込み）
* イラスト、アイコンセットの選定・作成（暫定で単色の簡素なアイコンのみ）
* アニメーション、トランジション、マイクロインタラクション
* レスポンシブの作り込み。**PCブラウザ幅のみを対象**とし、
  タブレット・スマートフォン対応は次計画に送る
  （`06_画面設計.md` §31 は「PCを主要ターゲット」としているため方針違反ではない）
* ダークモード
* 画面ごとの独自レイアウト。すべて §4 の3つの型に寄せる

---

## 2. 後から詰めるために、今だけは守ること

デザインを後回しにすると高くつくのは、**後から入れ直すのが困難な3つ**だけである。
逆に言えば、この3つさえ守れば残りはいつでも差し替えられる。

### 制約1. 色・余白・角丸・フォント・影を CSS 変数に集約する

コンポーネントは生の値を書かず、必ず変数を参照する。

```css
:root {
  /* 面と文字 */
  --tf-color-bg:            #ffffff;
  --tf-color-surface:       #f7f7f8;
  --tf-color-border:        #e3e3e6;
  --tf-color-text:          #1a1a1e;
  --tf-color-text-muted:    #6b6b73;

  /* 意味を持つ色 */
  --tf-color-primary:       #2f6fdb;
  --tf-color-primary-text:  #ffffff;
  --tf-color-danger:        #c0392b;
  --tf-color-success:       #1e8e5a;
  --tf-color-warning:       #b8860b;

  /* 余白は 4px 刻みの6段階だけ */
  --tf-space-1: 4px;  --tf-space-2: 8px;  --tf-space-3: 12px;
  --tf-space-4: 16px; --tf-space-6: 24px; --tf-space-8: 32px;

  --tf-radius-sm: 4px;  --tf-radius-md: 6px;  --tf-radius-lg: 10px;
  --tf-shadow-1: 0 1px 2px rgba(0,0,0,.06);
  --tf-shadow-2: 0 4px 12px rgba(0,0,0,.10);

  --tf-font-sans: system-ui, "Hiragino Sans", "Noto Sans JP", sans-serif;
}
```

上記の値は**暫定**であり、デザインを詰めるときにここだけ差し替える。
`005-ui-shell` の受け入れ条件に「生の hex 値・ピクセル直書きが存在しないこと」を含める。

### 制約2. コンポーネントに業務ロジックを持たせない

共通コンポーネントは props だけで見た目が決まるものとし、
API 呼び出し・権限判定・ドメイン知識を持たせない。
これを守らないと、デザイン変更のたびに業務ロジックを触ることになる。

### 制約3. Loading / Empty / Error / 権限なし の4状態を最初から用意する

後から差し込むのが最も高くつくのがこの4状態。
一覧・詳細・ダッシュボードのすべてで、最初から4状態を持つ。

```text
Loading   スケルトンではなく単純なスピナーで可
Empty     「まだありません」＋次の操作への導線（06_画面設計.md §35）
Error     APIのエラーコードを人間向け文言へ変換して表示。Stack Trace は出さない
権限なし   403 の画面。メニューを隠すだけにしない（06_画面設計.md §29）
```

## 3. 作る共通コンポーネント（これで打ち止め）

`06_画面設計.md` §32 のリストから、マイルストーンAに必要なものだけを取る。

| コンポーネント | 用途 |
| --- | --- |
| `Layout`（Header / SideNav / Main / Footer） | 共通レイアウト（`06_画面設計.md` §7） |
| `Button` | primary / secondary / danger / ghost の4種のみ |
| `Input` / `Textarea` / `Select` / `Checkbox` | フォーム部品 |
| `FormField` | ラベル＋説明＋エラー文言の枠 |
| `Card` | 区画 |
| `Table` ＋ `Pagination` | 一覧 |
| `Modal` | ダイアログの土台 |
| `ConfirmDialog` | 不可逆操作の確認（`06_画面設計.md` §37） |
| `Alert` | 画面内の常設メッセージ |
| `Toast` | 操作結果の通知（`06_画面設計.md` §36） |
| `EmptyState` | 空状態 |
| `Spinner` | 読み込み中 |
| `SecretField` | Secret のマスク表示と再入力（`06_画面設計.md` §38） |

`DatePicker` と `Chart` は**今回作らない**。
日時は `<input type="datetime-local">`、集計の可視化は数値表示で済ませ、
必要になった時点（Analytics のスプリント）で追加する。

これらは Plugin から利用される公開契約になる（`06_画面設計.md` §32）ため、
`packages/plugin-api` から型として参照できる形にしておく。

## 4. 画面は3つの型に寄せる

1機能ごとに新しい画面型を作らない。すべて以下のいずれかで作る。

```text
型A. 一覧画面
  ┌──────────────────────────────────┐
  │ 見出し                  [+ 新規] │
  ├──────────────────────────────────┤
  │ Table                            │
  │  … 行ごとに [編集] [削除] Action │
  ├──────────────────────────────────┤
  │ Pagination                       │
  └──────────────────────────────────┘

型B. 作成・編集フォーム
  ┌──────────────────────────────────┐
  │ 見出し                           │
  ├────────────────────┬─────────────┤
  │ FormField の縦積み │ サイドバー  │  ← Extension Point
  │                    │             │
  ├────────────────────┴─────────────┤
  │            [キャンセル] [保存]   │
  └──────────────────────────────────┘

型C. ダッシュボード
  ┌──────────────────────────────────┐
  │ Card を並べるグリッド             │  ← Widget の Extension Point
  └──────────────────────────────────┘
```

Plugin の Extension Point（`content.edit.sidebar` / `content.list.actions` /
`dashboard.after`）は、この3型の中に位置が確保されている。
**デザインを詰めるときに Extension Point の位置が消えないよう**、型を先に決めておく。
