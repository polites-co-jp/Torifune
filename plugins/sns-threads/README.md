# Threads配信（`sns-threads`）

Torifune に予約した SNS 投稿を、**Threads（Meta の Threads API）へ配信する** Plugin です。
**手動投稿（Threads の投稿画面を開いて人が送信する）にも対応しています。**

Torifune 本体は「いつ送るか・再試行・記録・画面」を持っています。
この Plugin が受け持つのは **1 件を Threads へ公開すること**、**必要ならアクセストークンを延長して Torifune へ返すこと**、
手動投稿のときに **投稿内容の入った Threads の投稿画面の URL を組み立てること**だけです。

**テキストだけの投稿と、画像（1〜10 枚）を添えた投稿を配信します。動画には対応していません。**

## 導入のしかた

1. `plugins/sns-threads/` を Torifune の `plugins/` の下に置きます
2. `/plugins` の「検出済み」に **「Threads配信」** が現れるので「導入」を押します
3. **再ビルドと再起動が要ります。** Plugin のコードはアプリのビルドに取り込まれるため、
   導入しただけでは動きません（画面の案内に従ってください）
4. `/plugins` で **有効化**します
5. `/social` で `provider` が **Threads** の SNS アカウントを作り、資格情報（3 項目）を入れます。各欄の下に、その値の用意のしかたが出ます。
   既にあるアカウントには、`/social` のアカウントの行の **「資格情報を設定」** から入れます

この Plugin は画面の設定を持ちません（`/plugins/sns-threads/settings` はありません）。

### Plugin を無効にしている間の表示

Torifune 本体は Threads を知らないため、**この Plugin を無効にしている間は、アカウントと投稿の SNS の表示が生の値の「threads」になります。**
アカウントを追加するときの選択肢からも消え、「資格情報を設定」には 3 項目の欄ではなく汎用の欄が出ます。
**資格情報の入力・入れ直しは、この Plugin を有効にしてから行ってください。**

## 用意するもの

### Threads のアカウントと Meta の App

**Threads のアカウントと、Meta の開発者向け画面（Meta for Developers）で作った App が要ります。**

### 長期アクセストークンとユーザー ID

次の手順で用意します（画面の名前は Meta 側の変更で変わることがあります）。

1. Meta for Developers で App を作り、**Threads API** を使えるようにします
2. 投稿に使う Threads のアカウントでログインし、次の 2 つの権限を許可します
   - `threads_basic`
   - `threads_content_publish`
3. 発行された短期のアクセストークン（1 時間で失効します）を **長期アクセストークン** に交換します
   （Threads API の `th_exchange_token`。交換には App の App Secret が要ります）
4. ユーザー ID を確かめます。長期アクセストークンで自分のプロフィール（`/me` の `id`）を問い合わせると分かります。
   **数字だけの ID です。`@` で始まるユーザーネームではありません**

- アクセストークンや App Secret を**コマンドラインに直書きしないでください**（シェルの履歴やプロセスの一覧に残ります）。
  交換や問い合わせを手元で行うときは、ファイルか標準入力で渡してください

### Torifune に入れる 3 項目

| 項目                 | 入れるもの                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| Threads ユーザー ID  | 数字だけの ID（例：`17841400000000000`）。ユーザーネームではありません                            |
| 長期アクセストークン | 上で発行した長期アクセストークン（`threads_basic` と `threads_content_publish` の権限があるもの） |
| トークンの有効期限   | 例：`2026-11-23T00:00:00Z`。**分からなければ `unknown` と入れてかまいません**                     |

Torifune に保存した資格情報は暗号化され、**保存後は画面に再表示されません。**
入れ直すときは、`/social` のアカウントの行の「資格情報を設定」で **3 つとも**入れ直します（保存すると丸ごと置き換わります）。

## トークンは60日で失効します

長期アクセストークンの有効期限は **60日**です。

- Torifune が延長するのは、**配信が成功したときだけ**です。
  配信が成功した時点で**残りが 30 日を切っていれば**（または期限が `unknown` なら）トークンを延長し、
  新しいトークンと期限を Torifune が保存し直します
- **30 日以上配信しない期間があると、トークンはそのまま失効しえます。失効したトークンは延長できません。**
  失効すると、次の配信は「アクセストークンが無効か期限切れです」という理由で失敗します。
  その場合は長期アクセストークンを発行し直し、`/social` のアカウントの行の「資格情報を設定」から入れ直してください
- 期限に `unknown` を入れた場合は、**次に配信が成功したときに延長を試み**、正しい期限に書き換えます
- **延長できるのは、発行から 24 時間以上たったトークンだけです**（Threads API の決まり）。
  発行してすぐに期限を `unknown` として入れると、最初の配信では延長に失敗することがあります。その場合は**次に成功した配信で延長されます**
- 延長に失敗しても、**投稿そのものは成功として扱います**（理由はサーバのログにだけ残ります）
- **配信の最中に資格情報を入れ直すと、その配信で延長したトークンは保存されません。** 入れ直した値が正として残ります
  （Torifune は、配信を始めたときから資格情報が変わっていないときだけ延長したトークンを書き戻します）

## 資格情報を入れるまでの猶予は約24時間です

Plugin を有効にしていない、あるいは資格情報を入れていない状態でも、投稿の予約そのものは受け付けます。
ただしその投稿は配信されずに待たされ、**予約時刻から約24時間で `failed` になります。**

`failed` は終端の状態です。**そこから配信し直すことはできず、新しい投稿として登録し直す**ことになります。
予約を入れたら、24時間以内に有効化と資格情報の登録を済ませてください。

## 投稿の作りかた（Threads の制限）

| 決まり              | 値                                                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 本文の長さ          | **500文字**まで。**絵文字は 1 つを UTF-8 のバイト数（多くは 4）で数えます**                                                |
| リンク（`link`）    | **本文の末尾に改行して足します**。足した後の本文で長さとリンクの本数を数えます（自動・手動とも同じ）                       |
| リンクの本数        | **本文の URL と `link` を合わせて、異なるものが5本まで**                                                                   |
| 画像                | **0〜10 枚**（画像なしのテキストだけの投稿もできます）。2 枚以上ならカルーセル（複数枚の投稿）になります。動画は扱いません |
| 画像の説明（`alt`） | **Threads へ送られます**                                                                                                   |
| `providerOptions`   | 指定できる項目はありません                                                                                                 |

- 上限を超える投稿は、**予約の時点で断ります。** 配信の直前になって初めて弾かれることはありません
- **Threads は本文の数え方を「500 文字」と「絵文字は UTF-8 のバイト数」までしか公開していません。**
  Torifune は分からない部分を**多めに数える側**に倒しています（絵文字以外は UTF-16 の長さで数え、`©` などの記号も絵文字として数え、URL も本文の文字として数えます）。
  そのため、**Threads なら受け付ける本文を、Torifune が予約の時点で断ることがあります**
- `https://` の無いドメイン（`example.com` など）はリンクとして数えません。Threads がそれをリンクと数える場合、
  リンクが 6 本以上になる投稿は配信のときに Threads に断られて `failed` になります（投稿はされません）
- 返信・引用・トピック・投票・位置情報・長文の添付・投稿の削除と編集には対応していません

### 画像は公開された URL で渡します

**Torifune は画像ファイルを預かりません。** 投稿に添える画像は、
**インターネットから誰でも取得できる 8MB 以下の JPEG か PNG 画像の `https://` の URL** として渡してください。

- 画像を取りに行くのは **Meta（Threads）のサーバ**です。Torifune のサーバは画像の URL へアクセスしません
- **画像の URL は Meta へ送られます**（URL に含まれるクエリ文字列も含めて）。署名付き URL を使う場合は、そのことを踏まえてください
- 社内ネットワークの中など、インターネットから取得できない URL では配信に失敗します

### 動画は扱いません

**動画の URL を渡しても、予約の時点では断れません。** Torifune もこの Plugin も、URL の先が画像か動画かを知る手段を持たないためです。
**動画の URL を指定した投稿は、配信のときに Threads が画像として処理できずに `failed` になります。**
動画を投稿したい場合は、Threads のアプリから投稿してください。

## 手動投稿

投稿ごとに **手動（`deliveryMode: 'manual'`）** を選べます。手動投稿では Threads API を呼びません（資格情報も使いません）。

1. 予約時刻を過ぎると、`/social` の **「手動投稿待ち」** に並びます
2. 「投稿画面を開く」を押すと、**本文の入った Threads の投稿画面**が別のウィンドウで開きます（ブラウザでログインしている Threads のアカウントで開きます）
3. 内容を確かめて、Threads の画面で投稿します
4. Torifune に戻り、**「投稿した」** を押します（投稿をやめたときは「取りやめ」）

- **手動投稿には画像を付けられません。** 画像を添える場合は、開いた投稿画面で添付してください
- 投稿画面に入る本文は、自動配信で送る本文と同じです（`link` も本文の末尾に改行して入ります）
- **手動投稿では、日本語の多い本文は短めにしてください。** 投稿画面の URL に本文を入れるため、URL が長くなりすぎる本文は予約の時点で断ります。
  目安として、**日本語だけの本文ならおよそ 223 文字まで**です（500 文字以内でも、手動投稿では登録できないことがあります。自動配信なら 500 文字まで送れます）

## 公開の前の処理待ち

Threads は、投稿の中身（container）を作ってから公開するまでに、サーバでの処理を待つ必要があります。
この Plugin は処理が終わったかを確かめながら、**最大でおよそ 15 秒**だけ待ちます。

- 間に合わなければ**公開せずに**配信を打ち切り、Torifune が時間をおいて送り直します。何度も間に合わなければ `failed` になります（投稿はされません）
- 公開されなかった中身は Threads 側で公開されずに残り、時間がたつと失効します

## 24 時間あたりの公開数の上限

Threads には **24 時間あたりに公開できる投稿数の上限**があります（値は Threads 側で変わるため、ここには書きません。カルーセルは 1 投稿と数えます）。
上限に達すると、その投稿は「呼び出し回数の制限」という理由で送り直され、それでも上限が続けば `failed` になります。時間をおいて新しい投稿として登録し直してください。

## うまくいかないとき

配信に失敗した投稿は `/social` の履歴に**理由**が残ります。よくあるものは次のとおりです。

| 履歴に出ること                                               | 見るところ                                                                                                                             |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 資格情報の形が正しくありません                               | ユーザー ID が数字だけか、トークンに空白・改行が混ざっていないかを確かめ、「資格情報を設定」から入れ直してください                     |
| アクセストークンが無効か期限切れです                         | 長期アクセストークンを発行し直し、`/social` のアカウントの行の「資格情報を設定」から入れ直してください                                 |
| 権限が足りません                                             | 長期アクセストークンに `threads_basic` と `threads_content_publish` の権限があるか確かめてください                                     |
| 画像を処理できませんでした・投稿の内容を受け付けませんでした | 画像の URL が、インターネットから取得できる 8MB 以下の JPEG か PNG の画像を指しているか確かめてください（動画の URL ではありませんか） |
| 処理が時間内に終わりませんでした                             | Torifune が時間をおいて自動で送り直します                                                                                              |
| 呼び出し回数の制限に達しました                               | Threads 側の制限です。Torifune が時間をおいて自動で送り直します                                                                        |
| 接続できませんでした・一時的に応答できませんでした           | しばらく待つと Torifune が自動で送り直します                                                                                           |
| 公開の結果が分かりません・応答を受け取れませんでした         | **二重投稿を避けるため再試行しません。** Threads 側で投稿されたかを確かめてから、必要なら予約し直してください                          |

失敗の理由に**資格情報そのものは書かれません。** Threads が返した自由な文言も載せません（HTTP の状態コードと、既知のエラーコードだけを載せます）。

## Threads API の宛先と版

この Plugin は **`https://graph.threads.net`** の Threads API の **`v1.0`** を使います（`threads-api.ts` の `THREADS_API_BASE_URL` と `THREADS_API_VERSION`）。

- 宛先と版は定数で、設定では変えられません（アクセストークンを任意のサーバへ送らせないためです）
- **Threads API の版が変わったら、この Plugin の更新が要ります**（Torifune 本体の更新は要りません）
- **この Plugin は実際の Threads ではまだ動かしていません。** Threads API の公開ドキュメントに沿って作り、偽の Threads API で確かめています。
  導入したら、まずテスト用の投稿で疎通を確かめてください

## この Plugin が持つもの・持たないもの

- **状態を 1 つも持ちません。** 設定もなく、投稿の状態も資格情報も自分では保存しません（延長したトークンは Torifune 本体が保存します）
- **アクセストークンは、Threads API への要求の URL（クエリ）と要求の本体（form）に載ります**（Threads API の公式の渡し方です）。
  この Plugin はその URL と本体をログにも失敗の理由にも出しませんが、Torifune の `fetch` に計測（OpenTelemetry・Sentry など）や送信側のプロキシを足して**外向きの要求の URL を記録するときは、クエリを伏せる設定にしてください**
- 投稿が成功すると、履歴の「投稿を見る」から Threads の投稿を開けます（Threads が投稿の URL を返さなかった場合は出ません）
- Torifune の Permission を 1 つも追加しません。データベースにも直接触りません
- **他の Plugin とコードを共有していません。** `sns-instagram` と似た作りですが、独立しています
