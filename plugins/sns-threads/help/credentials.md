## この手順書でそろうもの

Torifune の Threads のアカウントには、次の 3 つを入れます。

| Torifune の欄の名前  | 入れるもの                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Threads ユーザー ID  | **数字だけ**の ID（例：`17841400000000000`。例は見本で、実際の値とは違います）。`@` のユーザーネームではありません |
| 長期アクセストークン | この手順書で発行する、長い英数字の文字列。`threads_basic` と `threads_content_publish` の権限を持つもの            |
| トークンの有効期限   | 発行した日の 60日後の日時（例：`2026-11-23T00:00:00Z`）。分からなければ `unknown`                                  |

言葉の説明：

- **API**：プログラムから Threads に投稿するための窓口です。Torifune はこの窓口を通して投稿します
- **Meta for Developers**：Meta（Threads を運営する会社）の、開発者向けのサイトです。App を作ったりトークンを発行したりする画面があります
- **App（アプリ）**：Meta for Developers の中に作る「API を使う申請の単位」です。スマートフォンのアプリを作るわけではありません。Torifune 用に 1 つ作ります
- **アクセストークン**：「この App が、このアカウントとして投稿してよい」ことを表す、長い文字列の合い鍵です。パスワードと同じくらい大切に扱います
- **長期アクセストークン**：60日のあいだ使えるアクセストークンです。最初に出てくることがある「短期」のトークンは 1 時間で使えなくなります。Torifune に入れるのは長期のほうです
- **権限**：トークンで何をしてよいかの範囲です。Torifune には `threads_basic`（基本の読み取り）と `threads_content_publish`（投稿）の 2 つが要ります
- **テスター**：審査前の App を試してよい人です。自分の Threads アカウントを App のテスターにすると、そのアカウントのトークンを発行できます
- **Threads ユーザー ID**：API の中で使う、アカウントの番号です。画面に出る `@` の名前（ユーザーネーム）とは別のものです

## 始める前に用意するもの

- **Threads のアカウント**と、そのログイン用のパスワード（手順 5 と手順 6 で Threads にログインするときだけ使います。Torifune には入れません）
- **Meta for Developers にログインするためのアカウント**。公式の説明（開発者の登録の頁）は、Facebook のアカウントでログインしてから登録すると書いています
- **パソコンのブラウザ**をおすすめします。Meta for Developers の画面は横に広く、スマートフォンでは項目が隠れがちです。また、値を写して Torifune に貼る作業は、同じパソコンで 2 つのタブを並べると間違いが少なくなります
- Torifune で `/social` を開けて、アカウントを追加・編集できる利用者であること（「SNSアカウントを追加」や「資格情報を設定」のボタンが見えない場合は、Torifune の管理者に頼んでください）
- Torifune の管理者が、`/plugins` で「Threads配信」を**有効**にしていること（有効でない間は、Torifune に正しい欄が出ません。手順 9 を見てください）
- 発行したトークンを**一時的に**置く場所。いちばん安全なのは、メモに置かずに Meta の画面から Torifune の欄へそのまま貼ることです。どうしてもメモするなら、自分だけが見られる場所に置き、Torifune に入れ終えたら消します

## 全体の流れ

1. Meta for Developers に開発者として登録し、Threads の使い道を選んで App を作る
2. App に投稿の権限（`threads_content_publish`）を加える
3. 自分の Threads アカウントを App のテスターに招待し、Threads 側で承認する
4. App の画面で、自分のアカウントの長期アクセストークンを発行する
5. 数字だけのユーザー ID を確かめ、有効期限を決める
6. Torifune の `/social` で 3 つの欄に入れる

## 手順 1：Meta for Developers に開発者として登録する

すでに Meta for Developers で App を作ったことがある人は、手順 2 へ進みます。

- **開く画面**：ブラウザで Meta for Developers のトップの頁を開き、Facebook のアカウントでログインします
- **押すもの**：「Get Started（はじめる）」を押します。「Next（次へ）」で Meta の開発者向けの規約（Platform Terms と Developer Policies）に同意します
- **入れるもの**：確認のコードを受け取る電話番号とメールアドレスを入れ、届いたコードで確かめます。最後に自分の仕事に近いもの（occupation）を選びます
- **確かめること**：登録が終わり、App の一覧（「My Apps」（マイアプリ）など）を開けるようになること

公式の説明（開発者の登録の頁）で確かめたのは、「Get Started」→ 規約への同意 → 電話番号とメールアドレスの確認 → 仕事の選択、の順までです。登録が終わった後の画面の名前は確かめられませんでした。

## 手順 2：App を作る

- **開く画面**：Meta for Developers の App の一覧（「My Apps」（マイアプリ））を開きます
- **押すもの**：「Create App（アプリを作成）」を押します（公式の説明は、App を作る画面から始める、とだけ書いています。このボタンの名前は確かめられませんでした）
- **入れるもの**（App details：App の詳細）：App の名前（例：`Torifune`）と連絡先のメールアドレスを入れて「Next（次へ）」を押します
- **選ぶもの**（Use cases：使い道）：一覧から「**Access the Threads API**（Threads API にアクセス）」を選んで「Next」を押します
- **選ぶもの**（Business：ビジネス）：ビジネスポートフォリオ（会社の情報）をつなぐかを聞かれます。つなぐものが無ければ「I don't want to connect a business portfolio yet.（まだつながない）」を選んで「Next」を押します
- **確かめること**（Requirements：必要事項 → Overview：概要）：内容を見て「Next」、最後に「Go to dashboard（ダッシュボードへ）」を押します。App の画面（ダッシュボード）が開けば完了です

公式の説明は「App を作ると App ID と App Secret が 2 組できる。Threads API には Threads 用の App ID とその App Secret を使う」と書いています。**App Secret（App の秘密の鍵）は、この手順書の本道では使いません。Torifune にも入れません。**

## 手順 3：投稿の権限を加える

- **開く画面**：App のダッシュボードの左のメニューで「Use cases（ユースケース）」を押します（鉛筆の形のアイコンのこともあります）
- **押すもの**：「Access the Threads API」を押します（「Customize（カスタマイズ）」のボタンを押す形のこともあります）。その使い道で使える権限の一覧（必須のものと、選べるもの）が出ます
- **確かめること**：`threads_basic` が一覧にあり、「Required（必須）」になっていること（外せません）
- **押すもの**：`threads_content_publish` の行の右にある「**Add（追加）**」を押します
- **確かめること**：`threads_content_publish` が追加された状態になっていること

**権限を加えてからトークンを発行します（手順 6）。** 先にトークンを発行してしまったときは、権限を加えた後で発行し直します。権限の無いトークンでは、配信が「権限が足りません」で失敗します。

ほかの権限（返信・分析など）は Torifune では使いません。加えなくて構いません。

## 手順 4：自分の Threads アカウントをテスターに招待する

- **開く画面**：手順 3 と同じ「Access the Threads API」の画面で、左のメニューの「**Settings（設定）**」を開きます
- **押すもの**：「**Add or Remove Threads Test Users**（Threads のテストユーザーを追加・削除）」を押します。ダッシュボードの「App roles（アプリの役割）」→「Roles（役割）」の画面に移ります
- **押すもの**：「**Add People**（人を追加）」を押し、役割に「**Threads Tester**（Threads のテスター）」を選び、投稿に使う Threads アカウントのユーザーネームを入れて招待します
- **確かめること**：「Roles」の画面に、招待したアカウントが出ること

招待するときに入れる値（ユーザーネームなど）と、承認されるまでの表示（「承認待ち」「Pending」など）は、公式の説明で確かめられませんでした。

役割の一覧には「Testers」もありますが、選ぶのは「**Threads Tester**」のほうです。

## 手順 5：Threads 側で招待を承認する

招待は、Threads の側で承認するまで有効になりません。

- **開く画面**：投稿に使う Threads アカウントで、Threads のウェブサイト（パソコンのブラウザ）か、スマートフォンの Threads のアプリにログインします
- **押すもの**：Threads の「設定」→「アカウント」（英語では「Account Settings」）の中の「**Website permissions**（ウェブサイトのアクセス許可）」を開きます
- **押すもの**：届いている招待（手順 2 で付けた App の名前）を承認します
- **確かめること**：Meta for Developers の「Roles」の画面で、そのアカウントが承認待ちでなくなっていること

公式の説明で確かめられたのは「Threads のウェブサイトかアプリの、Account Settings の中の Website permissions で承認する」ところまでです。**その中のタブやボタンの名前（招待の一覧・承認のボタン）と、日本語で表示したときの名前は、公式の説明で確かめられませんでした。** 見つからないときは、表示の言語を英語にして「Website permissions」を探してください。

## 手順 6：長期アクセストークンを発行する

ここでは、コマンドを使わずに App の画面だけで発行する道を説明します。この道が使えないときは、後ろの「上級者向け：短期のトークンを長期のトークンに交換する」を見てください。

**この手順の画面（User Token Generator）は、2026-09-24 の時点で Meta の公式の説明に載っておらず、公式の説明で確かめられませんでした。** 画面の名前や、発行されるトークンの種類が違うことがあります。下の「確かめること」を必ず見てください。

- **開く画面**：手順 4 と同じ「**Settings**」の画面を、いちばん下までスクロールします
- **探すもの**：「**User Token Generator**（ユーザートークンの生成）」の欄を探します。手順 5 で承認したテスターのアカウントが並んでいます
- **押すもの**：投稿に使うアカウントの行の「**Generate Access Token**（アクセストークンを生成）」を押します
- **押すもの**：開いた別の窓で、Threads へのログインと、App に許可を与える確認を求められたら、その Threads アカウントで進めて許可します（許可する内容に、手順 3 の 2 つの権限が含まれていることを確かめます）
- **写すもの**：表示されたアクセストークンを写します。**写し終えるまで窓を閉じないでください。** 同じトークンがもう一度表示されるかは確かめられませんでした。閉じてしまったら、もう一度「Generate Access Token」を押して発行し直します
- **確かめること**：写した文字列の前後に空白や改行が入っていないこと。途中で切れていないこと（とても長い文字列です）

**発行されたトークンが長期（60日）か短期（1 時間）かは、公式の説明で確かめられませんでした。** 画面に有効期限や「long-lived（長期）」の表示があれば、それに従います。分からないときは、手順 8 で有効期限を `unknown` にし、「うまく入ったか確かめる」の 3 のやり方で確かめます。短期のトークンだった場合は、1 時間ほどで配信が「アクセストークンが無効か期限切れです」で失敗するようになります。そのときは上級者向けの節で長期のトークンに交換します。

この道では App Secret を使いません。**画面のどこかで App Secret の入力を求められたら、それは Torifune に入れる値ではありません。**

## 手順 7：数字だけのユーザー ID を確かめる

「Threads ユーザー ID」は**数字だけ**の文字列です。Threads の画面に出る `@` の名前（ユーザーネーム）ではありません。公式の説明（Threads Profiles の頁）は、自分のプロフィールを問い合わせたときに返る `id` を「Threads ユーザー ID」と書いています。

次のどれかで確かめます。

- **User Token Generator の画面に数字の ID が出ている場合**：その数字を写します（出るかどうかは確かめられませんでした）
- **Meta の「Graph API Explorer」（グラフ API エクスプローラ）を使う場合**：公式の説明（Threads Profiles の頁）は「テストの間は Graph API Explorer でトークンを作り、App に権限を与えられる」と書いています。Graph API Explorer を開き、右上の「Meta App」（Meta アプリ）で手順 2 の App を選び、Threads 用の表示に切り替えてから `threads_basic` の権限でトークンを生成し、問い合わせの欄に `me?fields=id,username` と入れて送ります。返ってきた結果のうち、`username` が自分のユーザーネームであることを確かめ、`id` の数字を写します。**Graph API Explorer の開き方、Threads 用の表示への切り替え、Threads のときのボタンの名前は、公式の説明で確かめられませんでした**（公式の説明で確かめられたのは、右上で App を選ぶこと、生成したトークンが右上に出ることまでです）
- **上級者向けの節の交換をした場合**：短期のトークンを受け取るときの応答に `user_id` として数字の ID が入っています

**確かめること**：写した値が数字だけでできていること（`@` や英字が混ざっていないこと）。

Graph API Explorer で生成したトークンは、ユーザー ID を確かめるためだけのものです。Torifune には入れません（手順 6 で発行したものを入れます）。

## 手順 8：有効期限を決める

「トークンの有効期限」の欄には、次のどちらかを入れます。

- **期限が分かる場合**：長期アクセストークンを発行した日の **60日後**の日付を、`YYYY-MM-DDT00:00:00Z` の形で書きます。例：9 月 24 日に発行したなら `2026-11-23T00:00:00Z`（年・月・日は `-` でつなぎ、最後の `T00:00:00Z` はそのまま付けます）
- **分からない場合**：`unknown` と入れます（半角の英小文字）。手順 6 でトークンの種類が分からなかったときも `unknown` にします

`unknown` を入れても配信はできます。Torifune は、次に配信が成功したときにトークンを延長し、正しい期限に書き換えます（「期限と更新」を見てください）。

## 手順 9：Torifune に入れる

**先に Torifune の管理者が `/plugins` で「Threads配信」を有効にしておきます。** Plugin を無効にしている間は、Torifune の画面に下の 3 つの欄が出ず、汎用の欄が 1 つだけ出ます。そこへ値を入れても配信には使えません。**有効にしてから入れてください。**

Torifune で `/social` を開きます。これから新しくアカウントを作るか、すでにあるアカウントに入れるかで、使う画面が違います。

### 新しくアカウントを作る場合（「SNSアカウントを追加」）

1. `/social` の「+ アカウントを追加」を押します。「SNSアカウントを追加」の画面が開きます
2. 「サービス」で「Threads」を選びます
3. 「表示名」に、Torifune の中で見分けるための名前を入れます（例：`会社の公式`）
4. 「ハンドル」に、画面の一覧で見分けるための名前を入れます（例：`@example`。この欄は表示用で、配信には使いません）
5. 下の 3 つの欄に、手順 6〜手順 8 で用意した値を入れます（下の表）
6. 「追加」を押します

### すでにあるアカウントに入れる場合（「資格情報を設定」）

1. `/social` のアカウントの一覧で、Threads のアカウントの行の「資格情報を設定」を押します
2. 開いた画面の 3 つの欄に、手順 6〜手順 8 で用意した値を入れます（下の表）
3. 「保存」を押します

### 欄と値の対応

| Torifune の欄の名前  | 入れる値                                               | 用意したところ |
| -------------------- | ------------------------------------------------------ | -------------- |
| Threads ユーザー ID  | 数字だけの ID                                          | 手順 7         |
| 長期アクセストークン | 発行したアクセストークン（前後に空白や改行を入れない） | 手順 6         |
| トークンの有効期限   | `2026-11-23T00:00:00Z` の形の日時か `unknown`          | 手順 8         |

- 保存した値は暗号化され、**画面に再表示されません**
- 入れ直すときは、**3 つの欄をすべて**入れ直します（一部の欄だけを変えることはできません）
- どちらの画面にも、この手順書を開く「手順書：」のボタンがあります。新しいタブで開くので、入力中の内容は消えません

入れ終えたら、手元にメモした値があれば消します。

## うまく入ったか確かめる

1. `/social` の「+ 投稿を作成」から、この Threads のアカウントを選んだテスト用の投稿（テキストだけで構いません）を作ります。「予約日時」を数分後にして保存します（「配信方法」の欄が出ていれば「自動」を選びます）
2. 予約時刻を過ぎたら、`/social` の投稿の一覧で状態が「配信済み」になっているかを見ます。「配信履歴」のボタンから、配信の結果と理由も見られます。Threads の自分のプロフィールに、その投稿が出ていることも確かめます
3. **手順 6 でトークンの種類（長期か短期か）が分からなかった場合**は、トークンを発行してから **1 時間以上たってから**、もう 1 件テスト用の投稿を予約します。これが「配信済み」になれば、1 時間で切れる短期のトークンではありません。「アクセストークンが無効か期限切れです」で失敗したら、短期のトークンだった可能性があります（上級者向けの節で交換します）

テスト用の投稿は、Threads 側で削除して構いません（Torifune から削除しても Threads の投稿は消えません）。

「失敗」になった場合は、履歴に出た理由を次の「よくある間違い」で探します。

## よくある間違い

| 症状（配信履歴に出ること・画面で起きること）    | 原因                                                                           | 直し方                                                                                                                          |
| ----------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| Threads の資格情報の形が正しくありません        | 「Threads ユーザー ID」に `@` のユーザーネームを入れた                         | 手順 7 で数字だけの ID を確かめ、「資格情報を設定」で 3 つとも入れ直します                                                      |
| Threads の資格情報の形が正しくありません        | トークンを写すときに前後に空白や改行が入った                                   | 空白や改行を入れずに、「資格情報を設定」で入れ直します                                                                          |
| Threads のアクセストークンが無効か期限切れです  | 1 時間で切れる短期のトークンを入れた                                           | 上級者向けの節で長期のトークンに交換するか、手順 6 で発行し直し、「資格情報を設定」で入れ直します                               |
| Threads のアクセストークンが無効か期限切れです  | 長いあいだ配信せず、60日の期限が過ぎた                                         | 手順 6 で発行し直し、「資格情報を設定」で入れ直します                                                                           |
| Threads のアクセストークンが無効か期限切れです  | トークンを途中までしか写さなかった・App ID など別の値を入れた                  | 手順 6 で発行し直し、全体を写して入れ直します                                                                                   |
| Threads のアクセストークンが無効か期限切れです  | Threads の「Website permissions」で App の許可を取り消した・テスターから外した | 手順 4・手順 5 をやり直し、手順 6 で発行し直します                                                                              |
| Threads の権限が足りません                      | `threads_content_publish` を加える前にトークンを発行した                       | 手順 3 で権限を加えてから、手順 6 で発行し直します                                                                              |
| User Token Generator に自分のアカウントが出ない | Threads 側で招待を承認していない                                               | 手順 5 で承認します                                                                                                             |
| 3 つの欄が出ず、欄が 1 つだけ出る               | Torifune の「Threads配信」が有効になっていない                                 | 管理者に `/plugins` で有効にしてもらい、画面を開き直してから入れます                                                            |
| 期限の欄に書いた日付が正しく使われない          | 日付の形が違う・発行日から 61 日より先の日付を書いた                           | 失敗にはなりません（読めない値は `unknown` として扱われ、次の成功した配信で正しい期限に書き換わります）。気になれば入れ直します |

別のアカウントの数字の ID を入れた場合も、配信は失敗します（理由の文言は Threads の応答によって変わります）。ユーザー ID とトークンは、**同じ Threads アカウントのもの**をそろえてください。

## 期限と更新

- 長期アクセストークンの有効期限は **60日**です（公式の説明の「Long-Lived Access Tokens」の頁）
- **Torifune は、配信が成功したときにトークンを自動で延長します。** 配信が成功した時点で、期限の残りが **30 日を切っていれば**（または期限が `unknown` なら）延長し、新しいトークンと期限を Torifune が保存し直します。利用者が何かをする必要はありません
- **延長できるのは、発行から 24 時間以上たったトークンだけです**（公式の説明：延長できるのは「発行から 24 時間以上たち、まだ失効していない」長期トークン）。期限に `unknown` を入れて発行の直後に配信すると、最初の延長は失敗することがあります。**それでも投稿そのものは成功します。** 延長は、次に成功した配信でもう一度試みられます
- **30 日以上配信しない期間があると、トークンはそのまま失効しえます。失効したトークンは延長できません。** 失効すると、次の配信が「アクセストークンが無効か期限切れです」で失敗します
- 失効したら、手順 6 で長期アクセストークンを発行し直し、`/social` のアカウントの行の「資格情報を設定」から **3 つとも**入れ直します
- **アプリへの許可の期間（90 日）**：公式の説明（「Get Started」の頁の「Authorization」）は、Threads のアカウントが App に与えた許可は **90 日**で切れると書いています。
  **公開のプロフィール**なら、トークンを延長すると許可も 90 日延びます（Torifune は配信が成功したときに延長するので、ふだんは何もしなくてかまいません）。
  **非公開のプロフィール**では、トークンを延長しても許可は延びません。90 日で切れたら、手順 5・手順 6 のとおりに App へ**許可し直し**（テスターの承認とトークンの発行をやり直し）、「資格情報を設定」から 3 つとも入れ直してください

## 安全のために

- 値は**この画面（Torifune）以外に貼らないでください。** チャット・メール・共有のメモ・AI のチャット・「トークンを確かめる」ような第三者のサイトに貼らないでください
- **Threads にログインするパスワードは Torifune に入れないでください**（入れる欄はありません。求められたら手順を誤っています）
- **App Secret（App の秘密の鍵）は Torifune に入れないでください。** Torifune は App Secret を使いません（トークンの延長にも要りません）。App Secret を知っている人は、あなたの App になりすませます。人に見せないでください
- トークンは発行した画面で一度しか表示されないことがあります。写すまで画面を閉じないでください。写した値は、Torifune に入れ終えたら手元のメモから消してください
- 値をコマンドラインに直書きしないでください（シェルの履歴やプロセスの一覧に残ります）。この手順書の本道はコマンドを使いません
- 値が漏れたと思ったら、Threads の「Website permissions」でその App の許可を取り消し（App Secret が漏れたときは Meta for Developers で App Secret を作り直し）、手順 5・手順 6 から発行し直してから、Torifune で「資格情報を設定」から入れ直してください
- Torifune に保存した値は暗号化され、画面に再表示されません。**入れ直すときはすべての欄を入れ直します**（一部だけは変えられません）
- トークンを使う問い合わせ（上級者向けの節の交換や、自分のプロフィールの問い合わせ）では、**App Secret やトークンが URL のクエリ（`?` の後ろ）に載ります。** そうした URL をブラウザのアドレス欄に貼ると、ブラウザの履歴に残ります。プロキシや計測の仕組みを通すときは、URL を記録させないでください
- 画面の写真（スクリーンショット）を人に送るときは、トークン・App Secret・ユーザー ID が写っていないかを確かめてください
- **入れ終えたら、クリップボードの履歴からも消してください。** Windows の「クリップボードの履歴」、スマートフォンの入力の履歴、クリップボードを同期するアプリに、写した値が残ることがあります

## 画面が違うとき

Meta for Developers と Threads の画面の名前や並びは変わることがあります。この手順書のとおりに見つからないときは、次を試してください。

- 表示の言語を英語にして、この手順書の英語の名前（「Create App」「Access the Threads API」「Customize」「Permissions」「Settings」「Add or Remove Threads Test Users」「Add People」「Threads Tester」「Website permissions」「User Token Generator」「Generate Access Token」）で探します
- 公式の説明のうち、App の使い道の設定（権限・Settings・テスター）は「Threads Use Case」（Threads の使い道）の頁、テスターの招待と承認は「Get Started」の頁、ユーザー ID は「Threads Profiles」の頁に書かれています。どれも Threads API の説明の目次にあります
- 「User Token Generator」が見つからないときは、下の「上級者向け：短期のトークンを長期のトークンに交換する」の道を使うか、Torifune の管理者に相談してください
- それでも見つからなければ、次の「公式の説明」を開いてください

## 上級者向け：短期のトークンを長期のトークンに交換する

手順 6 の画面が使えないとき、または発行されたトークンが短期（1 時間）だったときの道です。**App Secret を使い、秘密の値が URL に載ります。** 仕組みが分からない場合は、無理に進めず Torifune の管理者に相談してください。

この節は、公式の説明の「Get Access Tokens」と「Long-Lived Access Tokens」の頁のとおりに進めます。**要求を送る先（宛先）と引数の書き方は、この手順書には書きません。必ず公式の説明の最新の版を見てください。**

1. **受け取り先の URL を登録する**：App の「Customize」→「Settings」の「Client OAuth Settings」に、認可の結果を受け取る URL を登録して「Save」を押します。**受け取り先の URL は、自分が管理するサーバの `https://` の URL だけにしてください**（他人のサービスの URL にすると、認可コードがそこへ渡ります）。同じ画面に「Threads app ID」と「Threads app secret」が出ています（使うのは Threads 用の組です）
2. **認可の画面を開く**：公式の説明の認可の画面（Authorization Window）を、App ID・受け取り先の URL・権限（`threads_basic,threads_content_publish`）を付けてブラウザで開き、投稿に使う Threads アカウントで許可します
3. **認可コードを受け取る**：受け取り先の URL に `code` が付いて戻ります。公式の説明のとおり、末尾の `#_` は除きます。**認可コードは 1 時間だけ・1 回だけ使えます**
4. **短期のトークンに換える**：公式の説明のとおりに、認可コード・App ID・App Secret などを送ります。応答に短期のアクセストークン（1 時間有効）と、**数字だけのユーザー ID（`user_id`）** が入っています
5. **長期のトークンに交換する**：公式の説明のとおりに、`grant_type` を `th_exchange_token` にし、App Secret と短期のトークンを送ります。応答のアクセストークンが長期アクセストークン（60日）です。**期限の切れた短期のトークンは交換できません**（1 時間以内に済ませます）
6. 手順 8・手順 9 へ進みます（期限は交換した日の 60日後か `unknown`）

この道の注意：

- **App Secret やトークンを含む URL を、ブラウザのアドレス欄に貼らないでください。** ブラウザの履歴・同期・拡張機能から漏れることがあります
- **App Secret と短期のトークンは、交換の要求の URL にクエリとして載ります。** プロキシ・計測・ログの仕組みを通すときは、URL を記録させないでください
- 公式の説明は「長期のトークンを求める要求には App Secret が含まれるので、サーバ側のコードだけで行い、利用者の端末で動くコード（ブラウザの中など）では行わない」と書いています
- 値をコマンドラインに直書きしないでください（シェルの履歴やプロセスの一覧に残ります）。手元で送るときは、値をファイルか標準入力で渡し、終わったらファイルを消してください
- 受け取り先の URL と認可コードはブラウザの履歴に残ります。認可コードは一度使うと無効になりますが、使い終えたら履歴から消しておくと安心です
- App Secret は交換にだけ使います。**Torifune には入れません。** Torifune に入れるのは、手順 9 の 3 つの値だけです
