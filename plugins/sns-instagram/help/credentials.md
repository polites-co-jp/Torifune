## この手順書でそろうもの

Torifune の Instagram のアカウントには、次の 3 つを入れます。

| Torifune の欄の名前   | 入れるもの                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Instagram ユーザー ID | 投稿に使う Instagram のプロアカウントの、**数字だけ**の ID（例：`17841400000000000`。例は見本です）。**分からなければ `auto`** |
| 長期アクセストークン  | この手順書で発行する、長い英数字の文字列（**60日**で失効します）                                                               |
| トークンの有効期限    | トークンが切れる日時（例：`2026-11-23T00:00:00Z`）。**分からなければ `unknown` と入れてかまいません**                          |

**「Instagram ユーザー ID」は、`@` で始まるユーザーネーム（例：`@example_shop`）ではありません。**
数字だけの ID です。分からなければ `auto` と入れれば、Torifune が次の配信のときに確かめて保存し直します（手順 8）。

**App Secret（App の秘密の鍵）は Torifune に入れません。** Torifune に App Secret を入れる欄はありません。

言葉の説明：

- **プロアカウント**：Instagram の「ビジネス」または「クリエイター」の種類のアカウントです。個人用のアカウント（個人アカウント）からいつでも切り替えられます。API から投稿できるのはプロアカウントだけです
- **API**：アプリ（ここでは Torifune）が Instagram に「投稿して」と頼むための窓口です
- **Meta for Developers**：Instagram や Facebook を運営する Meta の、開発者向けのサイトです。Instagram の API を使うには、ここで「App」を作ります
- **App（アプリ）**：Meta for Developers に登録する「Instagram を使う道具」の名札です。Torifune のために 1 つ作ります。スマートフォンのアプリを作るわけではありません
- **アクセストークン**：Instagram があなたの代わりに投稿してよいと認めた「通行証」です。パスワードと同じくらい大切に扱います。「長期アクセストークン」は **60日** 使えるものです
- **テスター**：開発中の App を試してよい人（アカウント）です。自分のアカウントを自分の App のテスターにすると、審査（App Review）を受けずに自分のアカウントへ投稿できます
- **権限**：App が Instagram で何をしてよいかの範囲です。Torifune には `instagram_business_basic`（アカウントの基本の情報を読む）と `instagram_business_content_publish`（投稿する）の 2 つが要ります

## 始める前に用意するもの

- **Instagram のプロアカウント（ビジネスまたはクリエイター）**。個人アカウントの場合は、手順 1 で切り替えます。プロアカウントは公開のアカウントになります
- **Facebook のアカウント**。Meta for Developers に開発者として登録するときに、Facebook にログインしている必要があります（手順 2）。投稿に使う Instagram のアカウントと同じ人のものでなくてもかまいません
- **パソコンのブラウザ**をおすすめします。Meta for Developers の App の画面は、パソコンのブラウザで使う作りです。値を写して Torifune に貼る作業も、同じパソコンで 2 つのタブを並べると間違いが少なくなります。途中で Instagram にログインする小さな窓（ポップアップ）が開くので、ブラウザがポップアップを止めたら許可してください
- Torifune の `/plugins` で **「Instagram配信」の Plugin が有効になっていること**。無効な間は、「資格情報を設定」の画面に 3 つの欄ではなく汎用の欄が 1 つだけ出ます。先に Torifune の管理者に有効にしてもらってください
- Torifune で `/social` を開けて、アカウントを追加・編集できる利用者であること（「SNSアカウントを追加」や「資格情報を設定」のボタンが見えない場合は、Torifune の管理者に頼んでください）
- 発行したトークンを**一時的に**置く場所。いちばん安全なのは、メモに置かずに Meta の画面から Torifune の欄へそのまま貼ることです。どうしてもメモに置くなら、自分だけが開けるパソコンの中のメモにし、入れ終えたら消してください

## 全体の流れ

1. Instagram のアカウントをプロアカウントにする（個人アカウントの場合だけ）
2. Meta for Developers に開発者として登録し、Instagram の API を使う App を作る
3. App に投稿の権限を加え、投稿に使う Instagram のアカウントを App に加える
4. App の画面で長期アクセストークンを生成して写す
5. ユーザー ID の欄に入れる値（数字だけの ID、分からなければ `auto`）と、有効期限を決める
6. Torifune の `/social` で 3 つの欄に入れる

## 手順 1：Instagram をプロアカウントにする

すでにビジネスまたはクリエイターのアカウントなら、この手順は飛ばします。

- **開く画面**：パソコンのブラウザで `https://www.instagram.com` を開き、投稿に使うアカウントでログインします
- **押すもの**：左のメニューの「その他」（英語では「More」）→「設定」（「Settings」）→「プロフェッショナル向け」（「For professionals」）の中の「アカウントの種類とツール」（「Account type and tools」）→「プロアカウントに切り替える」（「Switch to professional account」）を押します
- **選ぶもの**：「クリエイター」（Creator）か「ビジネス」（Business）を選び、画面の案内に沿って進みます。どちらでも Torifune から投稿できます
- **確かめること**：設定の「アカウントの種類とツール」に、個人アカウントに戻す項目や、プロアカウントの種類を変える項目が出ていること

注意：

- 非公開の個人アカウントを切り替えると、**アカウントが公開になり、届いていたフォローのリクエストはすべて承認されます**
- この手順の画面の名前は、Instagram の公式のヘルプの検索結果の抜粋（英語）で確かめました。ヘルプの本文そのものと、日本語の表示の名前（上の「」の日本語）は、公式の説明で確かめられませんでした。見つからないときは、設定の中で「プロ」「アカウントの種類」の文字を探してください

## 手順 2：Meta for Developers に開発者として登録する

すでに Meta for Developers に登録していれば、この手順は飛ばします。

- **開く画面**：ブラウザで Facebook にログインした状態のまま、`https://developers.facebook.com` を開きます
- **押すもの**：「Get Started」（はじめる）を押します
- **押すもの**：「Next」（次へ）を押して、Meta の開発者向けの規約（Platform Terms と Developer Policies）に同意します
- **入れるもの**：電話番号とメールアドレスを入れ、届いた確認のコードを入れます
- **選ぶもの**：自分の仕事にいちばん近いもの（occupation）を選びます
- **確かめること**：登録が終わると、`https://developers.facebook.com/apps` で App の一覧（App Dashboard）が開けるようになること

## 手順 3：App を作る

- **開く画面**：`https://developers.facebook.com/apps` を開きます（App Dashboard。App の一覧の画面です）
- **押すもの**：右上の「Create App」（App を作成）を押します
- **入れるもの**：「App details」（App の詳細）で、App の名前（例：`Torifune 投稿`）と連絡先のメールアドレスを入れて「Next」を押します。App の名前は自分が見分けるためのもので、Torifune には入れません
- **選ぶもの**：「Use cases」（使い道）で、**「Manage messaging and content on Instagram」（Instagram のメッセージとコンテンツを管理）**を選んで「Next」を押します
  - 一覧に無いときは「Other」（その他）を選んで「Next」→ App の種類で「**Business**」（ビジネス）を選んで「Next」→ 名前とメールアドレスを入れて「Next」→ 開いた画面で「**Instagram**」の「Set up」（設定）を押します
- **選ぶもの**：「Business」（ビジネスポートフォリオ）では、会社で Meta のビジネスポートフォリオを使っていなければ「**I don't want to connect a business portfolio yet.**」（まだつながない）を選んで「Next」を押します。自分のアカウントへ投稿するだけなら、あとからつなぐ必要はありません
- **押すもの**：「Requirements」（要件）で「Next」、「Overview」（確認）で内容を確かめて「**Go to dashboard**」（ダッシュボードへ）を押します
- **確かめること**：新しい App の画面（Dashboard）が開き、左のメニューに App の名前が出ていること

知っておくこと：

- 自分の（または自分が管理する）アカウントへ投稿するだけなら、App の審査（App Review）も、App の公開（Publish）も要りません。何もしなければ「Standard Access」（標準のアクセス）のままで使えます
- 使い道（Use case）は、一度加えると外せません。間違えたときは App を作り直すのが早道です

## 手順 4：投稿の権限を加える

- **開く画面**：App の画面の左のメニューの「Dashboard」を押し、手順 3 で選んだ使い道（Instagram のもの）の「**Customize**」（カスタマイズ）を押します。左のメニューに「**API setup with Instagram login**」（Instagram ログインによる API の設定）が出ていれば、それを押します
- **押すもの**：「**Add all required permissions**」（必要な権限をすべて追加）を押します。`instagram_business_basic` と `instagram_business_manage_messages` が加わります（後者はメッセージの権限で、Torifune は使いませんが、この使い道では外せません）
- **押すもの**：左のメニューの「**Permissions and features**」（権限と機能）を押し、一覧から `instagram_business_content_publish` を探して加えます
- **確かめること**：加えた権限の一覧に、`instagram_business_basic` と `instagram_business_content_publish` の両方があること

`instagram_business_content_publish` を加えるボタンの正確な名前は、公式の説明で確かめられませんでした（公式の説明は「使い道の設定で、要る権限を加える」とだけ書いています）。

**権限は、手順 7 でトークンを生成する前に加えてください。** 後から権限を加えた場合に、生成済みのトークンへ権限が広がるかは、公式の説明で確かめられませんでした。後から加えたときは、手順 7 からトークンを生成し直すのが確実です。

## 手順 5：投稿に使う Instagram アカウントを App に加える

- **開く画面**：左のメニューの「Instagram」→「**API setup with Instagram login**」（画面によっては「API setup with Instagram business login」）を開きます
- **確かめること**：画面に App の名前、「Instagram app ID」（Instagram の App の番号）、「Instagram app secret」（App Secret）が表示されます。**どちらも Torifune には入れません**（「Instagram app ID」は App の番号で、ユーザー ID ではありません）
- **押すもの**：「**Generate access tokens**」（アクセストークンの生成）の欄の「**Add account**」（アカウントを追加）を押します
- **押すもの**：「Continue」（続ける）を押し、開いた小さな窓で、**投稿に使う Instagram のプロアカウント**でログインします（別のアカウントでログインしていたら、ログアウトしてから入り直します）
- **押すもの**：「Save」（保存）→「Got it」（了解）を押して App の画面に戻ります
- **確かめること**：「Generate access tokens」の欄に、そのアカウントのユーザーネームが並んでいること

加えるアカウントは公開のアカウントである必要があります（プロアカウントは公開です）。加えたアカウントは、左のメニューの「App roles」（App の役割）→「Roles」（役割）からも見たり外したりできます。

App を Meta のビジネスポートフォリオにつないでいる場合、役割の管理はビジネスマネージャ（Business Manager）で行うことがあります（公式の説明による）。

## 手順 6：テスターへの招待を承認する

**この手順は公式文書で確かめられませんでした。** 公式の説明は、手順 5 でアカウントを加えることと、「App roles」→「Roles」でアカウントを加えたり外したりできることだけを書いており、Instagram 側で招待を承認する場所を書いていません。

次は、Meta の開発者向けのコミュニティ（利用者どうしの掲示板。公式の説明ではありません）で案内されている場所です。手順 5 のアカウントの横に「招待中」「Pending」のような表示が出ている場合や、手順 7 でトークンを生成できない場合に試してください。

- **開く画面**：パソコンのブラウザで `https://www.instagram.com` を開き、**手順 5 で加えたアカウント**でログインします
- **押すもの**：自分のプロフィール →「プロフィールを編集」→「アプリとウェブサイト」（英語では「Apps and websites」。以前の表示では「Authorized Applications」）を開き、「**テスターへの招待**」（「Tester Invites」）のタブを押します。同じ掲示板では、ログインした状態で `https://www.instagram.com/accounts/manage_access/` を開く近道も案内されています
- **押すもの**：自分の App の名前の招待の「承認」（「Accept」）を押します。日本語の表示の名前は確かめられませんでした
- **確かめること**：Meta for Developers の App の画面に戻り、ページを読み込み直すと、そのアカウントが招待中の表示でなくなっていること

同じ掲示板では、「App roles」→「Roles」で人を加えるときの役割は、ただの「Tester」ではなく「**Instagram Tester**」を選ぶ、とも案内されています（これも公式の説明では確かめられませんでした）。

## 手順 7：アクセストークンを生成して写す

- **開く画面**：左のメニューの「Instagram」→「API setup with Instagram login」の「Generate access tokens」の欄を開きます
- **押すもの**：投稿に使うアカウントの横の「**Generate token**」（トークンを生成）を押し、開いた小さな窓で、そのアカウントで Instagram にログインします。許可を求められたら、許可します
- **確かめること**：長い英数字の文字列（アクセストークン）が表示されること
- **写すもの**：表示された文字列を**全部**コピーします。コピーのボタンがあればそれを使います。前後に空白や改行が入らないように気をつけます

公式の説明は「**App の画面（App Dashboard）で生成したアクセストークンは長期のもので、60日有効**」と書いています。このため、この手順書のトークンは、そのまま「長期アクセストークン」の欄に入れられます。

**写すまで画面を閉じないでください。** 同じトークンを後から表示し直せるかは、公式の説明で確かめられませんでした。閉じてしまったら、もう一度「Generate token」を押して生成し直します。

**生成した日付を控えておいてください**（手順 9 で使います）。

## 手順 8：ユーザー ID の欄に入れる値を決める

「Instagram ユーザー ID」の欄には、プロアカウントの**数字だけ**の ID（公式の説明では `user_id` と呼ばれます）を入れます。
**分からなければ `auto` と入れてください**（半角の英字。前後に空白を入れない）。

- **`@` のユーザーネームではありません。** 例：`@example_shop` は入れられません
- 手順 5 で見た「Instagram app ID」（App の番号）でもありません

### `auto` と入れた場合（おすすめ）

`auto` と入れておくと、保存した後の最初の配信のときに、Torifune が手順 7 のアクセストークンを使って Instagram に「このトークンの持ち主の ID」を問い合わせ、数字の ID を確かめて使います。
その配信が成功すると、Torifune は確かめた数字の ID を保存し直します。次の配信からは問い合わせをしません。

- 数字の ID を自分で探す必要はありません。トークンをブラウザや他のサイトに入れて確かめる必要もありません
- 配信が失敗したときは保存し直されません。次の配信のときに、もう一度問い合わせます
- 確かめられなかったときは、配信履歴に「Instagram のユーザー ID を自動で確かめられませんでした」と出ます。そのときは、下の「数字の ID が分かる場合」の方法で数字の ID を探し、「資格情報を設定」で入れ直してください（「よくある間違い」）

### 数字の ID が分かる場合

「Generate access tokens」の欄で、アカウントのユーザーネームの近くに長い数字が表示されていれば、それがユーザー ID である可能性があります。数字の ID が確かに分かるときは、`auto` の代わりにその数字を入れてもかまいません。
ただし、**App の画面のどこにユーザー ID が表示されるかは、公式の説明で確かめられませんでした。** 確かでないときは `auto` と入れてください。
`auto` でも確かめられず、App の画面でも見つからないときは、最後の「公式の説明」を開いてください。

## 手順 9：トークンの有効期限を決める

「トークンの有効期限」の欄には、次のどちらかを入れます。

- **生成した日の 60 日後の日付**を、`YYYY-MM-DDT00:00:00Z` の形で入れます。例：2026-09-24 に生成したなら、60 日後は 2026-11-23 なので `2026-11-23T00:00:00Z`
  - 末尾の `T00:00:00Z` は「その日の世界標準時の 0 時（日本時間の 9 時）」の意味です。本当の期限より少し早めになるので、安全な側です
  - 日数を数えるのが不安なら、1〜2 日早い日付にしてもかまいません（早めに延長が試みられるだけです）
- **分からなければ `unknown`** と入れます（半角の小文字）。Torifune は、次に配信が成功したときに延長を試み、正しい期限に書き換えます（「期限と更新」）

Torifune は、**今から 61 日より先**の日付や、日付として読めない値を、打ち間違いとみなして `unknown` と同じに扱います。

## 手順 10：Torifune に入れる

Torifune で `/social` を開きます。これから新しくアカウントを作るか、すでにあるアカウントに入れるかで、使う画面が違います。

### 新しくアカウントを作る場合（「SNSアカウントを追加」）

1. `/social` の「+ アカウントを追加」を押します。「SNSアカウントを追加」の画面が開きます
2. 「サービス」で「Instagram」を選びます（選択肢に無いときは、「Instagram配信」の Plugin が有効になっていません）
3. 「表示名」に、Torifune の中で見分けるための名前を入れます（例：`会社の公式`）
4. 「ハンドル」に、画面の一覧で見分けるためのユーザーネームを入れます（例：`@example_shop`。この欄は表示用で、配信には使いません）
5. 下の 3 つの欄に、手順 7〜9 で用意した値を入れます（下の表）
6. 「追加」を押します

### すでにあるアカウントに入れる場合（「資格情報を設定」）

1. `/social` のアカウントの一覧で、Instagram のアカウントの行の「資格情報を設定」を押します
2. 開いた画面の 3 つの欄に、手順 7〜9 で用意した値を入れます（下の表）
3. 「保存」を押します

### 欄と値の対応

| Torifune の欄の名前   | 入れる値                                                                          | 用意したところ |
| --------------------- | --------------------------------------------------------------------------------- | -------------- |
| Instagram ユーザー ID | `auto`、または数字だけの ID（`@` のユーザーネームや「Instagram app ID」ではない） | 手順 8         |
| 長期アクセストークン  | 「Generate token」で生成した文字列の全部                                          | 手順 7         |
| トークンの有効期限    | `2026-11-23T00:00:00Z` の形の日時、または `unknown`                               | 手順 9         |

- 保存した値は暗号化され、**画面に再表示されません**
- 入れ直すときは、**3 つの欄をすべて**入れ直します（一部の欄だけを変えることはできません）
- どちらの画面にも、この手順書を開く「手順書：」のボタンがあります。新しいタブで開くので、入力中の内容は消えません

入れ終えたら、手元にメモした値があれば消します。

## うまく入ったか確かめる

Instagram への投稿には**画像が 1 枚以上要ります。** 画像は、インターネットから誰でも取得できる **JPEG 画像の `https://` の URL** で渡します。

`/social` の「+ 投稿を作成」の画面には、画像の欄がありません。このため、Instagram のテスト用の投稿は、Torifune の API（`POST /api/v1/social/posts`。`media` に画像の URL を入れる）で登録します。API の使い方は、Torifune の文書「SNS投稿の外部連携」（`docs/マニュアル/SNS投稿の外部連携.md`）にあります。API を使えない場合は、Torifune の管理者に頼んでください。API を呼ぶときも、Torifune の API Token をコマンドラインに直書きしないでください（シェルの履歴に残ります）。

ユーザー ID の欄に `auto` と入れた場合は、このテスト用の投稿の配信のときに、Torifune が数字の ID を確かめます。配信が成功すれば、確かめた ID が保存し直されます。

1. テスト用の投稿を、この Instagram のアカウント・公開された JPEG 画像の URL・数分後の予約日時で登録します
2. 予約時刻を過ぎたら、`/social` の投稿の一覧で状態が「配信済み」になっているかを見ます。「配信履歴」のボタンから、配信の結果と理由も見られます
3. Instagram の自分のプロフィールに、その投稿が出ていることを確かめます。テスト用の投稿は、Instagram 側で削除して構いません（Torifune から削除しても Instagram の投稿は消えません）

「失敗」になった場合は、履歴に出た理由を次の「よくある間違い」で探します。

## よくある間違い

| 症状（配信履歴に出ること）                                     | 原因                                                                                                       | 直し方                                                                                                                                     |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Instagram の権限が足りません                                   | 個人アカウントのまま                                                                                       | 手順 1 でプロアカウントにし、手順 7 からトークンを生成し直して「資格情報を設定」で入れ直します                                             |
| Instagram の権限が足りません                                   | `instagram_business_content_publish` を加えていない・加える前にトークンを生成した                          | 手順 4 で権限を加え、手順 7 からトークンを生成し直して入れ直します                                                                         |
| Instagram の資格情報の形が正しくありません                     | 「Instagram ユーザー ID」に `@` のユーザーネームを入れた・トークンに空白や改行が入った                     | ユーザー ID は数字だけか `auto`（手順 8）、トークンは前後の空白なしで入れ直します（3 つの欄をすべて）                                      |
| Instagram のアクセストークンが無効か期限切れです               | トークンが失効した（60日を過ぎた）・写すときに欠けた                                                       | 手順 7 からトークンを生成し直し、「資格情報を設定」で 3 つの欄をすべて入れ直します                                                         |
| Instagram のアクセストークンが無効か期限切れです（と思われる） | 「API setup with Facebook Login」（Facebook ログイン）の画面や Graph API Explorer で作ったトークンを入れた | この Plugin は Instagram ログインの窓口（`graph.instagram.com`）を使います。手順 5〜7 の「API setup with Instagram login」で生成し直します |
| Instagram のユーザー ID を自動で確かめられませんでした         | 「Instagram ユーザー ID」に `auto` を入れたが、Instagram の応答から数字の ID を確かめられなかった          | 手順 8 の「数字の ID が分かる場合」で数字の ID を探し、「資格情報を設定」で 3 つの欄をすべて入れ直します                                   |
| 理由はさまざま                                                 | 「Instagram ユーザー ID」に「Instagram app ID」や別のアカウントの ID を入れた                              | 「Instagram ユーザー ID」に `auto` と入れ、「資格情報を設定」で 3 つの欄をすべて入れ直します                                               |
| 手順 7 で「Generate token」を押せない・アカウントが出ない      | テスターへの招待を承認していない                                                                           | 手順 6 を試します                                                                                                                          |
| 「資格情報を設定」に欄が 1 つしか出ない                        | 「Instagram配信」の Plugin が無効                                                                          | Torifune の管理者に `/plugins` で有効にしてもらってから入れます                                                                            |
| Instagram が画像を受け付けませんでした・処理できませんでした   | 画像の URL が公開された JPEG 画像を指していない                                                            | インターネットから誰でも開ける JPEG 画像の `https://` の URL にします                                                                      |

補足：

- Facebook ログインの画面で作ったトークンを入れたときに、履歴にどの理由が出るかは、公式の説明で確かめられませんでした（上の表の「と思われる」の行）。公式の説明は、Facebook ログインの API と Instagram ログインの API で窓口（ホスト名）が違うことを書いています
- 「Instagram ユーザー ID」に誤った数字を入れたときに出る理由も、公式の説明で確かめられませんでした
- 「トークンの有効期限」の形を間違えても、**配信は失敗しません。** Torifune は読めない値を `unknown` と同じに扱い、次に配信が成功したときに延長を試みます

## 期限と更新

- 長期アクセストークンの有効期限は **60日**です（公式の説明）
- **Torifune は、配信が成功したときに、残りが 30 日を切っていれば**（または期限が `unknown` なら）**トークンを延長し**、新しいトークンと期限を保存し直します。延長したトークンは、延長した日から 60 日使えます（公式の説明）
- 延長できるのは、**発行から 24 時間以上たった、まだ切れていないトークンだけ**です（公式の説明）。期限に `unknown` を入れて、発行した当日に配信すると、最初の延長は失敗することがあります。このときも**投稿そのものは成功**し、次に配信が成功したときにもう一度延長を試みます
- **30 日以上配信しない期間があると、トークンは延長されないまま失効しえます。** Torifune は配信のとき以外にトークンを延長しません。60 日のあいだ延長されなかったトークンは、失効して延長もできなくなります（公式の説明）
- 失効すると、次の配信が「アクセストークンが無効か期限切れです」という理由で失敗します。そのときは、手順 7 でトークンを生成し直し、`/social` のアカウントの行の「資格情報を設定」から、**3 つの欄をすべて**入れ直します（ユーザー ID は変わりません。有効期限は新しく決め直します）
- 延長に失敗しても、履歴には出ません（投稿は成功として扱われ、理由はサーバのログにだけ残ります）。しばらく配信の予定が無いときは、失効する前に手順 7 から生成し直しておくと安心です

## 安全のために

- 値は**この画面（Torifune）以外に貼らないでください。** チャット・メール・共有のメモ・AI のチャット・「トークンを確かめる」ような第三者のサイトに貼らないでください
- **Instagram や Facebook にログインするパスワードは Torifune に入れないでください**（入れる欄はありません。求められたら手順を誤っています）
- **App Secret（「Instagram app secret」）は Torifune に入れないでください。** Torifune の配信にも延長にも使いません。App の画面で表示しても、どこにも写さないでください
- 値は発行した画面で一度しか表示されないことがあります。写すまで画面を閉じないでください。写した値は、Torifune に入れ終えたら手元のメモから消してください
- 値をコマンドラインに直書きしないでください（シェルの履歴に残ります）。この手順書は、コマンドを使わない手順を先に書いています
- **トークンを URL に入れて開かないでください。** ブラウザの履歴・同期・拡張機能から漏れることがあります。ユーザー ID が分からなければ、手順 8 のとおり `auto` と入れてください
- **入れ終えたら、クリップボードの履歴からも消してください。** Windows の「クリップボードの履歴」、スマートフォンの入力の履歴、クリップボードを同期するアプリに、写した値が残ることがあります
- **画面の写真（スクリーンショット）を人に送る前に、値が写っていないか確かめてください**（アクセストークン・App Secret・ユーザー ID）
- 値が漏れたと思ったら、Meta for Developers の App の画面でトークンを生成し直してから（手順 7）、Torifune で「資格情報を設定」から入れ直してください。生成し直したときに古いトークンが使えなくなるかは、公式の説明で確かめられませんでした
- App Secret が漏れたと思ったら、App の画面の「App settings」→「Basic」（基本設定）で App Secret を作り直してください（公式の説明は、漏れたらすぐに作り直すよう書いています）。「Instagram app secret」も同じ場所で作り直せるかは、公式の説明で確かめられませんでした
- Torifune に保存した値は暗号化され、画面に再表示されません。**入れ直すときはすべての欄を入れ直します**（一部だけは変えられません）
- テスターや役割に加えるのは、自分が管理するアカウントだけにしてください

## 画面が違うとき

Meta for Developers と Instagram の画面の名前や並びは、よく変わります。この手順書のとおりに見つからないときは、次を試してください。

- App の画面の左のメニューで「Instagram」「API setup」「Generate access tokens」「Generate token」の文字を探します。公式の説明の中でも「API setup with Instagram login」と「API setup with Instagram business login」の 2 つの書き方があります
- 使い道（Use case）の名前が違うときは、「Instagram」を含む使い道を選びます。見つからなければ、手順 3 の「Other」→「Business」→「Instagram」の「Set up」の道を使います
- 「Facebook Login」（Facebook ログイン）の文字が入った画面や権限（`instagram_basic`・`instagram_content_publish` など、`business` の入っていないもの）は、この Plugin では使いません
- 生成したトークンが長期のものでなく、**1 時間で切れる短期のもの**だと画面に書かれている場合、長期のトークンへの交換には App Secret と、サーバ側で動かすプログラムが要ります（公式の説明）。この手順書はその手順を扱いません。公式の説明の「Get a long-lived access token」（長期アクセストークンを得る）を開き、App Secret を扱える人に頼んでください。交換した後の長期のトークンを、この手順書の手順 8 から続けて使えます
- 「Generate token」が見つからないとき、「Set up Instagram business login」（Instagram のビジネスログインの設定）の「Business login settings」で転送先の URL（Redirect URL）の登録を求められることがあります。この登録がトークンの生成に要るかは、公式の説明で確かめられませんでした
- 表示の言語を英語にして、この手順書の英語の名前で探すと見つけやすくなります
- それでも見つからなければ、次の「公式の説明」を開いてください
