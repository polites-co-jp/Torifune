# X配信・X API（`sns-x-api`）

Torifune に予約した SNS 投稿を、**X API で X へ自動投稿する** Plugin です（有料版）。手動投稿も選べます。

Torifune 本体は「いつ送るか・再試行・記録・画面」を持っています。
この Plugin が受け持つのは **1 件を X へ投稿すること**と、
手動投稿のときに **投稿内容の入った X の投稿画面（Web Intent）の URL を組み立てること**だけです。

**X API は有料（従量課金）です。** 使うには X の開発者アカウントでクレジットを購入しておく必要があります（下の「X API の料金」）。
料金を払わずに X へ届けたい場合は、無料版の **「X配信（手動投稿）」（`sns-x-manual`）** を使います。

## 無料版と有料版

X への配信 Plugin は 2 つあります。**どちらも provider は `x` で、同時には有効にできません**（片方だけを有効にします）。

|                      | `sns-x-manual`（無料版）                                                 | `sns-x-api`（有料版・この Plugin）                                    |
| -------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| X API の契約         | 要りません                                                               | **要ります**（従量課金のクレジット）                                  |
| 予約時刻に起きること | 「手動投稿待ち」に並びます。**人が投稿画面を開いて送信ボタンを押します** | Torifune が自動で投稿します（`deliveryMode: 'auto'`）。手動も選べます |
| 画像                 | 付けられません（投稿画面で添付します）                                   | 自動配信なら 4 枚まで                                                 |
| 資格情報             | 要りません（`/social` に資格情報の欄は出ません）                         | OAuth 1.0a の 4 つの値（`/social` の「資格情報を設定」で入れます）    |

登録済みの X のアカウントと予約は、どちらの Plugin でもそのまま使えます。**入れ替えても作り直す必要はありません**（下の「入れ替え」）。

## 導入のしかた

1. `plugins/sns-x-api/` を Torifune の `plugins/` の下に置きます
2. `/plugins` の「検出済み」に **「X配信（X API）」** が現れるので「導入」を押します
3. **再ビルドと再起動が要ります。** Plugin のコードはアプリのビルドに取り込まれるため、
   導入しただけでは動きません（画面の案内に従ってください）
4. `/plugins` で **有効化**します。`sns-x-manual` が有効なままだと有効化できません（先に `sns-x-manual` を無効化します）
5. `/social` で `provider` が **X** の SNS アカウントを作り、資格情報（4 項目）を入れます。各欄の下に、その値の用意のしかたが出ます。
   **既にある X のアカウント**（無料版から移った場合など）には、`/social` のアカウントの行の **「資格情報を設定」** から入れます

この Plugin は画面の設定を持ちません（`/plugins/sns-x-api/settings` はありません）。

## X API の料金

- **X API は従量課金です。** 前払いのクレジットを購入し、使った分だけ差し引かれます（確認した時点で、無料枠はありませんでした）
- **料金の額はここには書きません**（X 側で変わるためです）。X の料金表を見てください：<https://docs.x.com/x-api/getting-started/pricing>
- **URL を含む投稿は、URL を含まない投稿より料金が高くなります。** `link` を指定した投稿も、本文に URL を書いた投稿もこれに当たります。
  どの投稿に URL を入れるかは利用者の判断なので、Torifune は断りません
- 送る前に失敗して再試行するときは、投稿の要求は 1 回しか送りません。ただし**画像のアップロードは再試行のたびにやり直します**
- この Plugin は投稿に要る要求（画像の取得・画像のアップロード・投稿）のほかに X API を呼びません（アカウント情報の読み取りもしません）

## 資格情報（OAuth 1.0a の 4 つの値）を用意する

**OAuth 1.0a（User Context）の 4 つの値だけを使います。OAuth 2.0 のトークン（Bearer Token や OAuth 2.0 の Access Token）は使えません。**

X の開発者向け画面（Developer Console）で、次の手順で用意します（画面の名前は X 側の変更で変わることがあります）。

1. アプリを作ります。**API Key と API Key Secret** が発行されます
2. アプリの権限を **Read and write** にします
3. 投稿に使う自分のアカウントの **Access Token と Access Token Secret** を発行します
4. **権限を Read and write に変えたのが Access Token の発行より後なら、Access Token を発行し直してください。**
   読み取り専用のまま発行したトークンでは、投稿が HTTP 403 で断られます

### Torifune に入れる 4 項目

| 項目                              | 入れるもの                                          |
| --------------------------------- | --------------------------------------------------- |
| API Key（Consumer Key）           | アプリに発行された API Key                          |
| API Key Secret（Consumer Secret） | API Key と対になる Secret                           |
| Access Token                      | 投稿するアカウントの Access Token（Read and write） |
| Access Token Secret               | Access Token と対になる Secret                      |

- Torifune に保存した資格情報は暗号化され、**保存後に画面へ再表示されません**。
  入れ直すときは、`/social` のアカウントの行の「資格情報を設定」で **4 つとも**入れ直します（一部の項目だけを入れ直すことはできません。保存すると丸ごと置き換わります）
- 4 つの値に**有効期限はありません。** X 側でアプリの権限を取り消したり、トークンを発行し直したりすると、配信は認証の失敗で止まります
- **Torifune のサーバの時計がずれていると、認証に失敗します**（署名に時刻が入るためです）。サーバの時刻合わせ（NTP など）を有効にしてください
- 資格情報は X API の宛先へ送る要求の署名にだけ使います。送り先は X API に固定されていて、設定で変えることはできません
- **X へ送る要求の `Authorization` ヘッダをログに残さないでください**（APM・送信側のプロキシのログなど）。
  OAuth 1.0a は要求の本体を署名しないため、漏れたヘッダは署名の時刻から間もないうちなら、**別の本文の投稿にも使い回せます**

### 資格情報を入れるまでの猶予は約24時間です

Plugin を有効にしていない、あるいは資格情報を入れていない状態でも、投稿の予約そのものは受け付けます。
ただしその投稿は配信されずに待たされ、**予約時刻から約24時間で `failed` になります。**

`failed` は終端の状態です。**そこから配信し直すことはできず、新しい投稿として登録し直す**ことになります。
予約を入れたら、24時間以内に有効化と資格情報の登録を済ませてください。

## 投稿の作りかた（X の制限）

| 決まり              | 値                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------ |
| 本文の長さ          | **重み付きで 280** まで（日本語・絵文字は 1 文字を 2、`https://` で始まる URL は長さによらず 23 と数えます） |
| リンク（`link`）    | **本文の末尾に改行して足します**。足した後の長さで数えます（自動・手動とも同じ）                             |
| 画像                | 自動配信なら **4枚**まで。**手動投稿には付けられません**（投稿画面で添付してください）                       |
| 画像の説明（`alt`） | **X へは送られません**（指定しても断りはしません）                                                           |
| `providerOptions`   | 指定できる項目はありません                                                                                   |

- 上限を超える投稿は、**予約の時点で断ります。** 配信の直前になって初めて弾かれることはありません
- `https://` の無いドメイン（`example.com` など）は URL として数えません。X の数え方より少なく数えることがあり、
  その場合は自動配信なら X が断って `failed`（投稿はされません）、手動投稿なら X の投稿画面で送信できなくなります
- 返信・引用・スレッド・投票・長文投稿（X Premium）・動画には対応していません

### 画像は公開された URL で渡します

**Torifune は画像ファイルを預かりません。** 投稿に添える画像は、
**インターネットから取得できる 5MB 以下の JPEG・PNG・WebP 画像の `https://` の URL** として渡してください。
配信のときに、Torifune のサーバがその URL から画像を取得し、X へアップロードします。

- 1 枚あたり **5MB** まで。受け付ける形式は **JPEG・PNG・WebP** です（`Content-Type` で判断します）
- **GIF・動画は扱いません。** 指定すると配信のときに `failed` になります（再試行はしません）
- **転送（リダイレクト）は追いません。** 転送される URL を指定した場合は、転送先の URL を直接渡してください
- 取得に失敗したときの理由には、**取得先が返した HTTP の状態コードを書きません。**
  「時間をおいて再試行する」か「URL を直す必要がある」かだけが残ります
- **画像の説明（`alt`）は X へ送られません。** 送るには画像ごとに X API の要求が 1 つ増え、料金も増えるためです

### 手動投稿

この Plugin でも、投稿ごとに **手動（`deliveryMode: 'manual'`）** を選べます。

1. 予約時刻を過ぎると、`/social` の **「手動投稿待ち」** に並びます
2. 「投稿画面を開く」を押すと、**本文の入った X の投稿画面**が別のウィンドウで開きます（ブラウザでログインしている X のアカウントで開きます）
3. 内容を確かめて、X の画面で投稿します
4. Torifune に戻り、**「投稿した」** を押します（投稿をやめたときは「取りやめ」）

手動投稿では X API を呼ばないので、料金はかかりません。開く投稿画面は `sns-x-manual` と同じです。

## 入れ替え

**同時に有効にできるのは片方だけです。入れ替えは「有効な方を無効化してから、もう片方を有効化する」順で行います。**
登録済みの X のアカウントと投稿は provider（`x`）で結びつくので、入れ替えても作り直しません。

### 無料版からこの Plugin へ

1. `/plugins` で `sns-x-api` を「導入」します（再ビルドと再起動。この間 `sns-x-manual` は有効のまま動きます）
2. `/plugins` で `sns-x-manual` を「無効化」します
3. `/plugins` で `sns-x-api` を「有効化」します
4. `/social` で登録済みの X のアカウントの行の **「資格情報を設定」** を押し、4 つの欄（API Key（Consumer Key）／API Key Secret（Consumer Secret）／
   Access Token／Access Token Secret）に入れて「保存」します。各欄の下に説明が出ます（Access Token は「Read and write」にしてから発行したもの）。
   入れるまで、自動の予約は「資格情報 未設定」で待ちます（約24時間まで）
5. 以後の予約は「自動」を選べます。手動の予約はそのまま手動投稿待ちに並びます（同じ投稿画面が開きます）

- **導入を先に済ませる**のは、導入に再ビルドと再起動が伴うためです
- 2〜3 のあいだ（数秒）は、手動投稿待ちの行が「投稿画面を開けません」になりますが、「投稿した」「取りやめ」は押せます
- 4 は API でも行えます（外部のアプリから入れる場合や、無料版の間に先に入れておく場合）。要求の形です（`social.write` の権限で送ります。`{id}` は X のアカウントの ID）：

  ```http
  PATCH /api/v1/social/accounts/{id}
  Content-Type: application/json

  {
    "credentials": {
      "apiKey": "…",
      "apiKeySecret": "…",
      "accessToken": "…",
      "accessTokenSecret": "…"
    }
  }
  ```

- 本文や API Token（`tfp_` で始まる値）をコマンドラインに直書きしないでください（シェルの履歴やプロセスの一覧に残ります）。ファイルか標準入力で渡してください
- 4 の値は、無料版の間に上の要求（API）で先に入れておけます。
  画面からは先に入れられません（無料版の間は「資格情報を設定」に資格情報の欄が出ないため）
- 4 で入れた値は、保存済みの資格情報を**丸ごと置き換えます**。一部の項目だけを入れ直すことはできないので、4 つとも入れてください
- 無料版の間は資格情報の欄が出ません（入力は要りません）。以前の版の Torifune で汎用の資格情報の欄に何かを入れていた場合は、
  **1 の前に**「資格情報を設定」の「資格情報を消す」で消すか、4 で 4 つの値に置き換えてください（残っていれば「資格情報を設定」に警告が出ます）。
  そのままこの Plugin へ入れ替えると「資格情報 設定済み」として扱われ、形が合わないため、自動の予約が待たずに**すぐ `failed`** になります
- **順序を間違えた場合**（`sns-x-manual` を有効にしたまま `sns-x-api` を有効化した場合）、`sns-x-api` は有効化に失敗して `disabled` になり、
  `/plugins` に理由（provider `x` は別の Plugin が既に登録している）が出ます。**`sns-x-manual` は動き続け、何も失われません。** 2 からやり直してください

### この Plugin から無料版へ

1. `/plugins` で `sns-x-api` を「無効化」し、`sns-x-manual` を「有効化」します
2. 残っている「自動」の予約を「手動」に直します（`deliveryMode` を `manual` に。画像を付けた予約は画像を外します）

- 直さずに残した自動の予約は配信されずに待たされ、**約24時間で `failed` になります。** `/social` の表示が知らせます
- 入れていた 4 つの値は**残りますが、読まれません。** 消したい場合は、`/social` で X のアカウントの行の「資格情報を設定」を開き、
  **「資格情報を消す」** を押します（残っている間はそこに警告が出ます）。API では `PATCH /api/v1/social/accounts/{id}` に `{ "credentials": {} }` を送ります

## うまくいかないとき

配信に失敗した投稿は `/social` の履歴に**理由**が残ります。よくあるものは次のとおりです。

| 履歴に出ること                                     | 見るところ                                                                                                                           |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| X API の資格情報の形が正しくありません             | 4 つの値に空白・改行・全角文字が混ざっていないか確かめ、`/social` のアカウントの行の「資格情報を設定」から入れ直してください         |
| X API の認証に失敗しました（HTTP 401）             | 4 つの値が正しいか、取り消されていないかを確かめてください。**サーバの時計がずれていても起きます**                                   |
| X が投稿を受け付けませんでした（HTTP 403）         | 同じ内容の連投、アプリの権限（Read and write。変えた後に Access Token を発行し直したか）、X API のクレジットの残高を確かめてください |
| 画像を取得できませんでした                         | 画像の URL が、インターネットから取得できる 5MB 以下の JPEG・PNG・WebP 画像を指しているか、転送されていないかを確かめてください      |
| X API の呼び出し回数の制限に達しました             | X 側の制限です。Torifune が待ってから自動で送り直します                                                                              |
| 接続できませんでした・一時的に応答できませんでした | しばらく待つと Torifune が自動で送り直します                                                                                         |
| 投稿の要求が届いたかを確認できませんでした         | **二重投稿を避けるため再試行しません。** X 側で投稿されたかを確かめてから、必要なら予約し直してください                              |

失敗の理由に**資格情報そのものは書かれません。** X API が返した自由な文言も載せません（HTTP の状態コードだけを載せます）。

## この Plugin が持つもの・持たないもの

- **状態を 1 つも持ちません。** 設定もなく、投稿の状態も資格情報も自分では保存しません（資格情報は Torifune 本体が暗号化して保存します）
- 投稿が成功すると、履歴の「投稿を見る」から X の投稿を開けます（投稿 ID から組み立てた URL です）
- Torifune の Permission を 1 つも追加しません。データベースにも直接触りません
- 投稿の削除・編集はできません（X へ送ったあとは取り消せないためです）
- 手動投稿の URL を組み立てる `x-text.ts` は、`sns-x-manual` と**同じ内容のファイル**です。2 つの Plugin で手動投稿の結果が食い違わないよう、一致をテストで確かめています
- **この Plugin は実際の X ではまだ動かしていません。** 署名は X の公開ドキュメントの計算例で確かめていますが、導入したら、まずテスト用の投稿で疎通を確かめてください

同じ provider の Plugin を複数作るときは、共有したいファイルを各 Plugin に複製し、一致をテストで固定してください（Plugin は隣の Plugin のファイルを import できません）。
