# X API の 4 つの値（OAuth 1.0a）の発行手順

最終確認日：2026-09-24（この日に公式の説明と突き合わせました）

> この手順書は、X の開発者向け画面で OAuth 1.0a の 4 つの値（API Key・API Key Secret・Access Token・Access Token Secret）を用意し、Torifune に入れるまでを説明します。
> スクリーンショットは載せていません。画面の名前や配置は X 側の変更で変わることがあります。
> 見つからないときは、最後の「公式の説明」を開いてください。

## この手順書でそろうもの

Torifune の X のアカウントには、次の 4 つを入れます。**4 つで 1 組**です。どれか 1 つでも違うと、X は投稿を受け付けません。

| Torifune の欄の名前               | 入れるもの                                                                            | どんな値か                                          |
| --------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------- |
| API Key（Consumer Key）           | App に発行される「API Key」                                                           | App（下の説明）を見分けるための名前にあたる値       |
| API Key Secret（Consumer Secret） | 「API Key」と対になる「API Key Secret」                                               | App のパスワードにあたる値。人に見せません          |
| Access Token                      | 投稿に使う自分の X のアカウントの「Access Token」（「Read and write」で生成したもの） | 「どの X のアカウントとして投稿するか」を表す値     |
| Access Token Secret               | 「Access Token」と対になる「Access Token Secret」                                     | Access Token のパスワードにあたる値。人に見せません |

X の公式の説明では、API Key と API Key Secret を「Consumer Key」「Consumer Secret」とも呼びます。どちらも同じものです。

**この Plugin が使うのは OAuth 1.0a の 4 つの値だけです。** 同じ画面に並んでいる OAuth 2.0 の値（「Client ID」「Client Secret」）と「Bearer Token」は使いません。Torifune のどの欄にも入れないでください。

言葉の説明：

- **API**：プログラムが X に投稿などを頼むための窓口です。Torifune はこの窓口を通して X へ投稿します
- **App（アプリ）**：X の開発者向け画面で作る「API を使う入れ物」です。値はこの入れ物ごとに発行されます。スマートフォンのアプリとは別のものです
- **トークン（Token）**：「このアカウントとして操作してよい」ことを表す、長い文字列の許可証です
- **OAuth 1.0a / OAuth 2.0**：X が使っている 2 種類の許可のしくみです。名前が似ていますが、値は互いに使い回せません。この Plugin は OAuth 1.0a だけを使います
- **Developer Console（開発者向けの管理画面）**：App を作り、値を発行し、利用料を払う X の画面です（`https://console.x.com`）

## 始める前に用意するもの

- **X のアカウント**（投稿に使うアカウント）と、そのログイン用のパスワード（手順 1 で X にログインするときだけ使います。Torifune には入れません）
- **X API の料金を払う準備。X API は従量課金です。** 先にクレジット（前払いの利用料）を買い、使った分だけ差し引かれます（手順 7）。料金の額はこの手順書には書きません。X の料金表を見てください（最後の「公式の説明」）
  - **料金を払わずに X へ投稿したい場合は、この Plugin ではなく「X配信（手動投稿）」（`sns-x-manual`）を使います。** 予約の時刻になったら、人が X の投稿画面を開いて送信します
- **パソコンのブラウザ**をおすすめします。Developer Console はパソコンの画面を前提にしています。長い値を写して Torifune に貼る作業も、同じパソコンで 2 つのタブを並べると間違いが少なくなります
- Torifune で `/social` を開けて、アカウントを追加・編集できる利用者であること（「SNSアカウントを追加」や「資格情報を設定」のボタンが見えない場合は、Torifune の管理者に頼んでください）
- Torifune の管理者が、この Plugin（「X配信（X API）」）を `/plugins` で導入・有効化していること。「X配信（手動投稿）」が有効なままだと、この Plugin は有効にできません（下の「無料版（手動投稿）から移る場合」）
- 発行した値を**一時的に**置く場所。いちばん安全なのは、メモに置かずに X の画面から Torifune の欄へそのまま貼ることです。4 つを一度に貼れない場合は、自分だけが使うパソコンのメモ帳などに一時的に置き、Torifune に入れ終えたらすぐ消します（共有のメモ・チャットには置きません）

## 全体の流れ

1. Developer Console に X のアカウントでログインし、開発者の規約に同意する
2. App を作り、表示された API Key と API Key Secret を写す
3. App の権限（App permissions）を「Read and write」にする
4. **権限を変えた後で**、自分のアカウントの Access Token と Access Token Secret を生成して写す
5. クレジットを購入する
6. Torifune の `/social` で 4 つの欄に入れる

## 手順 1：Developer Console にログインする

- **開く画面**：ブラウザで `https://console.x.com` を開きます
- **押すもの**：ログインしていなければ、X のアカウントでログインします（サインインの画面が出たら、投稿に使う X のアカウントを選びます）
- **確かめること**：Developer Console の画面が開くこと

**投稿に使うアカウントでログインしてください。** 手順 6 で生成する Access Token は、「App を作ったアカウント（＝ここでログインしたアカウント）」として投稿するためのものです。会社の公式アカウントから投稿したいなら、そのアカウントでログインします。

## 手順 2：開発者の規約に同意する

初めて Developer Console を使うときだけの手順です。すでに開発者アカウントがあれば手順 3 へ進みます。

- **開く画面**：手順 1 の続きで表示される、開発者の規約（「Developer Agreement and Policy」）の画面
- **押すもの**：内容を読み、同意します。続けて、API をどう使うか（使い道）など、求められた基本の情報を入れます
- **確かめること**：Developer Console の最初の画面（ダッシュボード）が開くこと

使い道を書く欄には、例えば「自分（自社）のアカウントの予約投稿に使う」のように、実際の使い方を短く書きます。規約・欄の中身は X 側で変わることがあるので、画面の案内に従ってください。

## 手順 3：App を作る

- **開く画面**：Developer Console のダッシュボード
- **押すもの**：「New App」または「Create App」（App を作る）を押します
- **入れるもの**：
  - App の名前（例：`Torifune-Poster`。ほかと同じ名前は使えないことがあります）
  - 説明と使い道（例：「Torifune から自分のアカウントへ予約した投稿を送る」）
- **確かめること**：App が作られ、値（キーとトークン）が表示される画面、または App の詳しい画面が開くこと

画面が Project（プロジェクト。App をまとめる入れ物）を先に作るように求めた場合は、Project を作ってから、その中に App を作ります。X の公式の説明には「App は Project の中に作る」と書かれた頁と、Project に触れない頁があり、今の Developer Console で Project を作る画面が出るかは確かめられませんでした。

**App の名前は、X の上で他の人に見えることがあります。** X の公式の説明によると、API で作った投稿の情報には App の名前と Website URL（手順 5）が「投稿に使ったアプリ」として載ります。人に見られてよい名前にしてください。

## 手順 4：API Key と API Key Secret を写す

X の公式の説明では、App を作ったときに **API Key と API Key Secret が表示され、表示は一度だけ**です（同じ画面に Bearer Token も表示されます）。

- **開く画面**：手順 3 で App を作った直後の画面
- **写すもの**：「API Key」と「API Key Secret」の 2 つ。「Bearer Token」は写さなくて構いません（この Plugin は使いません）
- **確かめること**：写した値の前後に空白や改行が入っていないこと。API Key と API Key Secret を取り違えていないこと

画面を閉じてしまった・写しそこねたときは、作り直せます（「Regenerate」＝再生成）：

1. Developer Console の左側のメニューで「Apps」を開きます
2. 手順 3 で作った App を開きます
3. 「Keys and tokens」（キーとトークン）のタブを開きます
4. API Key and Secret（以前の画面では「Consumer Keys」）の行の「Regenerate」を押します

**再生成すると、前の値は使えなくなります。** すでに Torifune に入れていた場合は、4 つとも入れ直してください。

API Key を再生成したときに、Access Token と Access Token Secret も生成し直す必要があるかは、公式の説明で確かめられませんでした。API Key を再生成したら、念のため手順 6 で Access Token も生成し直し、4 つの値をそろえて入れるのが確実です。

## 手順 5：App の権限を「Read and write」にする

**この手順は、手順 6（Access Token の生成）より前に行います。** 順番を逆にすると、投稿できないトークンができます。

App の権限（App permissions）は、App に何を許すかの設定で、OAuth 1.0a では次の 3 つから選びます（X の公式の説明）。

| 権限                 | できること                             | この Plugin で              |
| -------------------- | -------------------------------------- | --------------------------- |
| Read only            | 読むだけ。投稿できません               | 使えません（投稿できない）  |
| Read and write       | 読む・投稿する・削除する・いいねなど   | **これを選びます**          |
| Read, write, and DMs | 上に加えてダイレクトメッセージの送受信 | 選びません（DM は使わない） |

- **開く画面**：Developer Console の「Apps」から手順 3 の App を開き、App の設定（App settings）の中の、認証の設定（authentication settings）の画面を開きます。この画面は「User authentication settings」（利用者の認証の設定）と呼ばれてきましたが、今の Developer Console での正確な名前と開き方は、公式の説明で確かめられませんでした（下の「画面が違うとき」）
- **選ぶもの**：
  - 使う認証のしくみを選ぶ欄があれば、**OAuth 1.0a を有効にします**（OAuth 2.0 と両方を有効にもできますが、この Plugin は OAuth 1.0a だけを使います）
  - 「App permissions」を **「Read and write」** にします
- **入れるもの（求められた場合）**：
  - 「Type of app」（App の種類）：OAuth 2.0 のための欄です。この Plugin は使わないので、選ぶ必要があれば「Web App」か「Automated App / Bot」（どちらもサーバで動く App）を選びます
  - 「Callback URI / Redirect URL」（認可の後に戻る先）：この Plugin は使いませんが、空にできない場合は、自分の Web サイトなど `https://` で始まる自分の管理する URL を入れます
  - 「Website URL」（App の Web サイト）：自分（自社）の Web サイトの URL を入れます。投稿の情報に載ることがあります（手順 3）
  - これらの欄が必ず入れるものかどうかは、公式の説明で確かめられませんでした
- **押すもの**：保存のボタン（「Save」など）を押します
- **確かめること**：App の権限の表示が「Read and write」になっていること

**すでに Access Token を生成していた場合は、この後の手順 6 で必ず生成し直します。** X の公式の説明は「権限を変えたら、新しい権限のトークンを得るために認可し直す必要がある」と書いています。権限を変える前に作ったトークンは、古い権限（読むだけ）のまま残ります。

## 手順 6：Access Token と Access Token Secret を生成して写す

- **開く画面**：Developer Console の「Apps」から手順 3 の App を開き、「Keys and tokens」のタブを開きます
- **押すもの**：「Access Token and Secret」（「Access Token & Secret」と表示されることもあります）の行の「Generate」（生成）を押します。すでに生成したことがあれば「Regenerate」（再生成）を押します。「Regenerate」は公式の説明で確かめましたが、初めて生成するときのボタンの正確な名前は確かめられませんでした
- **写すもの**：表示された「Access Token」と「Access Token Secret」の 2 つ。**表示は一度だけです。** 写し終えるまで画面を閉じないでください
- **確かめること**：
  - 手順 5 で「Read and write」にした**後で**生成したこと
  - 値の前後に空白や改行が入っていないこと
  - Access Token と Access Token Secret を取り違えていないこと

ここで生成されるのは、**手順 1 でログインした X のアカウント（App の持ち主）として投稿するためのトークン**です。別の X のアカウントから投稿したい場合は、そのアカウントで手順 1 からやり直します（別のアカウントのトークンをこの画面から作ることはできません）。

生成した画面に、トークンの権限（例：「Read and write」で作られたこと）が表示されるかは、確かめられませんでした。表示が無くても、**「Read and write」にした後で生成し直した**なら問題ありません。迷ったら、もう一度「Regenerate」を押して生成し直し、新しい値を入れてください（古い値は使えなくなります）。

## 手順 7：クレジットを購入する

**X API は従量課金です。** クレジットが無いと、値が正しくても投稿は X に断られます。

- **開く画面**：Developer Console の、料金・クレジット（billing・credits）の画面（正確な画面の名前は公式の説明で確かめられませんでした。公式の説明は「Developer Console でクレジットを購入する」とだけ書いています）
- **押すもの**：画面の案内に従ってクレジットを購入します
- **確かめること**：Developer Console にクレジットの残高が表示されること

知っておくこと（X の公式の説明から。額は書きません）：

- 料金は使った分だけで、月額の契約はありません。使うたびに残高から差し引かれ、残高が足りなくなると API の要求が止められます
- **URL を含む投稿は、URL を含まない投稿より料金が高く設定されています**
- 残高が減ったら自動で買い足す設定（auto-recharge）と、1 回の請求の期間に使える額の上限（spending limit）を Developer Console で決められます。思わぬ請求を避けるために、上限を決めておくと安心です
- 最新の料金は X の料金表で確かめてください（最後の「公式の説明」）

## 手順 8：Torifune に入れる

Torifune で `/social` を開きます。これから新しくアカウントを作るか、すでにあるアカウントに入れるかで、使う画面が違います。

### 新しくアカウントを作る場合（「SNSアカウントを追加」）

1. `/social` の「+ アカウントを追加」を押します。「SNSアカウントを追加」の画面が開きます
2. 「サービス」で「X」を選びます
3. 「表示名」に、Torifune の中で見分けるための名前を入れます（例：`会社の公式`）
4. 「ハンドル」に、画面の一覧で見分けるための X のユーザー名を入れます（例：`@example`。この欄は表示用で、配信には使いません）
5. 下の 4 つの欄に、手順 4・手順 6 で写した値を入れます（下の表）
6. 「追加」を押します

### すでにあるアカウントに入れる場合（「資格情報を設定」）

1. `/social` のアカウントの一覧で、X のアカウントの行の「資格情報を設定」を押します
2. 開いた画面の 4 つの欄に、手順 4・手順 6 で写した値を入れます（下の表）
3. 「保存」を押します

### 欄と値の対応

| Torifune の欄の名前               | 入れる値                                         | 写したところ |
| --------------------------------- | ------------------------------------------------ | ------------ |
| API Key（Consumer Key）           | API Key                                          | 手順 4       |
| API Key Secret（Consumer Secret） | API Key Secret                                   | 手順 4       |
| Access Token                      | Access Token（「Read and write」にした後で生成） | 手順 6       |
| Access Token Secret               | Access Token Secret                              | 手順 6       |

- 保存した値は暗号化され、**画面に再表示されません**
- 入れ直すときは、**4 つとも**入れ直します（一部の欄だけを変えることはできません。保存すると丸ごと置き換わります）
- どちらの画面にも、この手順書を開く「手順書：」のボタンがあります。新しいタブで開くので、入力中の内容は消えません

入れ終えたら、手元にメモした値があれば消します。

### 無料版（手動投稿）から移る場合

「X配信（手動投稿）」（`sns-x-manual`）を使っていた場合は、Torifune の管理者が `/plugins` で次の順に操作してから、上の「資格情報を設定」で 4 つの値を入れます。登録済みの X のアカウントと予約は、作り直さずにそのまま使えます。

1. 「X配信（X API）」を「導入」します（再ビルドと再起動が要ります。その間も手動投稿は使えます）
2. 「X配信（手動投稿）」を「無効化」します
3. 「X配信（X API）」を「有効化」します

2 つの Plugin は同時には有効にできません。順番を逆にすると、「X配信（X API）」の有効化が失敗します（手動投稿の方は動き続け、何も失われません）。そのときは 2 からやり直します。

## うまく入ったか確かめる

1. `/social` の「+ 投稿を作成」から、この X のアカウントを選んだテスト用の投稿を作ります。「予約日時」を数分後にし、「配信方法」を「自動」にして保存します。**テストの投稿もクレジットを使います。** URL を含まない短い本文にすると、料金を抑えられます
2. 予約時刻を過ぎたら、`/social` の投稿の一覧で状態が「配信済み」になっているかを見ます。「配信履歴」のボタンから、配信の結果と理由も見られます。成功していれば、履歴の「投稿を見る」から X の投稿を開けます
3. X の自分のプロフィールに、その投稿が出ていることを確かめます。テスト用の投稿は X 側で削除して構いません（Torifune から削除しても X の投稿は消えません）

「失敗」になった場合は、履歴に出た理由を次の「よくある間違い」で探します。

## よくある間違い

| 症状（配信履歴に出ること）                                     | 原因                                                                                                    | 直し方                                                                                                                              |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| X が投稿を受け付けませんでした（投稿、HTTP 403）               | 「Read and write」にする**前に** Access Token を生成した（トークンが読むだけのまま）                    | 手順 5 で「Read and write」になっているかを確かめ、手順 6 で Access Token を生成し直して、「資格情報を設定」で 4 つとも入れ直します |
| X が投稿を受け付けませんでした（投稿、HTTP 403）               | クレジットが無い・足りない（クレジットが無いときに 403 になるかは、公式の説明で確かめられませんでした） | Developer Console でクレジットの残高を確かめ、購入します（手順 7）                                                                  |
| X が投稿の要求を受け付けませんでした（投稿、HTTP 402）         | X API が「支払いが要る」と返した（クレジットの残高が無い・足りないと思われる）                          | Developer Console でクレジットの残高を確かめ、購入します（手順 7）。自動の予約は再試行しないので、購入した後に予約し直します        |
| X が画像を受け付けませんでした（画像のアップロード、HTTP 402） | 同上（画像のアップロードの時点で「支払いが要る」と返された）                                            | 同上                                                                                                                                |
| X が投稿を受け付けませんでした（投稿、HTTP 403）               | 直前と同じ内容を続けて投稿した                                                                          | 本文を変えて予約し直します                                                                                                          |
| X が画像のアップロードを受け付けませんでした（…HTTP 403）      | 上の 3 つと同じ（権限・クレジット）                                                                     | 上と同じです                                                                                                                        |
| X API の認証に失敗しました（…HTTP 401）                        | API Key と API Key Secret、または Access Token と Access Token Secret を入れ違えた                      | 手順 8 の表のとおりの欄に入っているかを確かめ、4 つとも入れ直します                                                                 |
| X API の認証に失敗しました（…HTTP 401）                        | 「Bearer Token」や OAuth 2.0 の「Client ID」「Client Secret」を入れた                                   | OAuth 1.0a の 4 つの値（手順 4・手順 6）を入れ直します                                                                              |
| X API の認証に失敗しました（…HTTP 401）                        | X 側で値を再生成した（古い値は使えなくなる）                                                            | 新しい値を 4 つとも入れ直します。API Key を再生成したなら、Access Token も生成し直すのが確実です                                    |
| X API の認証に失敗しました（…HTTP 401）                        | **Torifune のサーバの時計がずれている**（署名に時刻が入り、X は古すぎる時刻の要求を断る）               | Torifune を動かしているサーバの時刻合わせ（NTP など）を有効にするよう、サーバの管理者に頼みます。値を入れ直しても直りません         |
| X API の資格情報の形が正しくありません                         | 値の前後に空白・改行が入った、全角の文字が混ざった、欄が空のまま                                        | 値を写し直して、「資格情報を設定」で 4 つとも入れ直します                                                                           |
| （資格情報 未設定のまま、自動の予約が待たされる）              | 4 つの値をまだ入れていない                                                                              | 手順 8 で入れます。予約時刻から約24時間で、その予約は失敗になります。早めに入れてください                                           |

画面の案内で分からないときは、Torifune の管理者に、この Plugin の README の「うまくいかないとき」を見てもらってください。

## 期限と更新

- 4 つの値に**有効期限はありません**（X の公式の説明では、Access Token は期限切れにならず、取り消されるまで使えます。キーとトークンは再生成しない限り失効しません）。Torifune が自動で延長する仕組みもありません（延長の必要がありません）
- 次のときは、値が使えなくなります。**新しい値を用意して、「資格情報を設定」から 4 つとも入れ直してください**
  - X の Developer Console で、API Key や Access Token を「Regenerate」（再生成）したとき
  - App の権限を変えたとき（新しい権限のトークンを生成し直します。手順 5・手順 6）
  - App を削除したとき、App や開発者アカウントが停止されたとき
- 入れ直しの手順：`/social` のアカウントの一覧で X のアカウントの行の「資格情報を設定」を押し、4 つの欄をすべて入れて「保存」を押します
- クレジットは値とは別に減っていきます。残高が無くなると、値が正しくても投稿は断られます（手順 7）

## 安全のために

- 値は**この画面（Torifune）以外に貼らないでください。** チャット・メール・共有のメモ・AI のチャット・「トークンを確かめる」ような第三者のサイトに貼らないでください
- **X にログインするパスワードは Torifune に入れないでください**（入れる欄はありません。求められたら手順を誤っています）
- 4 つの値は発行した画面で**一度しか表示されません。** 写すまで画面を閉じないでください。写した値は、Torifune に入れ終えたら手元のメモから消してください
- 値をコマンドラインに直書きしないでください（シェルの履歴に残ります）。この手順書はコマンドを使いません
- **入れ終えたら、クリップボードの履歴からも消してください。** Windows の「クリップボードの履歴」、スマートフォンの入力の履歴、クリップボードを同期するアプリに、写した値が残ることがあります
- **画面の写真（スクリーンショット）を人に送る前に、値が写っていないか確かめてください**（API Key・API Key Secret・Access Token・Access Token Secret。「Keys and tokens」の画面には値が出ています）
- 値が漏れたと思ったら、X の Developer Console の「Keys and tokens」で該当の値を「Regenerate」（再生成）して古い値を使えなくしてから、Torifune で「資格情報を設定」から入れ直してください
- Torifune に保存した値は暗号化され、画面に再表示されません。**入れ直すときはすべての欄を入れ直します**（一部だけは変えられません）
- **X へ送る要求の `Authorization` ヘッダ（署名の入った部分）をログに残さないでください。** Torifune のサーバの前にプロキシや監視の仕組み（APM など）を置いている場合は、そのログにこのヘッダが残らない設定にするよう、サーバの管理者に頼んでください。OAuth 1.0a は要求の本文を署名しないため、漏れたヘッダは、署名の時刻から間もないうちなら別の本文の投稿にも使い回せます
- App の権限は「Read and write」までにします。「Read, write, and DMs」は選ばないでください（Torifune はダイレクトメッセージを使いません。漏れたときに読まれる範囲が広がります）
- Torifune 用の App（またはトークン）は、ほかのアプリやツールと使い回さないでください。1 つを取り消しても、ほかが止まらないようにするためです
- 使い過ぎに備えて、Developer Console でクレジットの使用の上限（spending limit）を決めておくと安心です

## 画面が違うとき

X の開発者向け画面は、名前や並びがよく変わります。以前は「Developer Portal」（`developer.x.com`）という名前の画面で、今の説明では「Developer Console」（`https://console.x.com`）と呼ばれています。この手順書のとおりに見つからないときは、次を試してください。

- App の一覧は「Apps」、値の画面は「Keys and tokens」、権限は「App permissions」、認証の設定は「User authentication settings」や「authentication settings」という名前で探します
- 値の行の名前は「API Key and Secret」（「Consumer Keys」）、「Access Token and Secret」、ボタンは「Generate」「Regenerate」で探します
- 権限の選択肢は「Read only」「Read and write」「Read, write, and DMs」の 3 つです。**「Read and write」を選び、その後で Access Token を生成し直す**、という順番だけは画面が変わっても同じです
- 料金・クレジットは「Billing」「Credits」という名前で探します
- 画面の表示の言語は英語が基本です。ブラウザの翻訳を使うと、ボタンの名前がこの手順書と違って見えることがあります。探すときは英語の名前で探してください
- それでも見つからなければ、次の「公式の説明」を開いてください。公式の説明の見出し「Creating an app」（App を作る）、「App permissions (OAuth 1.0a)」（権限）、「How to find and regenerate your API Key and Secret after App creation」（値の探し方・再生成）で探すと見つけやすくなります
